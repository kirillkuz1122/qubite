# Документы (DOC-002c)

Адреса: `/docs` — список своих документов, `/docs/{id}` — редактор. На телефоне
документ занимает рабочую область, панель блоков находится над клавиатурой.
На ПК виден список слева, `/`-меню и панель форматирования при выделении.

Данные берутся из DOC-002b (`packages/sync-client/DOCS.md`). В исходной копии
задания #144 этого клиента не было. Перенесены готовые `docs.ts`, его тесты,
документация, экспорт и зависимость Yjs из `task/DOC-002`; клиент не переписан.
Перенесён также согласованный файл решений `79.md` (D-750…D-756).

Решил так, можно откатить:

- `BlockNode` — один плоский ElementNode. `kind`, `checked` и `indent` идут
  через Yjs; изменение вида сохраняет ключ блока и его текст. Номера списка —
  производные значения соседей, отдельной записи в Yjs нет.
- Связка использует `CollaborationPlugin` с локальным провайдером. Сеть, повтор
  обмена и IndexedDB принадлежат `DocHandle`. Присутствие локальное, чужих
  курсоров нет. После сигнала WebSocket сначала синхронизируются метаданные,
  потом `DocStore.syncAll()`.
- Старый Markdown импортируется и при пустой строке. Поздний перенос сохраняет
  уже набранные блоки. Отметка в Y.Doc не позволяет повторить импорт при повторном
  подключении React; затем вызывается `markSeeded()`. `onReset` снимает прежнюю
  привязку и переоткрывает документ.
- Базы документов изолированы тем же именем аккаунта, что основная синхронизация.
  Короткое превью для локального поиска хранится в отдельном ключе localStorage
  аккаунта; весь текст и очередь правок сохраняет IndexedDB клиента DOC-002b.
- Старые входы из проекта, Command и Входящих направлены на настоящие документы.
  Полнотекстовый поиск Command остаётся отдельной задачей (D-756).

Тесты для CI: `BlockNode.test.ts` — свойства, Markdown туда и обратно, настоящая
привязка двух Lexical + Yjs без экрана; `handles.test.ts` — переоткрытие и
повторное подключение React; `e2e/docs.spec.ts` — поддельный API по контракту,
работа без сети с перезагрузкой, поиск, блоки, обе темы и 360 px.

Проверки, сборки и браузер в сессии на Pi не запускались по прямому указанию

Поправки DOC-002e1 к ревью #147: потерянные дописки и запасной Markdown после
чужого seed хранит `DocStore` в IndexedDB. `LostEdits` читает их через handle;
провайдер отвечает только за связь редактора и документа. Несколько возвращённых
блоков сохраняют порядок; запасной Markdown вставляется в конец. Фоновый экспорт
из `render.ts` читает слитую копию Yjs через headless Lexical и те же правила
Markdown, что экран. Тесты этих сценариев добавлены без запуска на Pi.

DOC-003b (#173): `MentionNode` — атомарный inline `qubite-mention`, в Yjs только
`target` и `kind`. `Mentions` рисует подпись из `DocHandle.links`, а `LinkSource`
отделяет поиск и чтение связей от сгенерированного API DOC-003a. Кэш подписей
хранится полем `links` в той же записи IndexedDB, что документ, отдельно от Yjs.
Переименование, удаление и восстановление цели меняют чип без правки текста.

Решил так, можно откатить:

- `@` распознаётся по тексту перед кареткой, включая границу форматированных
  фрагментов; почта и блок кода не открывают меню. Поиск задерживается на 150 мс,
  прежний запрос отменяется, его поздний ответ игнорируется. Esc сохраняет ввод
  и подавляет повторное открытие того же триггера. Без сети доступны названия
  из кэша текущего документа.
- Чип получает подпись только в DOM. Неизвестная цель — «…», удалённая —
  «Удалено» без перехода. Первый Backspace выделяет узел, второй удаляет его.
  Общие `Button`, `Presence`, `useSlide` и токены сохраняют правила §0.
  На телефоне меню находится над клавиатурой и панелью блоков; на ПК — у каретки,
  с ограничением по шапке и Command.
- Экспорт Markdown — `[@Название](qubite://uuid)`, без кэша — `[@](qubite://uuid)`.
  Импорт сохраняет UUID, тип берёт из кэша, иначе использует `docs.page`;
  переход уточняет тип по свежему ответу `links`. Превью показывает `@Название`.
- `DocStore.extractLinks` получает UUID из слитого дерева через headless Lexical.
  Уникальный список передаётся с тем же push, что текст и снимок; старые клиенты
  без этого колбэка оставляют поле отсутствующим. Очередь закрытого документа
  тоже использует экспорт дерева. Меню ограничивает число разных целей до 200;
  если офлайн-слияние превысило лимит, отправка ждёт удаления лишних ссылок,
  локальный текст сохраняется. Метаданные подписей не меняют Yjs.
- Для проектов используется `/planner/project/{id}`. Дела открываются через
  `/planner?task={id}`, события — `/calendar?event={id}`: добавлены обработчики
  существующих форм дела и события. Ctrl/⌘-клик запрашивает новую вкладку.

Поправка DOC-003b к ревью #175: потерянные дописки сохраняют порядок текста и
упоминаний. У `LostBlock` необязательное поле `content`: части `text` и `mention`
(только `target` и `kind`, без названия). Старые записи без этого поля возвращаются
по `text`; чистый текст сохраняется в прежнем формате. Решил так, можно откатить:
расширение не требует новой версии IndexedDB и сохраняет прежние текстовые записи.
Заметка «Вернуть?» читает названия из кэша `links`, без названия показывает
«@ссылка» и обновляется при изменении кэша. Возврат создаёт настоящий `MentionNode`;
чип без дописанного текста тоже считается потерянной правкой. Якорь живого соседа
учитывает чип как «@», как и `getTextContent()` редактора.
