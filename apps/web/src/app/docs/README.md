# Документы (DOC-002c)

Адреса: `/docs` — список своих документов, `/docs/{id}` — редактор. На телефоне
документ занимает рабочую область, панель блоков находится над клавиатурой.
На ПК виден список слева, `/`-меню и панель форматирования при выделении.

Данные берутся из DOC-002b (`packages/sync-client/DOCS.md`). В исходной копии
задания #144 этого клиента не было. Перенесены готовые `docs.ts`, его тесты,
документация, экспорт и зависимость Yjs из `task/DOC-002`; клиент не переписан.
Перенесён также согласованный файл решений `79.md` (D-750…D-756).

Решил так, можно откатить:

- `BlockNode` — один плоский ElementNode. `kind`, `checked` и `indent` идут
  через Yjs; изменение вида сохраняет ключ блока и его текст. Номера списка —
  производные значения соседей, отдельной записи в Yjs нет.
- Связка использует `CollaborationPlugin` с локальным провайдером. Сеть, повтор
  обмена и IndexedDB принадлежат `DocHandle`. Присутствие локальное, чужих
  курсоров нет. После сигнала WebSocket сначала синхронизируются метаданные,
  потом `DocStore.syncAll()`.
- Старый Markdown импортируется и при пустой строке. Поздний перенос сохраняет
  уже набранные блоки. Отметка в Y.Doc не позволяет повторить импорт при повторном
  подключении React; затем вызывается `markSeeded()`. `onReset` снимает прежнюю
  привязку и переоткрывает документ.
- Базы документов изолированы тем же именем аккаунта, что основная синхронизация.
  Короткое превью для локального поиска хранится в отдельном ключе localStorage
  аккаунта; весь текст и очередь правок сохраняет IndexedDB клиента DOC-002b.
- Старые входы из проекта, Command и Входящих направлены на настоящие документы.
  Полнотекстовый поиск Command остаётся отдельной задачей (D-756).

Тесты для CI: `BlockNode.test.ts` — свойства, Markdown туда и обратно, настоящая
привязка двух Lexical + Yjs без экрана; `handles.test.ts` — переоткрытие и
повторное подключение React; `e2e/docs.spec.ts` — поддельный API по контракту,
работа без сети с перезагрузкой, поиск, блоки, обе темы и 360 px.

Проверки, сборки и браузер в сессии на Pi не запускались по прямому указанию
владельца. Скриншоты ожидаются из CI в `docs/design/screens/doc-002/`.
