# Документы без сети (DOC-002b)

Метаданные документа и его содержимое идут разными путями:

- `createDoc(client, title)` и `renameDoc(client, id, title)` записывают обычные
  операции `SyncClient`. `create` не отправляет текст или служебные поля Yjs.
- `docList(await client.all())` возвращает живые `docs.page`, свежие сверху:
  `{ id, title, preview, updated }`. `updated` — время снимка в миллисекундах.
- `DocStore` хранит Yjs v1 в отдельной IndexedDB `qubite-docs`. Если приложение
  переключает аккаунты, оно должно использовать отдельный `dbName` для каждого
  аккаунта, как и для основной базы синхронизации.

Решил так, можно откатить: транспорт принимает `Uint8Array`, а HTTP-адаптер сам
переводит их в base64 и поля `seed_markdown` / `seedMarkdown`. Обработчики ошибок,
CSRF, Bearer и cookie соответствуют `httpTransport`; опции у адаптеров общие.

## Подключение экрана

```ts
import { DocStore, httpDocsTransport } from '@qubite/sync-client';

const store = new DocStore({
  transport: httpDocsTransport(),
  // Необязательно: сериализация слитого Y.Doc без открытого экрана.
  renderText: (doc) => markdownFromYDoc(doc),
});
const handle = await store.open(id);
// open восстанавливает локальную копию и делает первую попытку обмена.
// Недоступный сервер, 404 или отсутствие сети не мешают получить handle.

// Экран привязывает Lexical к handle.doc и задаёт синхронный экспорт Markdown.
handle.text = () => markdownFromEditor();
const unsubscribe = handle.onStatus((status) => {
  showSaveStatus(status);
  // Здесь также можно заметить появление seedMarkdown после восстановления сети.
});
const unsubscribeReset = handle.onReset(() => {
  // Сначала отсоединить старую привязку Lexical, затем заново открыть документ.
  reopenEditor(id);
});

// После первого успешного pull. Проверять именно !== null: пустая строка — тоже seed.
if (handle.seedMarkdown !== null) {
  // Наполнить Y.Doc один раз, сохранив уже имеющиеся офлайн-правки.
  importMarkdownIntoEditor(handle.seedMarkdown);
  await handle.markSeeded();
}

// WebSocket «есть новое», а также завершившийся client.sync() после create:
await store.syncAll();

// Уход с экрана. close сразу отсоединяет запись и отменяет таймер отправки;
// Promise ждёт записи на устройство, но не зависшего запроса к серверу.
unsubscribe();
unsubscribeReset();
await handle.close();
// При остановке приложения: await store.close().
```

`open` для уже открытого ID возвращает тот же handle и пробует синхронизацию.
Экран должен выполнять импорт seed только один раз за время жизни привязки;
при `onReset` привязка создаётся заново. После перезапуска сохранённый seed
отправляется автоматически, поэтому повторный импорт не нужен.

`onStatus` сразу сообщает текущий статус, затем сообщает результат локальной
правки и каждой попытки обмена. Статус может повторяться: при этом экран может
увидеть изменившийся `seedMarkdown`.

| Статус    | Значение                                                                                   |
| --------- | ------------------------------------------------------------------------------------------ |
| `saved`   | Нет локальных правок, ожидающих подтверждения сервера                                      |
| `pending` | Есть локальные правки, ожидается перенос Markdown или объект ещё не дошёл до сервера (404) |
| `offline` | Сеть недоступна или сервер ответил 5xx; очередь сохранена                                  |
| `error`   | Сервер отклонил запрос, сломался экспорт Markdown или не удалась запись в IndexedDB        |

## Сохранение и повтор обмена

Событие `Y.Doc.update` сразу начинает транзакцию IndexedDB: байты дописываются
в журнал, а локальная правка увеличивает счётчик неотправленных изменений.
Запись на устройство не ждёт таймера. При более чем 50 записях журнал одного
документа сливается в одно обновление внутри той же транзакции. Серверные
обновления тоже сохраняются, но не создают локальную очередь.

`sync()` сначала получает недостающее со своим вектором состояния и применяет
его с origin, равным `DocStore`. Затем отправляет разницу относительно вектора
сервера, если есть неподтверждённые правки. Подтверждение сохраняет серверный
вектор и снимает очередь только до версии, вошедшей в запрос. Более поздние
правки остаются в очереди. Одни удаления также считаются изменениями, даже
если вектор состояния Yjs не изменился.

Локальный Markdown записывается вместе с правкой. Опция `renderText(doc)`
сериализует актуальное слитое дерево при фоновом `syncAll()`. Web использует
headless Lexical + `@lexical/yjs` из `apps/web/src/app/docs/render.ts`;
дополнительных зависимостей нет. При открытом экране используется `handle.text`;
при отключении экрана возвращается фоновая функция. Без `renderText` сохраняется
прежнее поведение: отправляется последний сохранённый Markdown.

После правки обмен запускается через `debounceMs` (по умолчанию 500 мс).
Ошибка не удаляет очередь. Повтор — по `sync()`, `syncAll()` или событию
`online`; постоянного опроса сервера нет. `syncAll()` поднимает также документы,
которые сохранены в этой базе, но сейчас не открыты на экране.

Первый перенос старого Markdown ждёт `markSeeded()`, затем отправляется с
`seed: true`. И отметка seed, и текст переживают перезапуск. При 409
`seed_taken` сначала делается pull. Вектор первого seed-запроса записывается
перед отправкой и переживает потерю ответа и перезапуск. Если вектор сервера
покрывает этот снимок, сервер принял наш seed: снимается отметка seed, затем
обычный push отправляет более поздние правки без сброса журнала.

Если сервер принял чужой seed, перед сбросом собственный Markdown атомарно
сохраняется как `handle.recovered: string | null`. Чужой seed до этого решения
не сливается с локальным вариантом. После `onReset` надо переоткрыть редактор;
если сброс случился внутри начального `open`, он сам возвращает новый живой
handle. Запасной вариант переживает закрытие и перезапуск. Экран предлагает
вставить его в конец; `await handle.clearRecovered()` убирает предложение после
вставки либо отказа. Остальные ошибки HTTP копию не удаляют.

Тесты находятся в `src/docs.test.ts`: отдельные IndexedDB и Y.Doc в памяти,
поддельный HTTP без сети. На Raspberry Pi проверки не запускались по условиям
задания; их должен выполнить CI.

## Потерянные дописки (DOC-002d)

`watchLostEdits(doc, origin, cb)` ищет текст, который исчез при слиянии из-за
удаления блока на другом устройстве (D-375, D-399, DOC-002d). Формат Lexical 0.52:
корень `root` — `Y.XmlText`, блоки — вложенные `Y.XmlText` с `__type: "qubite-block"`,
вид — атрибут `kind`. Маркеры текстовых узлов `Y.Map` и форматирование не входят
в найденный текст.

Подключать после загрузки исходной согласованной копии, до локальных правок,
удалений и обмена. В `Y.applyUpdate` передавать тот же `origin` по идентичности.
После каждой транзакции с этим `origin`, в том числе пустой, наблюдатель
запоминает вектор состояния как границу последнего обмена.

- Если пришло удаление живого блока, возвращаются только живые перед удалением
  вставки текущего `doc.clientID` после последнего обмена (режим по умолчанию).
- Если пришли новые символы в уже удалённый блок, возвращаются только они.
- `cb` вызывается только с непустым списком `{ text, kind, after }`, по порядку
  блоков. `after` — обычный текст предыдущего **живого** блока после слияния,
  `null` — вставить в начало. Повторное применение обновления не даёт дублей.

`DocStore` подключает наблюдатель сразу после загрузки IndexedDB, до первой
сетевой транзакции. Он передаёт `() => serverSv` и пятый аргумент `'all'`:
неотправленными считаются Item **всех** клиентов за последним известным вектором
сервера, включая прошлые открытия и другие вкладки. Четвёртый аргумент — функция,
возвращающая `Map<number, number>` подтверждённых часов. Прежний режим наблюдателя
для текущего clientID сохраняется для самостоятельных вызовов.

Найденные блоки сразу записываются в IndexedDB до записи удалённого обновления.
Это работает и при `syncAll()` для закрытых документов. `handle.lost: LostBlock[]`
доступен после `open`; `handle.onLost(cb)` сразу отдаёт текущий список и сообщает
об изменениях. `await handle.clearLost()` убирает найденное после выбора человека;
дописки, пришедшие во время записи выбора, остаются для следующего предложения.

Вставку после согласия выполняет экран через Lexical. Несколько блоков с одним
якорем вставляются после предыдущего восстановленного блока, сохраняя порядок.
Провайдер редактора больше не отслеживает потери и не подтверждает их по статусу.

Решил так, можно откатить: на время наблюдения фильтр `doc.gcFilter` удерживает
удалённые поддеревья только внутри `root`. Обычное стирание символов в живом
блоке сохраняет стандартную очистку: намеренно стёртое не станет допиской.
Иначе стандартный GC Yjs уничтожает
родителя и якоря ещё до прихода запоздавшего текста. Остальные разделы Y.Doc
сохраняют прежний фильтр. Возвращённый `stop()` снимает обработчики и возвращает
прежний фильтр (если его не заменили снаружи); несколько наблюдателей делят эту
защиту. При уничтожении документа наблюдатель останавливается сам.
Уже очищенные **до подключения** блоки восстановить нельзя; удержанные данные
увеличивают память документа и могут остаться в ней до дальнейшей очистки или
его закрытия. Реализация использует внутренние `Item` закреплённого Yjs 13.6.33;
при обновлении версии нужны тесты совместимости.

## Поправки ревью #147 (DOC-002e1)

Решил так, можно откатить: новые поля (`seedSv`, `recovered`, `lost`) добавляются
в существующие записи с безопасными значениями по умолчанию; версия IndexedDB
и формат `/y` сохраняются. Rust не меняется. Тесты без сети добавлены к
`docs.test.ts`, `docs-lost.test.ts`, `BlockNode.test.ts` и `Editor.test.tsx`.
На Pi эти тесты и остальные проверки не запускались по указанию владельца.
