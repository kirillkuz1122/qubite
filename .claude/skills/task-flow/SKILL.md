# Сессия задачи (D-641)

1. **Карточка.** Прочитай свой issue (поиск по ID) и только решения, на которые он ссылается: `grep -rn "D-581" docs/product/decisions/`. STATUS, архивы и весь DECISIONS не читай. Поставь метку `in_progress` вместо прежней.
2. **План.** Разбей на куски по 1–3 файла. Код больше ~30 строк — задание Codex Sol (скилл `delegate`), пока он пишет — делай следующий кусок или жди будильником. Сам пишешь только мелочь и склейку. Ни одного задания Codex за задачу — объясни в отчёте почему (D-647).
3. **Ветка.** Работай в ветке `task/ID` и открой PR в `main` — без PR нет ревью Codex.
4. **Сомнения.** Владельца спрашивай только про Pi и сеть, удаление данных и направление продукта (D-585). Остальное решай сам, записывай решением «агент, можно откатить» в последний `docs/product/decisions/NN.md` и строкой в индекс `DECISIONS.md`. Номера — у менеджера в задании.
5. **Проверка.** `scripts/check.sh` зелёный, CI зелёный, PR Codex проверены. Ревью своего PR — всегда Codex Terra (`codex-review`), UI-скриншоты ПК и телефона 360 px — тоже Terra, по `docs/design/DESIGN_SYSTEM.md` §0.5.
6. **Сдача.** Коммит на русском; после ревью и зелёного CI слей PR в `main` (squash). Issue: метка `review`, если нужна приёмка владельца (любой UI), иначе закрыть. Строка в `docs/project/STATUS.md` (файл ≤ 80 строк — старое убирай).
7. **Отчёт** — комментарий в своём issue (менеджер читает его по будильнику; `send_message` ему не доходит — D-646), карточка из 5 строк:
   - Сделано: …
   - Не сделано / отложено: …
   - Владельцу проверить: 1–3 пункта, где нажать.
   - Решения: D-…
   - Codex: сколько заданий и ревью, номера issue.
   - Лимит: сколько примерно ушло (если видно).

Стоп-условия: кончается запас лимита (менее 10% недели — D-587), задача оказалась вдвое больше, или нужен ответ владельца — отчёт менеджеру и конец хода, без «ещё чуть-чуть».
