# /calibrate — из поправок в правила

**Главное правило: без явного «да» владельца ни один файл не меняется.** Ответ «да» относится к одному предложению; «да ко всем» — только если владелец так и написал.

1. Прочитай журнал `corrections.md` (Qubite — `docs/harness/corrections.md`): только строки с пустым «Чем стало». Нет таких — скажи «поправок нет» и закончи.
2. Сгруппируй похожие. Для каждой группы выбери **одно** место, где правило сработает всегда (от надёжного к слабому):
   - **проверка** — скрипт, хук, тест, CI: сработает без чтения текста;
   - **навык** `.claude/skills/<имя>/SKILL.md` — если поправка про один процесс;
   - **AGENTS.md** — если про всех агентов проекта (в файле ≤ 60 строк: добавил строку — убери или слей другую);
   - **память** — общая о владельце: в общем харнессе `MEMORY.md`, пока его нет — не предлагай, оставь строку в журнале;
   - **выкинуть** — разовое.
3. Правило формулируй **короче, а не длиннее**: если в файле уже есть близкое — предложи заменить, а не дописать. Одна поправка — одна строка.
4. Покажи владельцу таблицей простыми словами: «поправка → куда → что будет написано (точный дифф) → что уберу взамен». Жди ответа.
5. На «да» — внеси правку, в журнале поставь в «Чем стало» `→ навык delegate` / `→ AGENTS.md` / `→ проверка …` / `→ память` / `→ выкинуто` и дату. На «нет» — `→ отклонено`, правило не трогай. На молчание — ничего не меняй, строки остаются до следующего раза.
6. Личное (имена, адреса, ключи, здоровье) в публичный репозиторий не пиши — такие правила предлагай только для приватного харнесса (D-938).

Запуск: вручную `/calibrate` или раз в неделю агентом `weekly-audit` — он готовит таблицу, но применять без владельца не может.
