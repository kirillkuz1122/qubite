# Частный подбор Kwork

Базовые исходники для установки Kwork. Парсер/runner/notify/bot устанавливаются вместе в `~/.hermes/scripts/`; cron запускает `kwork_run.sh`, polling и worker — отдельные системные службы `kwork-bot-poll` и `kwork-bot-work`. Существующие `.env` и `~/services/kwork-bot/private.json` не входят в репозиторий. На Raspberry есть дополнительные изменения, сделанные через Hermes: динамические промпты, профиль, вложения, варианты и голосовые правки, аналитик. Эти расширения не полностью представлены в данном каталоге; при обновлении нельзя заменять действующие скрипты базовыми без сравнения.

👍/👎 сохраняются в SQLite `~/services/kwork-bot/bot.sqlite`, оценку можно изменить. Удаление карточки не удаляет предпочтение. Подбор получает до 12 подходящих примеров, поровну положительных и отрицательных при их наличии, без откликов и истории диалогов. Это контекст для Jev, не обучение весов модели. Изменение оценок инвалидирует кеш решений для ещё не обработанных заказов; ранее отправленные/отклонённые заказы автоматически заново не рассылаются.

Кнопки только от владельца и только на соответствующей карточке. Оценки записываются сразу в короткой транзакции, без вызова LLM и без блокировки worker откликов.

Тесты: `PYTHONPATH=integrations/kwork pytest integrations/kwork/tests`.

Отклики: `anthropic/claude-haiku-5.5`, только Anthropic, `allow_fallbacks:false`, потолок $0.10/$0.50 за 1M вход/выход. Каждый заказ — отдельный короткий контекст, без предыдущих откликов. Jev продолжает отбор. Старые кеши и отправленные карточки не удалять; изменение модели инвалидирует кеш только при следующем запросе того же заказа.

В расширенной установке Raspberry отклики имеют явный резервный маршрут `google-vertex/global` с тем же потолком цены. Обновление и границы проверки описаны в [отчёте миграции](../../docs/haiku-migration.md).
