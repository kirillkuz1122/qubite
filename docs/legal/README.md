# Правовые документы нового Qubite

Полные новые тексты: [условия](TERMS.md), [приватность](PRIVACY.md), [cookies](COOKIES.md), [отдельное согласие на обработку данных](CONSENT.md). Старые турнирные документы находятся в legacy и не применяются к новой платформе. Канонический пакет UI: [documents.json](../../apps/web/src/legal/documents.json), версия qubite-account-v1; [хеш пакета](BUNDLE.json). Страницы доступны без входа по /#/legal/terms, privacy, cookies, consent, на том же origin.

AUTH-007 получил прямое разрешение владельца подготовить новые тексты. Неизвестны оператор/статус/адрес, контакт, страны запуска/хостинга/backup, получатели SMTP/AI, сроки хранения и порядок исполнения запросов. Вопрос отправлен владельцу; реквизиты не выдуманы. publication_ready=false — документы полноценные по структуре и содержанию, но ещё не действующая публичная оферта/политика. Заполнять известные факты, затем провести проверку применимого права перед запуском, а не копировать старую турнирную политику.

В UI условия и согласие на данные имеют **два независимых, выключенных по умолчанию переключателя**, отдельные ссылки. В текущем AUTH-006 API остаётся один technical consent_version/consent_accepted для пакета; AUTH-007 отправляет true только после обоих действий. PostgreSQL фиксирует пакет/время/источник, но не отдельные purpose-specific утверждения. Это не достаточное доказательство всех будущих юридических согласий. QUB-LEGAL-001 до публичного deployment должен разделить необходимые юридические основания/версии и evidence там, где это требуется; marketing/AI/distribution нельзя включать этим bool. Старые consent rows не превращать задним числом в отдельные согласия.

Cookies: технические session/preauth/oauth, без рекламных/аналитических scripts. Не делать «принять всё» обязательным условием входа. Cosmetic localStorage описан отдельно. Перед включением будущих необязательных категорий — самостоятельный отказ/выбор/отзыв и технический gate до загрузки. Cookies самого внешнего owner-private demo хостинга не являются cookies рабочего Qubite; описано в документе.

## Основание решений и ограничения проверки

- [Официальный текст 152-ФЗ на сайте Минтруда](https://mintrud.gov.ru/docs/laws/130), просмотр13.10.2026: статья9 требует отдельного оформления согласия и доказательства основания; статьи5/18.1 — цели/состав/сроки и доступность политики. Текст страницы перечисляет изменения по24.06.2025; это не подтверждение отсутствия более поздних изменений к дате production.
- [Официальные правила ЕС о cookies](https://europa.eu/youreurope/business/growing/digitalising/online-privacy/index_en.htm), просмотр13.10.2026: различать необходимые cookies запрошенной функции и категории, требующие предварительного согласия. Это референс классификации; применимость ЕС к Qubite ещё не установлена.
- [Федеральный закон156-ФЗ, официальный портал](https://publication.pravo.gov.ru/document/0001202506240021) найден, но fetch timed out; не считать отдельной выполненной проверкой полного текста последней редакции.

До запуска: сверить действующую редакцию права выбранных стран, реквизиты/договоры/локализацию/уведомления где применимы, детские сценарии, срок ответа/удаления/backup, real cookie inventory и фактические технические меры. Эти тексты не дают права скрытно включить данные в AI. Прототип и fixtures не являются проверкой юридического соответствия публичного сервиса.
