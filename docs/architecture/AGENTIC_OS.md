# Агентная ОС: харнесс владельца и «Пульт» в Qubite (HAR-002)

Статус: **черновик для обсуждения, работа не начата** (17.11.2026), задача #245. Решения — D-930…D-937 в [decisions/95.md](../product/decisions/95.md). Владелец: «пока нет, просто запиши… лимитов пока нет и надо ещё доосуждать многое и прям чётко всё разобрать, что мы именно хотим и как оно будет выглядеть».

## 0. Что это одной фразой

Одна система, в которой агенты работают на владельца **без его ПК**: знают, кто он и как с ним говорить, сами учатся на его правках, по расписанию делают тихую работу и предлагают улучшения, а владелец видит всё это — задачи, навыки, расходы, лимиты — на красивом экране **в Qubite, в том числе с телефона**. Сначала обкатываем на Qubite, потом переносим на всю папку `programming`.

## 3. Три слоя

1. **Общий харнесс владельца** — отдельный **приватный** репозиторий (не Qubite: Qubite может быть публичным, а здесь личное), ставится в `~/.claude/` на всех машинах:
   - `CLAUDE.md` — карта до ~150 строк: кто владелец (ссылка), как отвечать, куда смотреть;
   - `USER.md` — кто он: стек (Arch, bspwm, Python, React, Rust), характер, что любит и не любит, как пишет (голосом — понимать по смыслу);
   - `SOUL.md` — как агент говорит: на «ты», по-русски, без воды, объяснять «почему»;
   - `MEMORY.md` — каталог памяти, одна строка на запись со ссылкой на файл; `memory/` — сами записи; список проектов строкой на проект;
   - общие навыки: `note`, `calibrate`, `personalise`, `land-pr`, ревью, джокеры;
   - моды и хуки: Ribbon, страж опасных команд (хук, а не правило в тексте — хук срабатывает всегда).
   Цель: новая сессия в любом проекте сразу знает владельца («начал новый бренд — она уже понимает, как со мной общаться»).
2. **Проектный слой** — `AGENTS.md`, навыки и решения проекта (у Qubite уже есть). В проект — только то, что про проект.
3. **Пульт в Qubite** — экран над первыми двумя (§5).

## 4. Где это работает: ПК, Pi, облако

Требование владельца: **ноутбук выключается, агенты работают дальше**; всё, что поменяли без него, возвращается на ПК.

| Место | Что умеет | Чего нельзя | Цена |
|---|---|---|---|
| ПК владельца | всё, вся папка `programming` | работает не всегда | — |
| Raspberry Pi | 24/7: расписание, `claude -p` для тихих задач, Telegram-бот, хранение, git | тяжёлые сборки и тесты (D-620), Rust-workspace Qubite собирается долго и греет | уже есть |
| Облачные сессии Claude Code | сборки, тесты, Playwright, PR | живут до простоя; нет файлов ПК | в подписке, но тратят лимиты |
| GitHub Actions | CI, сборки по пушу | — | бесплатно в лимитах GitHub |
| VPS (если понадобится) | сборки 24/7, белый IP | — | платно; владелец: «зачем, когда есть Pi» — пока не берём |

Как я вижу схему (предложение, D-935):
- **Код** — источник правды GitHub: каждый проект — свой репозиторий; ПК, Pi и облако синхронизируются через `git push/pull` по веткам. Конфликты видно и их решают явно.
- **Не-код** (заметки, память агента, файлы без git) — двусторонняя синхронизация Syncthing между ПК и Pi: Pi всегда онлайн, ПК догоняет при включении. Минус: одновременная правка на двух машинах даёт файл-конфликт `.sync-conflict`, его надо разбирать.
- **Pi — диспетчер, облако — руки**: Pi по расписанию запускает тихие задачи сам (`claude -p`, лёгкие) и отдаёт тяжёлые (сборка, тесты) в облачную сессию или CI, а результат забирает через git.
- Доступ к Pi снаружи — сейчас Tailscale (лежит с 16.11), в будущем своя сеть (IDEA-096).

## 5. Модуль «Пульт» в Qubite

Решено владельцем 17.11 (D-930): пульт агентов — **модуль Qubite**, а не отдельная игрушка. Почему: работает на телефоне (моды Claude Code — только на ПК); Recos ложатся во Входящие, потолки — в AI-шлюз (`AI_COST_GUARD.md`), расписание — в календарь; мы сами — первые пользователи. В будущем связан с IDE (IDEA-012), Git (IDEA-095), хронологией (`SYNC_AND_HISTORY.md`), своими устройствами и облаком Qubite (IDEA-001, IDEA-096), локальной LLM (IDEA-094), агентами на других устройствах (IDEA-002, IDEA-003). Владелец: «если это всё сделать интуитивно, красиво и офигенно — будет классно».

### 5.1. Что видно на его экране (ориентир по духу, не по составу)

- **Главная** — в центре карта (точки-сфера, вокруг кольцо значков приложений и навыков); слева «Микро-приложения» (список с описанием строкой) и «Календарь»; справа «Почта» (крупная цифра + 3 важных письма + полоса «микс за день»), «Задачи по расписанию» (время · название · где запущено · статус NEXT/QUEUED), «Колода навыков» (карточка: значок, `/имя`, модель · усилие, кнопки ▶ ⚙ 🗑).
- **Навык → модель × усилие**: сетка Haiku/Sonnet/Opus/Fable × low…max, ползунок.
- **Recos**: слева разделы ARMS со счётчиками; карточки «#1 MEMORY: Shrink CLAUDE.md» — «польза», «что сделаю», метки «усилие / приоритет / экономия токенов», файлы, которые тронет; кнопки «в корзину», «Применить все комментарии».
- **Задачи (Routines)**: строка = значок, название, дни недели, токены в неделю, $ в неделю; сортировка по токенам; «за 7 дней: 60,9 млн токенов, $57,78».
- **Второй мозг**: таймлайн (строки ARMS, по дням — столбики правок), 2D-кольца, 3D-сфера, поиск по 424 тыс. файлов.
- Стиль: почти чёрный фон, тонкие линии, оранжевый/жёлтый/голубой акценты, моноширинные подписи, точечные шкалы — близко к нашему языку (сетка точек `q-grid`).

- Лимиты 5ч/7д — то, что читает Ribbon из Claude Code; проверить, можно ли получать их вне Claude Code.
- Всё это — данные о работе владельца: только его аккаунт, только чтение, без токенов в git и логах.

## 6. Jev (выбор модели на каждый запрос)

Быстрая модель решений от TypeSafe через OpenRouter: на каждый запрос решает, кому отдать — Haiku, Sonnet или Opus (у Jay: 4451 решение по ~0,6 с за $0,18, ~40% ушло на Haiku). У владельца на OpenRouter ~$20 (D-933).
- Это инструмент **харнесса** (разработки), не продукта: правило «платный ИИ — только через AI-шлюз» касается Qubite; для харнесса — свой ключ OpenRouter с потолком на ключе.
- Ключ — в файле на машине (не в чате, не в git); журнал решений с выключателем; сравнить расход неделю с Jev и неделю без.
- Начинать, когда будут недельные лимиты — иначе не с чем сравнить.

## 7. Что не берём (D-936)

- **3D-сферу на сотни тысяч файлов** — красиво, но пользы мало, а дорого в макете и коде; карта — 2D.
- **Пинг «держать кэш тёплым» раз в 50 минут** — выгоду он считает в ценах API; на подписке каждый пинг съедает 5-часовой лимит. Дешевле не будить остывшие сессии (D-900).
- **Векторную БД для памяти** — он сам от неё отказался: Claude ищет по файлам лучше.
