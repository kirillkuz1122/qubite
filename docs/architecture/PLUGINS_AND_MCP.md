# Расширения, собственный MCP и Developer Bridge

Основа — [MC §15](../context/QUBITE_MASTER_CONTEXT.md). Этап: MCP-сервер — P2, Plugin SDK — P3. Документ фиксирует границы, чтобы ядро с первого дня не мешало расширениям.

## 1. Собственный MCP-сервер (P2)

MCP — это стандартный интерфейс к данным и инструментам для внешних агентов (Codex, Claude Code, Hermes). Это **не** новая модель и **не** замена авторизации.

- **Ресурсы:** контекст проекта, документы, решения, краткие сводки.
- **Инструменты:** искать, читать, создавать/обновлять задачи, предлагать изменения, отчитываться о прогрессе.
- **Промпты:** «возобновить проект», «ретроспектива», «подготовить релиз».
- **Доступ:** OAuth / короткоживущие scoped-токены (`mcp.<domain>`), для локального stdio — отдельные ключи. Токены не логируются, отзываются.
- **Граница:** внешний Codex видит **только выданный проект**. Дневник, другие проекты, финансы и данные команды без разрешения недоступны.
- Каждый вызов проходит тот же Policy Gate и AI-шлюз, что и интерфейс.

## 2. Context Capsules

Переносимый пакет минимального контекста: цель проекта, ТЗ, решения, ограничения, задачи, файлы/ссылки, недавний прогресс. Ручной выбор приватности, редактируемый манифест, экспорт Markdown/JSON/zip. Нужен, чтобы не объяснять проект заново при переходе между агентами (I-48).

## 3. Plugin SDK (P3)

- Язык SDK — **TypeScript/JavaScript**; переносимая логика — **WebAssembly** (исследовать Extism или аналог). Своего языка плагинов не делаем.
- Манифест: `id`, версия, `minHostVersion`, возможности (`ui`, `server`, `mobile`, `workflow`, `mcp`), разрешения, точки входа, UI-вклады (виджеты, команды, маршруты, блоки), миграции, подпись/хеш, платформы.
- Разрешения показываются **до** установки, отзываются. Нет `universal_admin`, нет доступа ко всей БД, файлам, сети и секретам.
- Исполнение в песочнице/отдельном процессе с квотами; UI изолирован; входные данные валидируются.
- API для плагинов: Objects, Events, Commands, Search, UI Slots, Notifications, Agent Tools, Memory — каждый со своим scope.
- Установка синхронизируется на уровне аккаунта; устройство включает только совместимые части и честно сообщает о несовместимых.

## 4. Что закладываем в ядро уже в MVP

- Все инструменты и действия описываются JSON Schema и регистрируются в реестре — так их потом получат MCP и плагины.
- Policy Gate поддерживает субъекты «агент», «API-ключ», «плагин» и правило пересечения прав.
- События объектов публикуются во внутреннюю шину — на неё позже подпишутся Pulse и плагины.
