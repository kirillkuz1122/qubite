# Настольный помощник Qubite (DESK-001)

Статус: ТЗ, 15.11.2026. Решения — D-875…D-886, D-890 в [decisions/90.md](../product/decisions/90.md). Задача — GitHub issue DESK-001.

## 0. Что это одной фразой

Персонаж на рабочем столе Linux, которому владелец диктует голосом или пишет: спросить что-то быстро (вместо похода в ChatGPT), дать команду компьютеру («выключи туннель», «перекинь Telegram на третий стол», «громкость 30»), попросить помочь с тем, что на экране, или сделать дело в Qubite. Это **модуль Qubite**, а не отдельная программа: вход через аккаунт Qubite, думает сервер Qubite, лимиты — AI-шлюз Qubite.

Откуда взялось: набросок владельца «Desktop AI Companion 🐈» (14.11) — только примерная идея. Проба Codex на Qt (PR #234, `experiments/desktop-companion/`) отвергнута: код до требований, не тот стек. Из неё ничего не берём, кроме мысли про `bspc` и «контекст только по запросу».

## 1. Что умеет (по ответам владельца 15.11)

| Умение | Как | Подтверждение |
|---|---|---|
| Быстрый вопрос | Текст/голос → сервер → ответ в облачке | нет |
| Команды компьютеру | Только через **команды** из белого списка, не мышью (§4) | для опасных — да |
| Помощь с экраном | Модель сама решает: взять выделенный текст или кадр активного окна | кадр — только по запросу владельца |
| Компьютер-юз мышью | Когда команды нет: вызывается сильная модель, **сама делает цепочку шагов** | перед опасным шагом — да |
| Дела Qubite | Создать задачу, мысль во Входящие, «что на завтра», напоминание | нет (обратимо) |
| Самообучение | Частая просьба → навык → одна команда (§6) | новый навык — да |
| Напоминания | **Единственное**, что он говорит сам, без вопроса | — |

Не умеет и не будет: читать экран постоянно, сам заговаривать (кроме напоминаний), запускать произвольные команды оболочки, ходить в сеть мимо сервера Qubite.

## 2. Вид и поведение

- **Свой новый персонаж** — не один из четырёх помощников сайта (`COMPANIONS.md`), но в том же языке: плоская фигура, глаза-точки, следит за курсором, «дышит», пружины из `packages/motion`. Есть характер (тон реплик, реакции на успех/ошибку).
- **Облик и имя** — дизайнер предлагает 3–4 варианта в Figma (файл `UZ5s8bNDVUfqK2yy80DAWR`, страница «Новые модули» → «Настольный помощник»), владелец выбирает. До выбора — временная фигура.
- Живёт на столе (прозрачное окно поверх всех, без рамки, мимо фокуса). Скрывается клавишей или из трея; скрытый — значок в трее и горячая клавиша работают.
- **Ответ — облачко у курсора** с кнопками «Да / Нет / Подробнее». Длинный ответ — раскрывается в маленькое окно чата.
- Состояния персонажа: спит · слушает · думает · делает · ждёт подтверждения · ошибка.

## 3. Ввод

- **Голос — «зажал-сказал»** (push-to-talk): держишь клавишу — пишет, отпустил — отправил. Распознавание — то же, что у CMD-005: облако через шлюз, локальный Whisper или свой ключ.
- Текст — та же горячая клавиша Command из CLIENTS.md §3, поле ввода в облачке.
- Клавиши настраиваются; по умолчанию предложить такие, что не пересекаются с bspwm/sxhkd владельца (проверить на его конфиге).

## 4. Команды компьютеру (локальный исполнитель)

Три уровня (D-890). Главное правило: **расширяет список только владелец своим нажатием на своём ПК**; сервер и модель могут только предлагать.

1. **Разрешённые команды** — выполняются сразу. Сервер шлёт `{"command": "bspwm.move_window", "args": {...}}`, клиент сверяет имя со списком и собирает вызов с проверенными аргументами (`std::process::Command`, аргументы отдельно, без `sh -c`).
2. **Терминал по запросу** — для всего, чего нет в списке. Модель предлагает точную строку; облачко показывает её целиком и кнопки «Выполнить / Нет». После «Выполнить» строка идёт в `sh -c` с таймаутом, вывод (обрезанный) возвращается модели, цепочка продолжается. Каждая новая строка — отдельное подтверждение.
3. **Терминал → навык.** Похожая подтверждённая команда повторилась → модель предлагает шаблон: имя, фраза, команда, поля с типами (`число 0–100`, `стол 1–10`, `приложение из списка`). После «Да» шаблон пишется в локальный список (`~/.config/qubite/commands.toml`) и дальше работает как уровень 1. Поля подставляются отдельными аргументами, не вклейкой в строку — иначе через поле пролезет `; rm …`.

Красный список (`sudo`, `rm -r`, `dd`, `mkfs`, `curl|wget … | sh`, запись в `/etc` и `/boot`, `chmod 777`): подсвечивается, требует подтверждения каждый раз, навыком без вопроса не становится. Сервер не может записать в локальный список ничего — запись только по нажатию в клиенте.

Первый набор (Linux, X11, bspwm):

| Группа | Команды | Чем |
|---|---|---|
| VPN (Happ) | `vpn.tun_on`, `vpn.tun_off`, `vpn.status` | способ — выяснить на ПК владельца (§4.1) |
| Окна и столы | фокус, перенос окна на стол, перейти на стол, свернуть/закрыть, раскладка | `bspc` |
| Приложения и сайты | открыть приложение из списка, открыть URL | `.desktop`-файлы, `xdg-open` |
| Звук | громкость, mute, выход | `wpctl` (PipeWire) / `pactl` |
| Музыка | play/pause/next/prev, что играет | `playerctl` (MPRIS) |
| Яркость | яркость экрана | `brightnessctl` |
| Система | заблокировать экран | по конфигу владельца |

Опасные (нужно «Да»): закрыть окно с несохранённым, выключить TUN, всё из компьютер-юза, что вводит текст, отправляет, удаляет или платит.

### 4.1. Happ: прокси всегда, переключается только TUN

Владелец хочет: прокси Happ включён всегда и весь трафик идёт через него, а «выключить VPN» значит **выключить только TUN-режим** одной командой, без 33 кнопок. Как это сделать, зависит от того, что Happ даёт на Linux (CLI, конфиг-файл, локальный API, systemd-юнит). Первый шаг этапа 3 — разведка **на ПК владельца, только с его разрешения** (это сеть/VPN, D-585): посмотреть, ничего не меняя, и предложить способ. До ответа команды `vpn.*` — заглушки.

## 5. Мозг: сервер Qubite и маршрутизация моделей

- Клиент — тонкий: экран, голос, исполнитель. Решает, что делать, серверный агент `crates/qubite-agent` через AI-шлюз (`AI_COST_GUARD.md`, источники `owner` / `chatgpt` / `own_key`).
- **Маршрутизация (по словам владельца):**
  - по умолчанию — **Luna** (быстрая, дешёвая): разговор, вопросы, выбор команды;
  - нужен компьютер-юз — Luna вызывает **Terra**;
  - сложная задача (план, код, разбор) — вызывает **Sol**.
  Названия — профили шлюза, а не жёсткие ID: модель за профилем меняется в настройках. Каждый вызов считается в бюджете; превышение — честная ошибка в облачке.
- Контекст с ПК (выделение, кадр окна, список окон) уходит на сервер **только в запросе**, где он нужен, и не хранится дольше ответа, кроме того, что владелец сам сохранил.
- Без сети: работают только локальные команды по точному совпадению (после этапа 6) и напоминания, уже лежащие на ПК.

## 6. Самообучение «как Hermes»

1. Сервер ведёт счётчик похожих просьб (по смыслу, не по тексту).
2. Просьба повторилась 3+ раза и решалась одинаково → агент **предлагает навык**: имя, фраза-триггер, шаги (цепочка команд из белого списка), пример.
3. Владелец жмёт «Да» → навык сохраняется (формат навыков — `AI_AGENTS_MEMORY_SKILLS.md`), и дальше это **одна команда** без компьютер-юза и без дорогой модели.
4. Если задачу можно решить командой — компьютер-юз не используется вообще.
Навык собирается из разрешённых команд и шаблонов, которые владелец подтвердил из терминала (§4, уровень 3). Добавить в список сам, без нажатия владельца, он не может.

## 7. Как устроен клиент

- `apps/desktop` — **Tauri 2**, это и есть APP-001 (#68): одно настольное приложение Qubite, помощник — его модуль (окно-персонаж + трей), а не второй бинарник.
- Rust: окно-оверлей (X11, прозрачность, click-through вне персонажа), глобальные клавиши, запись звука, исполнитель команд, кадр окна (`xdotool`/X11 API), трей, автозапуск.
- UI: React/TS, персонаж — `packages/ui/src/Companion.tsx` (Canvas) и `packages/motion`.
- Вход — PKCE (AUTH-006, D-177): клиент `qubite-desktop`, `qubite://auth/callback`. Токен — в системном хранилище (Secret Service), не в файле.
- Linux X11 + bspwm первым; Wayland, Windows, macOS — позже, исполнитель за трейтом `Platform`.

## 9. Безопасность

- Список команд хранится в клиенте; пополняет его только владелец. Произвольная строка терминала — только после показа и «Выполнить», каждый раз.
- Кадр экрана — только по явной просьбе, в облачке видно «смотрю окно X».
- Компьютер-юз: перед вводом текста, отправкой, удалением, оплатой — подтверждение; кнопка «Стоп» всегда видна, Esc останавливает.
- Сеть и VPN владельца: команды `vpn.*` трогают только Happ и только TUN; Tailscale и прочие сети не трогаются.
- Токены и ключи — в системном хранилище, не в git и не в логах.
