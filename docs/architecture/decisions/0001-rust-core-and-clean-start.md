# 0001. Новое ядро на Rust с нуля

- Статус: принято
- Дата: 2026-10-17
- Решения владельца: [D-001](../../product/DECISIONS.md), [D-003](../../product/DECISIONS.md), [D-005](../../product/DECISIONS.md)

## Контекст

Старый Qubite — Node.js-монолит (`server.js` ≈ 9 900 строк, `db.js` ≈ 9 200, `app.js` ≈ 17 500) с глобальными турнирными ролями. Codex начал новое ядро на Python/FastAPI (ветка `codex`), но владелец остался недоволен результатом и решил, что для многих будущих модулей и desktop-приложения нужен Rust.

## Варианты

1. Продолжить FastAPI-ядро Codex.
2. Постепенно вырезать модули из старого Node (strangler).
3. Новое ядро на Rust с нуля; старое — образец для переписывания.

## Решение

Вариант 3. Сервер — один Rust-бинарник (модульный монолит, axum + sqlx). Код из ветки `codex` не переносится; используются только продуктовые и дизайнерские решения, которые владелец принял (они собраны в DECISIONS.md).

## Последствия

- Первая польза появится позже, чем при strangler, поэтому план начинается с самого практичного модуля (Command + Inbox).
- Один язык для сервера, Tauri и общего ядра устройств (`qubite-local` через UniFFI на Android).
- Python-сервисы переписываются на Rust по одному; до этого живут в `legacy/`.
- Rust сложнее для быстрых правок, поэтому важны строгие тесты и CI с первого дня.

## Как пересмотреть

Если окажется, что какой-то модуль на Rust писать неоправданно дорого (например, сложная ML-обработка), допускается отдельный сервис на другом языке за API ядра — через новый ADR.
