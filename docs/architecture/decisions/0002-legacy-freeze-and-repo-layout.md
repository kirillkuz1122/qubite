# 0002. Старый код заморожен в legacy, монорепозиторий

- Статус: принято
- Дата: 2026-10-17
- Решения владельца: [D-022](../../product/DECISIONS.md), [D-023](../../product/DECISIONS.md)

## Контекст

В корне лежали вперемешку старый сайт, сервисы, деплой и документы. Владелец хочет чистый корень, ничего не потерять и всегда понимать, где старое, а где новое.

## Решение

- Весь старый проект перенесён **одним деревом** в `legacy/qubite-v1/` без изменения кода: относительные пути, установщик и 321 тест продолжают работать.
- Старые заполненные `.env` лежат рядом со старым кодом (не в git).
- Новый код живёт в `crates/`, `apps/`, `packages/`, `deploy/`, `docs/` (см. [OVERVIEW](../OVERVIEW.md)).
- Новый код **никогда** не импортирует ничего из `legacy/`. Переписанный модуль сначала полностью заменяет функцию, потом старая часть помечается в `legacy/README.md` как заменённая.

## Последствия

- На Raspberry Pi нельзя делать `git pull` main поверх работающего старого Qubite (пути изменились). Сервер остаётся на ветке `tournaments` / теге `qubite-v1.0` до нового установщика.
- Ветка `codex` и тег `qubite-v1.0` — архивы, не удаляются.

## Как пересмотреть

Когда все модули переписаны и старый сервер выключен, `legacy/` можно удалить отдельным решением владельца (история останется в git).
