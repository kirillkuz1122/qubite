# 0005. Аккаунты с нуля, один owner, запрет по умолчанию

- Статус: принято
- Дата: 2026-10-17
- Решения владельца: [D-050](../../product/DECISIONS.md)…[D-063](../../product/DECISIONS.md)

## Контекст

В старом Qubite был фактически один аккаунт (владельца). Переносить пароли, сессии и глобальные роли не нужно.

## Решение

- Аккаунты создаются в новой БД заново. Owner — командой `qubite owner create` при установке; публичного пути стать owner нет; owner один (ограничение в БД).
- Default deny: новый пользователь получает только аккаунт; модули и AI выдаёт владелец вручную, права раздельные (read/write/manage/ai).
- Турнирные роли — только внутри модуля турниров.
- Один вход для всех модулей и сервисов; для расширений/агентов — отдельные ключи (P2).

## Последствия

- Старые аккаунты турниров при переписывании модуля не переносятся автоматически (данные турниров — отдельное решение в задаче TOUR-001).

## Как пересмотреть

Если понадобится перенос данных старых участников турниров — отдельная задача импорта с согласованием.
