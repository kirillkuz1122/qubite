# 0003. PostgreSQL на сервере, SQLite на устройствах

- Статус: принято
- Дата: 2026-10-17
- Решение владельца: [D-004](../../product/DECISIONS.md)

## Контекст

Нужны: атомарные бюджеты и права при параллельных запросах, много пользователей, поиск по смыслу, офлайн на устройствах, работа на Raspberry Pi.

## Варианты

1. SQLite везде — проще для Pi, но слабее для конкурентной записи, ролей БД и векторного поиска.
2. PostgreSQL + pgvector на сервере, SQLite на устройствах.

## Решение

Вариант 2. Сервер: PostgreSQL 16+ с pgvector, доступ через sqlx, очередь задач в той же БД. Устройства: SQLite через общий Rust crate `qubite-local` (FTS5 для поиска, очередь синхронизации). Web в MVP — IndexedDB для офлайн-очереди.

## Последствия

- На Pi нужно настроить PostgreSQL под малую память (shared_buffers, work_mem) — делается в установщике.
- Тесты сервера запускаются на временном PostgreSQL (в CI — сервис-контейнер).

## Как пересмотреть

Если PostgreSQL окажется слишком тяжёлым для конкретного Pi — замер и новый ADR (например, вынос БД на другую машину).
