# 0004. Клиенты: один React-интерфейс, Tauri, нативный Ink

- Статус: принято; выбор оболочки Android — открыт
- Дата: 2026-10-17
- Решение владельца: [D-003](../../product/DECISIONS.md)

## Контекст

Нужны web, desktop и Android. Дизайн с живым материалом должен быть одинаково хорошим везде. Делать весь интерфейс дважды (React и Compose) — двойная работа и расхождение анимаций. Перо требует нативной скорости.

## Решение

- Web: React + TypeScript.
- Desktop: Tauri 2 с тем же React.
- Android: общий React-интерфейс + **нативный Ink** на Kotlin (Compose + Jetpack Ink или альтернатива по замерам).
- Оболочка Android (Tauri 2 Mobile или своя Kotlin + WebView) — **открытый вопрос**, решается прототипом в задаче APP-002 по задержке пера, плавности переходов, жестам и размеру APK.

## Последствия

- Дизайн-система — общий пакет `packages/ui`; производительность анимаций проверяется на WebView слабого телефона.
- Общая логика устройств — Rust (`qubite-local`), на Android через UniFFI.

## Как пересмотреть

Если WebView на Android не даст нужной плавности, конкретные экраны переносятся в Compose — новый ADR с замерами.
