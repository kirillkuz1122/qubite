# 0009. Редактор документов: два прототипа, Tiptap или Lexical, CRDT — Yjs

- Статус: предложено — **выбор редактора за владельцем** ([D-299](../../product/DECISIONS.md), вопрос Q-85)
- Дата: 2026-10-21
- Задача: DOC-001 (дальше — DOC-002)

## Контекст

Docs — блочный редактор (DOC-01) с офлайн-правкой и слиянием без потерь (DOC-04, [SYNC §2](../SYNC_AND_HISTORY.md): текст — CRDT). Владелец выбирает редактор сам, по ощущениям (D-299). Поэтому сделаны **два живых прототипа на одном сценарии** — страница `/lab/editor` (переключатель «А · Tiptap» / «Б · Lexical»):

- блоки: заголовок, подзаголовок, текст, список, нумерованный, чек-лист, цитата, код;
- `/` в пустой строке — меню блоков (русские и английские слова, стрелки, Enter, палец), над полем — панель блоков для пальца;
- Markdown-шорткаты: `#`, `##`, `-`, `1.`, `[ ]`, `>`, ```` ``` ```` и пробел;
- **две копии** («Ноутбук» и «Телефон»): в сети правка сразу видна во второй; «Сеть» выключена — копии расходятся; «Слить две копии» — каждая получает недостающее (векторы состояния Yjs). Сервера нет, всё в браузере;
- телефон — 360 px, касания; стиль DS-007, движение только `transform`/`opacity`.

Общий код (меню, панель, пара копий, начальный конспект) одинаков для обоих — отличаются только движок и его связка с CRDT.

## Варианты

| | А · Tiptap 3.32 (ProseMirror) | Б · Lexical 0.52 (Meta) |
|---|---|---|
| CRDT в прототипе | Yjs 13.6 через y-prosemirror (`@tiptap/extension-collaboration`) — родная связка | Yjs 13.6 через `@lexical/yjs` — родная связка |
| Размер куска сборки (gzip) | **139 КБ** (+ Yjs и общий код лаборатории 29 КБ) | **104 КБ** (+ те же 29 КБ) |
| Открытие лаборатории (CPU ×4) | 1,16 с первый раз, 0,55 с повторно | 1,0 с первый раз, 0,51 с повторно |
| Большой документ, 400 абзацев (CPU ×4) | вставка 0,39 с, печать 24 мс на знак | вставка 0,68 с, печать 31 мс на знак |
| Слияние: разные блоки, один абзац, одно место | без потерь, порядок одинаковый на обеих копиях | без потерь, порядок одинаковый |
| Слияние: «отметил дело» ‖ «поправил его текст» | обе правки | обе правки |
| Слияние: «сделал абзац заголовком» ‖ «дописал в него» | **дописанное теряется** | **дописанное теряется** |
| Слияние: «удалил блок» ‖ «дописал в него» | блок удалён вместе с дописанным | блок удалён вместе с дописанным |
| Телефон | чек-лист — настоящий флажок; правила ввода работают с экранной клавиатурой | флажок рисуется CSS, нажатие ловит плагин по координатам |
| Зрелость | ProseMirror — с 2015, Tiptap 3 — стабильная ветка, большой набор расширений, таблицы/упоминания/формулы готовые | версия 0.x (API ещё меняется: в 0.52 часть collab-API помечена `EXPERIMENTAL`), развивается быстро, плагины — примеры из playground |
| Лицензия | MIT (ядро и все взятые пакеты; платные у Tiptap — только облако и Pro-расширения, их не берём) | MIT |

### Почему не Loro

Loro (MIT, 1.16) — сильный CRDT на Rust, но: у Lexical привязки к Loro нет; у ProseMirror есть `loro-prosemirror` 0.4 (молодая); WASM весит **3,4 МБ (1,1 МБ gzip)** — на слабом телефоне это заметно дольше открытия, чем весь редактор. Yjs — 25–30 КБ gzip, на сервере у него есть **yrs** (Rust-порт Yjs с тем же форматом), так что сервер на Rust (D-001) хранит и сливает те же обновления. Поэтому оба прототипа — на Yjs, и это решение не зависит от выбора редактора.

## Замеры

Как мерили: production-сборка (`vite build` + `vite preview`), Chromium без сети и сервера, `Emulation.setCPUThrottlingRate = 4`. Числа — с этой облачной машины (она сама медленная), сравнивать стоит А с Б, а не с телефоном владельца.

| Что | А · Tiptap | Б · Lexical |
|---|---|---|
| Кусок редактора, gzip / без сжатия | 139 КБ / 436 КБ | 104 КБ / 333 КБ |
| Общий код лаборатории + Yjs, gzip | 29 КБ | 29 КБ (тот же) |
| Открытие: первое / повторные (до текста в обеих копиях) | 1155 мс / 557, 554 мс | 995 мс / 534, 492 мс |
| Печать в маленьком документе | 10,2 мс на знак | 9,9 мс на знак |
| Вставка 400 абзацев | 391 мс | 680 мс |
| Печать в документе из 400 абзацев | 23,9 мс на знак | 31,4 мс на знак |
| Слияние после офлайн-правок в большом документе | 162 мс | 243 мс |

«Мс на знак» — от нажатия до появления во **второй** копии, вместе с задержкой самого Playwright (она одинаковая у обоих), поэтому важна разница, а не число.

Сценарии слияния (обе копии без сети, потом «Слить»):

| Сценарий | А | Б |
|---|---|---|
| Обе правят один абзац (начало и конец) | обе правки | обе правки |
| Каждая добавляет свой пункт чек-листа | оба пункта | оба пункта |
| Обе пишут в одно и то же место | обе вставки подряд, одинаково на копиях | то же |
| Отметить дело ‖ поправить его текст | дело отмечено, текст новый | то же |
| Удалить цитату ‖ дописать в неё | цитаты нет, дописанное пропало | то же |
| Сделать абзац заголовком ‖ дописать в него | заголовок, дописанное пропало | то же |

Вывод: по качеству слияния движки **равны** — его определяет Yjs, а не редактор. Последние два случая — потери, которые надо закрыть в DOC-002 (Q-87).

## Решение (рекомендация агента — выбор за владельцем)

Агент советует **А · Tiptap**, но решает владелец по ощущениям:

- **зрелость:** ProseMirror с 2015 года, Tiptap 3 — стабильная ветка; у Lexical версия 0.x, связка с Yjs нового поколения помечена `EXPERIMENTAL`;
- **что будет нужно дальше** (DOC-01, DOC-003): таблицы, формулы, ссылки `[[документ]]`, упоминания `@задача`, изображения — у Tiptap это готовые MIT-расширения, у Lexical — в основном примеры из playground, которые придётся переписывать;
- **большие документы и слияние** — быстрее у Tiptap (печать 24 против 31 мс на знак, слияние 162 против 243 мс при CPU ×4);
- **телефон:** у Tiptap флажок чек-листа — настоящий элемент, его проще нажать и он читается экранным диктором;
- **минус Tiptap:** на 35 КБ (gzip) тяжелее — на слабом телефоне это около 0,15 с при первом открытии, потом кэш.

За Lexical: он легче и чуть быстрее открывается, у него аккуратная модель узлов и сильная команда Meta. Если по ощущениям Б приятнее — это весомая причина: оба прототипа покрывают сценарий целиком.

Независимо от выбора:

- CRDT — **Yjs** в браузере и **yrs** на сервере (DOC-002); слияние — обмен обновлениями по векторам состояния, как в `Pair` лаборатории;
- общий код лаборатории (`/`-меню, панель блоков, виды блоков) переезжает в Docs как есть;
- проигравший прототип удаляется вместе с его пакетами после выбора (лаборатория останется с одним редактором или уйдёт).

## Последствия

- Смена вида блока при одновременной правке текста теряет текст у **обоих** движков (Yjs не умеет «переименовать» узел — удаляет и вставляет заново). То же — «удалил блок» ‖ «дописал в него». В DOC-002 можно хранить вид блока свойством одного общего узла (тогда смена вида не теряет текст) и предупреждать о правке в удалённом блоке — решает владелец (Q-87).
- Лаборатория — отдельный кусок сборки: остальной сайт от неё не тяжелеет.
- Пакеты закреплены точными версиями (`apps/web/package.json`).

## Как пересмотреть

Если Lexical выйдет из 0.x с несовместимыми изменениями или Tiptap закроет нужное за Pro — пересмотреть выбор; формат Yjs при этом не меняется, документы переносятся конвертером. Если Yjs не справится с очень большими документами — тогда снова смотреть Loro (на сервере он тоже на Rust).
