# Memos и Vikunja: первый вход, телефон и Arch Linux

## Первый пароль

1. Войди своим аккаунтом на [Qubite Auth](https://qubiteapp.online/auth).
2. Открой [создание аккаунта Memos](https://qubiteapp.online/service-enroll?service=memos) или [создание аккаунта Vikunja](https://qubiteapp.online/service-enroll?service=vikunja).
3. Посмотри указанный логин, придумай и повтори пароль (от 8 символов, латинская буква и цифра, максимум 72 байта UTF-8). Сохрани его в AliasVault. Пароль приложения отдельный от пароля Qubite.
4. Нажми «Создать аккаунт», затем «Открыть сервис» и войди указанным логином/паролем в самом приложении.

Подготовленные аккаунты владельца имеют логин `kirill`; записи и доступ Hermes сохраняются. Для друзей используется их логин Qubite, если он подходит обоим приложениям. Для логинов с `_`/`.` или другими неподдерживаемыми символами показан стабильный `qb-<ID>` — не пытайся самостоятельно заменить его на имя другого человека.

Повторный вход на страницу создания не меняет пароль. Если его забыли, нужен штатный сброс в приложении/помощь владельца; повторная выдача разрешения Qubite не сбрасывает пароль. В случае неоднозначного сбоя создание блокируется до проверки, чтобы повтор не перезаписал уже принятый пароль.

## Дать доступ другу

Создай ему аккаунт Qubite или используй существующий. В админке пользователя разреши Memos/Vikunja; в Telegram это также доступно через `/service_user <логин>`. Отправь ему соответствующую ссылку создания аккаунта. Открытая регистрация самих приложений закрыта.

Разрешение **не открывает твои заметки и проекты**. После регистрации, если хотите работать вместе, отдельно пригласи его в пространство Memos или расшарь проект/команду Vikunja. Отзыв доступа Qubite закрывает внешний сайт, но не удаляет данные пользователя. Сайты не требуют включённого Tailscale на телефоне.

## Веб-интерфейс

- [Memos](https://memos.qubiteapp.online): короткие заметки, Markdown, вложения, поиск и пространства. Личные заметки держи приватными. Для записей, которые должен видеть Hermes, выбирай пространство **Кирилл и Арчи**.
- [Vikunja](https://vikunja.qubiteapp.online): проекты, задачи, сроки, метки и виды списка/доски/календаря. Hermes подключён к ограниченному ключу владельца: он видит доступные владельцу проекты, а не все аккаунты друзей. Почтовые уведомления не настроены.

## Телефон

Android: открой сайт в браузере, выполни оба входа. В браузере с поддержкой установки веб-приложений выбери меню → «Установить приложение» / «Добавить на главный экран». Формулировка зависит от браузера. Начать удобнее с Chrome/Chromium; при установке в другом браузере его сессия Qubite может потребовать отдельного входа.

iPhone/iPad: открой сайт в Safari → «Поделиться» → «На экран Домой». При первом открытии ярлыка снова войди, если система не перенесла сессию.

У Memos есть официальный [PWA-манифест и режим отдельного окна](https://usememos.com/features/pwa-support). Это интерфейс твоего сервера; ему нужна сеть, гарантированного офлайн-режима здесь нет. Для Vikunja можно использовать мобильную веб-версию и ярлык; наличие кнопки установки зависит от браузера и версии приложения. Сторонние мобильные клиенты отдельно не проверялись.

## Arch/CachyOS, Firefox и Zen

В Zen/Firefox просто открой ссылки и закрепи вкладки — устанавливать сервер на ноутбук не нужно. Для отдельного окна веб-приложения используй Chromium с пунктом установки/создания ярлыка; это по-прежнему сайт на Raspberry, с обычными браузерными сессиями.

У Vikunja есть [официальный desktop-клиент для Linux/macOS/Windows](https://vikunja.io/help/desktop/) с Custom Server и быстрым добавлением задач. Совместимость конкретной desktop-сборки нужно проверить: браузерные страницы остаются за входом Qubite. Для обычных API-клиентов добавлен нативный вход и проверка токена через Qubite-разрешение, без требования браузерной cookie. Если приложение использует старые или OAuth-endpoints, которые не поддерживает установленная версия сервера, одного адреса может быть недостаточно; пришли название/версию клиента.

## Hermes

Можно попросить: «Сохрани эту идею в Memos в нашем пространстве» или «Создай в Vikunja задачу … со сроком …». Мост допускает чтение/создание/изменение заметок, задач и проектов; удаление и управление пользователями ему не выданы. При выключенном сервисе нужно включить его через Qubite `/power`, а затем повторить запрос. Первый пароль владельца не отправляется Hermes: он работает своими API-ключами.

## Отдельные API-клиенты

Сначала выбери пароль на странице Qubite. Затем в клиенте укажи `https://memos.qubiteapp.online` или `https://vikunja.qubiteapp.online`, **нативный логин, показанный при регистрации**, и этот пароль. Пароль Qubite здесь не подходит. Режим «регистрация» в стороннем приложении не открывает аккаунт: он создаётся только через разрешённую страницу Qubite. Для Memos можно использовать собственный PAT, созданный в настройках нативного аккаунта.

Информационные endpoints серверов доступны для определения версии; чтение/изменение данных требуют нативного Bearer-токена или браузерного входа. Нативный токен проверяется самим приложением, затем Auth проверяет привязку аккаунта, его активность и разрешение Qubite. Отзыв разрешения закрывает также внешнее API, даже если нативный токен ещё действует. Memos refresh проверяет получившуюся личность до передачи токена клиенту. Конкретные сторонние приложения могут не поддерживать API версии Memos 0.31/Vikunja 2.7 — это нужно проверить отдельно.

- Вход нативных клиентов Vikunja: Qubite сохраняет путь и параметры `/oauth/authorize` через вход/первый пароль. Обмен PKCE-кода, вращение OAuth refresh и нативный cookie refresh проверяют активную привязку и grant перед возвратом токена. Переходы остаются на точном origin сервиса; callback в приложение выполняет сам Vikunja.
