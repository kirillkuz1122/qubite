# Поиск и хранилище Qubite

Платформа остаётся управляющим сервером. Новые сервисы используют её учётные записи и owner-доступ, не меняя турнирные роли. Hermes не встроен в портал.

## Адреса текущей Raspberry

- Платформа: https://qubiteapp.online/
- Поиск: https://search.qubiteapp.online/
- Хранилище: https://vault.qubiteapp.online/
- Примеры стиля: https://qubiteapp.online/design-system
- Hermes и OmniRoute сохраняют отдельные существующие адреса и учётные записи.

Веб-сайты доступны через исходящий Cloudflare Tunnel: белый IP и включённый Tailscale на телефоне не нужны. Существующий исходящий sing-box не превращается в VPN-сервер.

## Выдача доступа друзьям

1. Войти владельцем в Qubite → **Админка → Пользователи**.
2. Для уже зарегистрированного друга нажать **Выдать** рядом с поиском или хранилищем. Создание аккаунта само по себе не выдаёт доступ к ним.
3. Если аккаунта нет, нажать **Пригласить пользователя**, указать латинский логин и почту. Передать одноразовую ссылку: действует 7 дней, секрет находится во фрагменте URL и удаляется клиентом из адресной строки.
4. Друг сам выбирает пароль Qubite. После первого входа приглашение нельзя использовать для замены его пароля; обычное восстановление пароля работает отдельно.
5. Владелец задаёт для поиска запросы в час/день, доступ к платным моделям и истории, бюджеты в долларах на день, месяц и всё время. Ноль в денежном лимите допускает бесплатные ответы; пустое поле снимает соответствующий индивидуальный лимит. Общий бюджет сервиса остаётся.
6. Пользователь открывает **Мои сервисы**. Видны все три сервиса, включая те, к которым доступ ещё не выдан.

Стандартная регистрация регулируется `AUTH_INVITE_ONLY`: на текущей Raspberry она открыта (`false`) с настоящим Turnstile; Google и Telegram OAuth выключены; Telegram-бот управления работает отдельно. Почта иностранных сервисов допускается. Установщик по умолчанию предлагает закрытый режим приглашений; для открытой регистрации нужны рабочие Turnstile и email delivery.

## Поиск по умолчанию в браузере

Добавить поисковую систему:

```text
Имя: Qubite
Короткая команда: qb
URL: https://search.qubiteapp.online/search?q=%s
```

`/opensearch.xml` публикует OpenSearch-описание. Если браузер поддерживает обнаружение OpenSearch, достаточно открыть поиск и добавить его через настройки поисковых систем. После входа Qubite запрос из URL сохраняется при переходе через авторизацию. Cookie `qb_session` — Secure, HttpOnly, SameSite=Strict; общий домен задаётся `SESSION_COOKIE_DOMAIN`, сессия имеет ограниченный срок и может быть отозвана. Это не бессрочный вход.

Тёмная тема Qubite использует настоящие логотип/SVG из проекта, Manrope/Jura/Space Grotesk, розово-янтарный акцент. Переключатель даёт ещё четыре темы; фон и акцент настраиваются отдельно для каждой. Настройки сохраняются на устройстве. Скрипты и CSS без хешей не кешируются надолго; HTML добавляет версию ресурсов, чтобы обновления появлялись без ручной очистки кэша.

### Модели и источники

- Без платного доступа: только бесплатная ступень, без Jev и ручного выбора платных моделей.
- Авто у владельца/пользователя с платным доступом: Jev оценивает запрос; простой готовый короткий ответ из источника может обойтись без большой модели. Знак `?` в конце запроса обязательно включает ИИ-обработку.
- Ступени `free`, `economy`, `balanced`, `deep` и резерв бесплатной ступени задаются через `.env.example` и `models.json`. Сложная ступень использует GLM Flash, DeepInfra FP4 → Novita FP8. Провайдеры закреплены явно; произвольный OpenRouter fallback выключен.
- Модель получает результаты SearXNG и ограниченные извлечённые тексты страниц, с ссылками на источники. Извлечение блокирует локальные/служебные адреса. Это уменьшает выдумывание, но не гарантирует истинность: значимые факты проверять по источникам.
- Краткое резюме раскрывается в разделе ИИ-ответ. Продолжение разговора отправляет лишь выбранные последние сообщения; сервер не подмешивает архивную историю.
- Визуализации выполняются в изолированном iframe. Модель выбирает найденные изображения, но не генерирует их.

### История и контекст

В **Приватность** два независимых переключателя: сохранять историю и отправлять контекст текущего разговора. По умолчанию сохранение выключено; владелец может разрешить его другу, а друг включит сам.

История теперь хранится на сервере **без дополнительного шифрования**, по выбору пользователя. Переключатель сохраняется в аккаунте, поэтому чаты доступны на другом устройстве после входа; отдельная фраза больше не нужна. Отключение останавливает новые сохранения, но не удаляет прежние записи. Удалить их можно отдельно. Старые зашифрованные записи сохраняются до явного переноса с прежней фразой; без фразы расшифровать их невозможно.

Модель получает только текущий запрос и два коротких названия последних вопросов. Если нужен прошлый контекст, она возвращает служебный `history_request`; Jev выбирает один чат/поиск по коротким темам, затем передаются последние четыре сообщения выбранного чата либо выбранный поисковый фрагмент. Не связанные с прошлым вопросы не получают всю историю. Это можно выключить в Приватности. Обычное сохранение истории не означает автоматическое чтение всех чатов агентом.

Администратор с доступом к базе технически может прочитать историю. API-ключ получает её только со scope `history`, при разрешении владельца и включённой истории у пользователя. Все ключи работают в рамках своего аккаунта. Access log Uvicorn выключен; технические логи не содержат текст запросов, пароли или ключи.

## Telegram-управление

В действующем боте **@qubiteappbot**: `/start` → **Поиск и хранилище** или `/services`. `/service_user логин` открывает нужный аккаунт. Список доступен только TELEGRAM_OWNER_ID в личном чате; модераторы не управляют сервисами и бюджетами.

Кнопки позволяют выдавать/отзывать поиск и хранилище, разрешать платные модели/историю, менять лимиты запросов и денег на день/месяц/всё время, приглашать аккаунты и удалять хранилище с вводом логина. **Общий бюджет и расходы** показывает дневные расходы и позволяет изменить глобальный бюджет без рестарта; тот же лимит доступен в веб-админке. Настройка хранится в system_settings, `SEARCH_DAILY_BUDGET_USD` задаёт только первоначальное значение. Это бюджет приложения; установленный в OpenRouter лимит API-ключа нужно менять отдельно в кабинете OpenRouter.

Числа вводятся ответом на конкретный запрос бота, запрос истекает за 5 минут; денежный «-» снимает индивидуальный лимит. Сообщения таких форм не попадают в старые prompts поддержки/VPN. Новое меню использует те же domain-функции grants и приглашений, что web API; чужие пароли и история не отправляются в Telegram. Отключение Telegram OAuth не отключает административного бота.

## AliasVault

После выдачи доступа открыть **Мои сервисы → Создать хранилище**, в AliasVault указать **тот же логин Qubite** и собственный **отдельный мастер-пароль**. Нативный клиент создаёт криптографические данные; Qubite не получает мастер-пароль. Пароль Qubite и мастер-пароль AliasVault могут и должны отличаться. Смена мастер-пароля делается в самом AliasVault.

Владелец может отозвать/вернуть доступ и удалить чужое хранилище после ввода логина-подтверждения, но не расшифровывать его. Своё owner-хранилище через этот API удалить нельзя. Отзыв выставляет `Blocked` и отзывает refresh tokens; уже выданный короткий JWT может действовать до истечения срока. Уже скачанные и расшифрованные на устройстве данные удалить удалённо нельзя.

Внутри native AliasVault регистрация включена только за защитным прокси: публичные register/validate-username проходят проверку Qubite cookie, выданного разрешения и совпадения логина. Не открывать native 9082 наружу и не убирать этот gate. Публичная админка закрыта. Управляющий процесс общается через Unix socket, проверяет UID клиента и принимает только block/delete.

### Firefox и телефон

1. Установить официальное расширение/приложение AliasVault: [Firefox](https://docs.aliasvault.com/installation/browser-extensions/), [Android/iOS](https://docs.aliasvault.com/installation/mobile-apps/).
2. В настройке сервера выбрать self-hosted/custom server и указать **`https://vault.qubiteapp.online`**.
3. Войти логином своего AliasVault и **мастер-паролем**, не паролем Qubite. Создание нового хранилища сначала выполнить в браузере через портал Qubite.
4. В телефоне включить AliasVault как службу автозаполнения; в Firefox разрешить расширению заполнение форм.

Клиенты совместимы с self-hosted сервером, но их установку/автозаполнение на конкретном телефоне нужно проверить на устройстве. Почтовые alias-функции требуют отдельной SMTP/MX-инфраструктуры; обычный Cloudflare Tunnel не обеспечивает входящую почту. Хранение паролей работает независимо от неё.

## VPN: управляющий сервер и ноды

`SERVICES_VPN_ENABLED=false` означает, что сама машина не предоставляет VPN. Начальная локальная нода создаётся неактивной; в текущей установке Raspberry так и работает. При отсутствии внешней активной ноды со свежим heartbeat интерфейс подключения/выдачи серый, сервер возвращает 503 на выдачу VPN. **Добавление и управление внешними нодами остаются доступны** в разделе Прокси.

Когда добавлена активная внешняя нода и от неё пришёл heartbeat (порог 15 минут), доступ становится доступен автоматически. VPN выдаётся в карточке пользователя через окно срока/VIP/скорости/числа подключений/no-log. Настройки переводят владельца к конкретной подписке существующего раздела Прокси. Пользователь видит личную ссылку и устройства в Моих сервисах. Смена ссылки меняет bearer token и отзывает VPN-сессии; старые профили перестают работать после синхронизации нод. Секрет ссылки хранится зашифрованным существующим proxy credential key. Старые подписки без сохранённого шифротекста получают ссылку только после явного обновления, без скрытой ротации.

Через обычный Cloudflare HTTP Tunnel стандартный VLESS/NaiveProxy-клиент к Raspberry не подключится. При белом IP/пробросе порта или отдельной серверной ноде работают прежние VLESS Reality/NaiveProxy. Детали: [proxy/app-api.md](proxy/app-api.md), [proxy/server-setup.md](proxy/server-setup.md). База остаётся на master; ноды синхронизируются через API.

## Установка на новую Debian/Ubuntu

Проверено: синтаксис/генерация/модульные тесты и текущая ручная интеграция на Raspberry. **Полная чистая установка на второй машине пока не прогонялась.** Не запускать её на действующей Raspberry ради теста: старый VPN-этап меняет Nginx/Caddy/firewall.

```bash
cp .env.example .env
# Заполнить домен, выбранные компоненты, Turnstile/email, ключи и модели.
sudo bash deploy/install.sh
```

Установщик спрашивает platform/search/vault и способ входа:

- **Cloudflare:** исходящий HTTP tunnel, машина только master для VPN; затем можно добавить внешние ноды. Для named tunnel предложит авторизацию в браузере и создаст DNS-записи. У существующего туннеля явно задать `CLOUDFLARE_CONFIG_PATH`; посторонние ingress-маршруты сохраняются.
- **Белый IP:** обычный HTTPS через Caddy; при выборе VPN используются прежние Nginx SNI-router + Caddy NaiveProxy + sing-box. Основной web-vhost старого master переносится на loopback платформы, NaiveProxy и порт 18443 сохраняются. Для другого основного домена необходимо дополнить SNI map старого VPN-установщика: его шаблон пока ориентирован на qubiteapp.online/ru.
- **Remotely managed Cloudflare token:** токен хранится в закрытом файле; Public Hostnames задать в Cloudflare dashboard согласно выведенным origin-адресам. Их автоматическое создание по одному connector token не реализовано.

Поиск/выдача приглашённого хранилища требуют платформу. Node.js ≥22, Python venv, Docker. `.env` читается как данные, не как shell. Generated runtime/env/БД исключены из Git. Native PostgreSQL volumes не chown'ятся пользователем приложения. Caddy проверяется до reload; чужие конфиги и существующий AliasVault не заменяются без проверки.

Первого владельца создать через CLI в окружении установленного приложения:

```bash
node back/scripts/invite-owner.js your@email.example yourlogin
```

Команда возвращает одноразовую ссылку. При systemd EnvironmentFile выполнять CLI с теми же переменными `DATABASE_PATH`, `APP_BASE_URL`, `INITIAL_OWNER_EMAIL`, `SERVICES_INTERNAL_KEY`; безопаснее заполнить закрытый root `.env` теми же значениями. Существующего владельца команда не заменяет. Для обычных пользователей действует web-приглашение.

# После создания venv и установки зависимостей + pytest:

Они не являются частью свежего установщика: для новой машины отдельно настроить расписание и проверить восстановление. Изменения файлов owner/index.html, существовавшие до этой работы, не включались в наш commit.

### Быстрый обзор и подробный ответ

В поисковой выдаче платным пользователям сначала отвечает Ling 3.0 Flash: 2–4 предложения по небольшому набору явно обозначенных поисковых фрагментов. Этот этап не читает все страницы и не строит HTML-визуализации. Если Jev одобрил готовый короткий ответ источника, используется он; знак вопроса принудительно включает модель. «Подробнее» запускает отдельный полный ответ: ограниченное чтение страниц, Jev и выбранная пользователем модель. Автоматический режим владельца не начинает с бесплатной модели.

Бесплатный режим: Gemma 4 → Qwen 3.8 → Inkling Small → Nemotron → Ling; каждый провайдер явно указан, цена ограничена нулём. Ожидание маршрута ограничено 10 секундами, всего 35 секундами для обзора. Наличие бесплатных моделей не гарантирует доступность или скорость. При обрыве после законченного текста показывается текст с предупреждением, вместо просьбы сократить вопрос. Неизвестная стоимость запроса после тайм-аута остаётся зарезервированной: это консервативная защита бюджета.

На 03.10.2026 Ling через Novita: $0.021/M вход, $0.063/M выход; настройки `SEARCH_FAST_*` можно менять. Уменьшенный обзор экономит токены, но его стоимость зависит от длины источников. Лимит ключа OpenRouter действует отдельно от бюджета приложения.

API, MCP для Hermes и переносимый skill: [search-api.md](search-api.md). Пустые поля количества запросов также означают отсутствие персонального ограничения; общий лимит денег и защита от частых запросов остаются.

API и переносимый skill описаны в [search-api.md](search-api.md). Новые события сервисов и ошибок поиска подключены к обычному журналу Qubite; отдельный сервис журналирования не требуется.

## Аналитика ИИ и обратная связь

Владелец открывает «Аналитика» на сайте: расходы и вызовы моделей по UTC-дням, таблица моделей и пользователей; нажатие на аккаунт показывает его графики и модели. В Telegram `/services` → «Аналитика ИИ» либо карточка пользователя → «Расходы этого пользователя». Учитываются API и браузерные ответы, маршрутизация/проверка Jev и ошибки провайдеров; обычный веб-поиск без LLM не считается вызовом модели.

Журнал SQLite поиска расширяется добавлением колонок model/provider/status, без удаления старых сумм. Ранние записи с неизвестной моделью показываются отдельно; распределение для них не восстанавливается выдумыванием. Неизвестная стоимость после разрыва связи остаётся в резерве бюджета. Только владелец и внутренний сервис с проверенными внутренними заголовками авторизации читают агрегаты. Запросы, тексты страниц и история в аналитику не попадают.

В поле поиска отдельная HTTP(S)-ссылка или домен открывается напрямую браузером. Если рядом есть другие слова, запрос отправляется поисковому движку. Другие схемы и ссылки с логином/паролем не открываются таким способом.

Для Kwork кнопки 👍/👎 сохраняют примеры предпочтений владельца; это контекст для будущих решений Jev, не дообучение модели. До 12 ограниченных примеров без откликов и диалогов. Удаление карточки не стирает оценку. Исходники и тесты: `integrations/kwork/`.

«Настройки поиска» → «Автоматически проверять ответы Jev (платно)»: настройка сохраняется для аккаунта, независимо от истории. Если выключить, у свежего ответа доступна кнопка «Проверить Jev», без нового поиска/генерации. Ручная проверка требует платного разрешения; действует пока исходные данные результата находятся в памяти (30 минут и до перезапуска поиска).
