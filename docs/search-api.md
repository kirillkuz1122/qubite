# API поиска Qubite для агентов

## Выпуск ключа

Открой https://qubiteapp.online → **Мои сервисы → Поиск → API-ключи**. Назови ключ, выставь число вызовов в день (пусто = без ограничения) и, если требуется, разреши чтение истории. Владелец также управляет ключами друзей через **Администрирование → Пользователи → Поиск → API-ключи**.

Ключ показывается целиком один раз. На сервере хранится SHA-256, имя, короткий префикс и права. Ключ можно отозвать; блокировка аккаунта/поиска действует и на все его ключи. Не вставляй ключ в адрес сайта или frontend приложения. Для браузерных проектов используй свой сервер как посредник, чтобы ключ не раскрывался посетителям.

Базовый адрес: `https://search.qubiteapp.online`. Все методы требуют `Authorization: Bearer <ключ>`. Ключ не заменяет вход в Qubite и не даёт доступ к чужой истории. Лимит API-ключа считается отдельно, расходы на модели учитываются в бюджете аккаунта и общем бюджете поиска. Опрос уже созданного задания не расходует дневную квоту ключа.

| Метод | Тело / назначение | Вызов модели |
| --- | --- | --- |
| `POST /api/v1/search` | `{"query":"...","mode":"summary","limit":4}` | Сжатый Markdown с точными данными и источниками |
| `POST /api/v1/search` | `{"query":"...","mode":"sources","limit":4}` | Нет; только найденные страницы и фрагменты |
| `GET /api/v1/jobs/{job_id}` | Дождаться долгого поиска | Дополнительного вызова нет |
| `POST /api/v1/fetch` | `{"url":"https://...","mode":"markdown"}` | Нет; основной текст выбранной страницы |
| `POST /api/v1/fetch` | `{"url":"https://...","mode":"summary"}` | Сжатие одной страницы |
| `POST /api/v1/fetch` | `{"url":"https://...","mode":"html"}` | Нет; оригинальный HTML как строка JSON |
| `GET /api/v1/history` | Недавние названия чатов и поисковые запросы | Нет; нужен scope history и включённая история |
| `GET /api/v1/history/{id}` | Только выбранный чат или поиск | Нет |

Пример успешного поиска:

```json
{"status":"done","markdown":"Краткий ответ [1].","sources":[{"id":1,"title":"Источник","url":"https://example.org","status":"read"}],"cost_usd":0.00003,"truncated":false}
```

Если поиск не закончился за 25 секунд, ответ содержит `job_id` и `poll_url`. Опрос возвращает `status: running`, затем `status: done` с полем `result`, либо `status: error`. Клиент из репозитория делает это автоматически. HTTP 401 — ключ не действует; 403 — недостаточно прав / история выключена; 429 — квота; 422 при fetch — недоступная страница; 503 — временная ошибка модели/поиска. Не делай бесконечных повторов.

`summary` по умолчанию использует Ling 3.0 Flash / Novita без reasoning, резерв — Nemo / DeepInfra. Текущая проверенная цена [Ling на OpenRouter](https://openrouter.ai/inclusionai/ling-3.0-flash) 03.10.2026: **$0.021/M вход, $0.063/M выход**; настройки `SEARCH_FAST_*`. Это скидка провайдера, она может измениться. Например 3000 входных + 250 выходных токенов стоят примерно $0.000079; реальная стоимость возвращается OpenRouter. Бесплатные аккаунты получают только бесплатные маршруты, без автоматического перехода на платные.

## Источники и ограничения

Возвращается компактный Markdown в поле `markdown` JSON; его можно сохранить в `.md`. Источники помечены как прочитанные (`read`) или доступные лишь фрагментом (`unread`). Числа/даты/условия должны сохраняться в сжатии, но если точность критична, читай исходный Markdown страницы и сверяй данные: сжатие моделью может ошибаться.

Один fetch читает **одну страницу**, не весь домен. Исходный HTML ограничен 1.5 MB, Markdown — 150000 символов. Для summary передаётся ограниченный основной текст; смотри `input_truncated` и `truncated`. Страницы с авторизацией, динамической загрузкой, CAPTCHA и ошибки сайтов могут оказаться недоступны. API не исполняет JavaScript сайтов, не скачивает приватные сети/metadata IP; редиректы также проверяются. HTML возвращается как данные JSON, не как исполняемый документ.

## Подключение к своим проектам

Скопируй skill `integrations/qubite-search/skills/qubite-search/` в каталог skills своего агента. Он содержит переносимый Python-клиент без сторонних зависимостей.

Создай **вне git** файл `qubite-search-private.json` с правами `chmod 600`:

```json
{"base_url":"https://search.qubiteapp.online","api_key":"ВСТАВЬ_НОВЫЙ_КЛЮЧ"}
```

Настрой `QUBITE_SEARCH_CONFIG` на путь к нему. Альтернатива — секретные переменные `QUBITE_SEARCH_API_URL` и `QUBITE_SEARCH_API_KEY` своего приложения. Не передавай сам ключ аргументом команды. Примеры:

```bash
export QUBITE_SEARCH_CONFIG=/полный/путь/qubite-search-private.json
python3 integrations/qubite-search/skills/qubite-search/scripts/qubite_api.py search 'Raspberry Pi 5 питание'
python3 integrations/qubite-search/skills/qubite-search/scripts/qubite_api.py fetch 'https://example.org/docs' --mode markdown
python3 integrations/qubite-search/skills/qubite-search/scripts/qubite_api.py history
```

Для stdio MCP установи SDK `mcp` в окружение агента и добавь сервер:

```json
{"command":"/путь/venv/bin/python","args":["/путь/qubite-search/qubite_mcp.py"],"env":{"QUBITE_SEARCH_CONFIG":"/путь/qubite-search-private.json"}}
```

MCP предоставляет `qubite_search`, `qubite_fetch`, `qubite_history`, `qubite_verify`. В Hermes существующий SDK используется повторно. Его отдельный ключ принадлежит владельцу Qubite, имеет поиск/извлечение/чтение **только его** opt-in истории. Обычное чтение истории начинается с названий, затем одного нужного чата; нет постоянной загрузки всех разговоров.

## Сохранение истории

Приватность → **Сохранять историю** включает синхронизацию устройств. По умолчанию у новых пользователей она выключена. Отключение останавливает новые записи и API-чтение; предыдущие чаты остаются до удаления. Старые зашифрованные чаты можно перенести по кнопке с прежней секретной фразой; фраза используется только в браузере. Без неё старые записи восстановить нельзя.

Администратор, имеющий доступ к базе, технически может читать обычную историю. Мастер-пароли и шифрование AliasVault этот выбор **не затрагивает**.

## Журнал на сайте

Операции поиска, чтения страниц, выдачи/отзыва ключей и ошибки подключены к существующему журналу Qubite. Записываются аккаунт, тип операции, HTTP-статус, время и стоимость, когда она известна. У незащищённых аккаунтов также сохраняется текст успешного поискового запроса (браузер и API) в отдельной таблице; только owner видит его в «Запросах поиска» и обычном аудите. Не сохраняются ответы ИИ, история диалога, страницы и ключи. Журнал не заменяет opt-in личную историю; `save_history:false` не отключает служебный журнал.

«Админка → Пользователи → Защитить от логов» останавливает запись и удаляет уже записанные запросы этого аккаунта из служебного журнала. Владельцы защищены по умолчанию; статус/кнопки видны только owner. «Разрешить логи» записывает только будущие запросы — историю задним числом не импортирует. До 30 дней, не более 1000 запросов на аккаунт; при смене защиты личная история и расходы не удаляются. Журнал не восстанавливает запросы, которые не были сохранены до его установки. Серверные резервные копии могут содержать удалённые записи до истечения собственного срока хранения.

## Проверка фактов и актуальности

`search(mode=summary)` и `fetch(mode=summary)` возвращают `verification`: `status` (`supported`, `uncertain`, `unsupported`, `not_checked`), `label`, `warnings`, `cost_usd`, `retry_recommended`. При сомнении также есть `agent_instruction`: не представлять спорные утверждения как факты; предложить новый уточнённый запрос или исходную страницу. Повтор выполняет сам клиент по решению пользователя. Сервер не запускает второй поиск/генерацию автоматически.

Для аккаунтов с платными моделями после ответа выполняется **один** ограниченный по времени вызов Jev с ответом и теми же источниками. В `cost_usd` входит генерация и проверка; `generation_cost_usd` показывает стоимость генерации отдельно. Гости с бесплатными моделями получают `not_checked`, без платного Jev. Ошибка, лимит или некорректный результат проверки не скрывают ответ и не превращаются в успешный вердикт.

`current_date_utc` передаётся генератору и проверке. Запросы о текущих рейтингах/ценах моделей дополняются текущим годом и месяцем в единственном первоначальном поиске; явные исторические запросы сохраняются. `search_query` показывает запрос движку. Источники могут содержать `published_at`, `modified_at`, `retrieved_at`: последняя дата не доказывает актуальность статьи. `truncated` означает обрыв **текста ответа**, не метаданных. Недоступная дата, неизвестная ссылка, обрыв ответа или неполный контекст проверки не допускают уверенную зелёную пометку.

Jev проверяет соответствие предоставленным данным, а не достоверность сайтов в интернете. `supported` нельзя трактовать как гарантию истины. Для точных текущих тарифов/бенчмарков следует выбирать официальные источники и сохранять связь модель — версия теста — значение — единицы — дата.

### Отключение и ручная проверка

Поле `verify: false` у POST search/fetch summary пропускает платную проверку готового ответа; `true` явно просит проверку (при наличии права/бюджета). Если поле не передано, действует настройка аккаунта из поиска. Отключение проверки не отменяет отдельную маршрутизацию/выбор прошлого чата через Jev. В `sources`, `markdown`, `html` LLM-проверки нет вообще.

Ответ summary содержит `verification_id`. В течение 30 минут, до перезапуска сервиса, можно POST `{}` на `/api/v1/verify/{verification_id}` для результата search либо `/api/v1/fetch/verify/{verification_id}` для результата fetch. Нужен **тот же ключ** с соответствующим scope и платным разрешением. Проверка использует сохранённые фрагменты, не запускает новый поиск или генерацию. Уже проверенный результат возвращается повторно без оплаты. После истечения времени — 404; старые тексты в истории от этого не удаляются.

CLI: `search 'вопрос' --no-verify`, `fetch 'https://example.org' --mode summary --no-verify`, затем `verify RESULT_ID --source search` (или fetch). MCP: необязательный параметр verify у search/fetch; `qubite_verify(verification_id, source='search'|'fetch')`.

## Фильтры и происхождение выдачи

`POST /api/v1/search` дополнительно принимает `safesearch` (0/1/2, по умолчанию 1), `language` (`all`, `ru-RU`, `en`), `time_range` (`day`, `week`, `month`, `year` или null), `engines` (список имён движков; null = включённые движки категории general). Неизвестные имена и пустой список отклоняются. Строгая безопасность исключает движки без поддержки фильтра; неподдерживаемые умеренная безопасность/дата отмечаются в `filter_warnings`. Для примера: `{"query":"Raspberry Pi 5","mode":"sources","engines":["yandex","yahoo"],"safesearch":0}`.

В ответе `elapsed_ms` — полное время задания, `search_elapsed_ms` — поиск, `engine_timings` — фактические времена движков (null, если измерение отсутствует), `filters` — применённые параметры. Источники сохраняют `engines` — все движки, нашедшие ссылку, а не только один. Измерения получаются из исходного `Server-Timing` без дополнительных поисков. `GET /api/search/config` доступен с браузерной авторизацией и возвращает только ограниченный публичный каталог движков и их возможности; секреты SearXNG не возвращаются.
