# Отклик Kwork → интервью Qubite Brief

В приватной карточке **готового отклика** появилась отдельная кнопка **«Добавить Brief»**.
Она не публикует отклик на Kwork и не пишет заказчику от личного Telegram-аккаунта.

## Как пользоваться

1. Подготовить отклик в Kwork-боте, при необходимости исправить его обычной кнопкой.
2. Нажать **«Добавить Brief»**. Бот сразу подтверждает очередь; создание выполняет отдельный worker.
3. В карточке появится отклик со ссылкой на интервью, кнопки открытия и копирования ссылки.
   Полный текст «Отклик + Brief» копируется по последовательным пронумерованным частям.
4. Проверить текст и самостоятельно решить, где его использовать.
5. В Brief поступит уведомление о новом интервью. После `/start` клиента появятся его профиль
   и переписка. Простое открытие ссылки ещё не передаёт Telegram ID. Клиент подтверждает согласие
   на интервью; готовый PDF отправляется только владельцу.

Ссылка действует **7 дней**, закрепляется за первым клиентом. Повтор кнопки и повтор после
ошибки Telegram используют то же интервью и тот же вариант отклика, без нового ИИ-вызова.
Название, постоянный фокус и переписка существующего интервью не переписываются при повторе.
Просроченные и отозванные приглашения не восстанавливаются автоматически. Управление ими — в Brief.

У новых откликов Haiku возвращает дополнительные внутренние поля `brief.title`, `brief.preset`
и `brief.focus` вместе с обычным JSON отклика. Это один запрос, но его ответ немного длиннее.
Если старый сохранённый отклик этих полей не содержит, используются название и описание заказа
и общий список существенных пробелов. Платной регенерации старого текста ради ссылки нет.
Фокус ограничен одним заказом; предыдущие заказы и их ответы в запрос модели не добавляются.

При длинной карточке показывается последний вариант. Прежние варианты остаются в SQLite и
доступны через существующие кнопки копирования. Правки отклика сохраняют ссылку при отображении;
исходный вариант до добавления ссылки не удаляется.

**Ограничение площадки:** условия Kwork запрещают перенос общения и оплаты вне сервиса;
проверь [условия использования](https://kwork.ru/terms_of_service) перед размещением внешних контактов.
Интеграция сама ничего на площадке не размещает, скидок и условий сделки не обещает.

## Устройство и развёртывание

- `integrations/kwork/kwork_brief.py` — кнопка, короткий owner-only callback, очередь, дополнение карточки.
- `services/specbot/bridge.py` — локальный одноразовый helper. Нет нового HTTP-порта, polling или ИИ.
- `integrations/kwork/install_brief_hooks.py` — точечные hooks для ранней версии репозитория и
  более новой рабочей версии Kwork. Не заменять рабочие `kwork_bot.py` / `kwork_runner.py` старыми
  копиями из репозитория: на Raspberry есть независимые правки вариантов, промптов и вложений.

Перед установкой: приватный backup обоих скриптов и SQLite через `Connection.backup()`, дождаться
завершения активных jobs, остановить только `kwork-bot-poll` / `kwork-bot-work` для замены кода.
Скопировать `bridge.py` в `~/services/qubite-specbot/app/`, `kwork_brief.py` рядом с Kwork-скриптами;
применить patcher к каталогу скриптов и проверить `py_compile`, затем запустить оба Kwork unit.
Перезапуск Brief не нужен: его существующий sender читает durable outbox из той же базы.

Два локальных файла с правами `600` включают интеграцию:

`~/services/qubite-specbot/kwork-bridge.json`:

```json
{"enabled":true,"bot_username":"fdlkfdjflsjdfbot"}
```

`~/services/kwork-bot/brief-integration.json`:

```json
{
  "enabled": true,
  "bot_username": "fdlkfdjflsjdfbot",
  "bridge_python": "/home/kirill/services/qubite-specbot/.venv/bin/python",
  "bridge_script": "/home/kirill/services/qubite-specbot/app/bridge.py"
}
```

Без `enabled:true` кнопки и дополнительные поля ИИ отключены. Для уже доставленных карточек
обновить только `reply_markup`, без платной регенерации и повторной отправки сообщения.

`bridge.py` загружает существующий `private.env` внутри своего процесса. Его содержимое не
возвращается вызывающему коду. stdin содержит только `oid`, `title`, `preset`, `focus`; stdout —
`sid`, `url`, `created`. Команда и пути фиксированы локальной настройкой; данные заказа не становятся
аргументами shell. Worker проверяет точное имя бота, HTTPS origin `t.me` и формат start-токена.

В Brief миграция добавляет `external_invites(source,session)` с уникальными ключами и внешним
ключом к интервью. Создание и уведомление входят в одну SQLite-транзакцию. Детерминированный
HMAC-токен восстанавливается по приватному `data/brief-link.key` (`600`); база Brief содержит
только его хеш. Замена/потеря ключа не создаёт другое приглашение молча. При удалении интервью
связь удаляется каскадно; после этого новый явный запрос может создать новое интервью.

В Kwork отдельная таблица `brief_links` хранит ссылку и текст варианта для повторной доставки;
это чувствительные данные, SQLite и её каталог приватны. Backup должен сохранять базы **обоих**
сервисов, HMAC-ключ и конфигурацию. Не публиковать приглашения, базы или файлы настройки в git.
Удаление карточки Kwork сохраняет уже созданное интервью; закрыть доступ можно в самом Brief.

## Проверка

```bash
PYTHONPATH=integrations/kwork python -m pytest -q integrations/kwork/tests services/specbot/tests
```

Проверяются owner/card доступ, повторные callbacks, отсутствие ИИ-запросов при добавлении ссылки,
повтор после ошибки Telegram, сохранность вариантов, конкурентное создание одного приглашения,
привязка первого клиента, истечение/отзыв ссылки и сохранность focus при повторе.

## Переговоры

Кнопка создания ссылки сама ничего не отправляет клиенту. Отдельная включаемая интеграция
для новых приглашений помогает после паузы/сбоя и оценивает готовое ТЗ. Цена, срок и новый
объём работ подтверждаются владельцем в Kwork-боте. Личный Telegram использует существующую
сессию и blocklist, клиент видит предупреждение до интервью. [Полная инструкция](kwork-negotiations.md).
