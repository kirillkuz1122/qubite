# Qubite Brief: личный Telegram-бот для ТЗ

Отдельный бот, не компонент учётных записей Qubite и не копия чужого исходного кода. Администрирование только в личном Telegram-диалоге владельца. Клиентам нужен персональный `start`-токен. Оплата и веб-админка в эту версию не входят.

## Как пользоваться

1. Открой бота и нажми `/start`.
2. `/new` → выбери «Разработка», «Дизайн», «Маркетинг» или «Любой проект» → напиши название.
3. Отправь полученную ссылку клиенту. Она действует семь дней и закрепляется за первым открывшим её Telegram-пользователем. Каждый проект имеет отдельное интервью.
4. Клиент подтверждает начало, отвечает текстом или голосом. Бот уточняет расплывчатые ответы, противоречия и критерии результата. Можно сделать паузу и продолжить через `/sessions`.
5. При первом входе клиента владелец получает уведомление с именем, @username (если есть) и Telegram ID. Эти данные также видны в карточке интервью; кнопка открывает профиль. Для профиля без username Telegram может ограничить открытие по ID настройками приватности. Владелец получает реплики клиента и ИИ с кнопками управления. «Перехватить» останавливает ИИ; «Написать клиенту» отправляет ручную реплику; «Направить ИИ» меняет последующие вопросы; «Вернуть ИИ» продолжает разговор с сохранёнными ответами.
6. «Завершить интервью» собирает черновик. Клиент видит итоговую сводку требований и может дополнить её. Владелец сразу получает черновой PDF; после подтверждения клиента — PDF и Markdown. Клиент получает только сообщение о завершении.
7. «Файлы» экспортирует PDF, Markdown и структурированный JSON. Предположения, нерешённые вопросы и предварительная сложность выделены отдельно. Сложность не является фиксированной оценкой цены или сроков.

Для личной проверки без второго аккаунта — `/test`. Пиши ответы как клиент, управление остаётся доступно командами. `/stoptest` закрывает тестовый режим. Не отправляй реальные приглашения самому себе: для этого есть тест.

Промпты меняются в `/presets` → шаблон → «Изменить». Обновление применяется к новым приглашениям; для текущего интервью используй «Направить ИИ». Не включай секреты в промпты.

## Команды владельца

- `/new [шаблон] название` — короткий путь создания приглашения.
- `/sessions` — последние интервью с кнопками.
- `/view ID` — переписка; `/take ID` — ручной перехват; `/resume ID` — продолжение ИИ.
- `/say ID текст` — отправить клиенту от имени владельца; автоматически включает ручной режим.
- `/steer ID текст` — указания для следующих вопросов ИИ.
- `/prompt разработка текст` — заменить промпт шаблона (`дизайн`, `маркетинг`, `общий`).
- `/finish ID` — подготовить ТЗ; `/export ID` — файлы.
- `/revoke ID` — остановить интервью и закрыть ссылку.
- `/delete ID` — удаление переписки и файлов после отдельного подтверждения.
- `/budget` — расходы; `/budget 0.05` — дневной потолок **бота**. Лимит ключа OpenRouter задаётся отдельно и не меняется этой командой.
- `/cancel` — отменить ввод настройки.

## Модель и бюджет

Модель: `openai/gpt-6-luna`. Каждый запрос имеет `provider.only` и `allow_fallbacks:false`. Первая попытка — `openai/flex`, запасная — `openai`. Azure, OpenAI Fast и другие провайдеры автоматически не подключаются. Переключение происходит при сетевом таймауте, временной недоступности маршрута (404/408/429/5xx), но не при неверном ключе, исчерпанном балансе или некорректном запросе.

Проверено 07.10.2026 в публичном [каталоге OpenRouter](https://openrouter.ai/api/v1/models/openai/gpt-6-luna/endpoints): Flex $0.05/$0.25, обычный OpenAI $0.10/$0.50 за 1 млн входных/выходных токенов. Цены не фиксируются навсегда; `max_price` запрещает маршрутизацию выше этих потолков.

Потолок по умолчанию $0.05 за день UTC и $0.05 на интервью. На каждую попытку предварительно резервируется консервативная сумма с учётом входного UTF-8 и максимального выхода. После ответа — фактический `usage.cost`. При неизвестном результате таймаута резерв остаётся: запрос мог быть оплачен. Бот не повторяет автоматически прерванный при перезапуске платный запрос. Удаление интервью не сбрасывает денежный счётчик.

Передаётся компактная актуальная сводка, несколько последних учтённых реплик и **все новые** ответы с прошлого обновления сводки. Старые PDF и ответы других клиентов не добавляются в контекст. Очень большой контекст отклоняется с понятным сообщением, без молчаливого удаления требований. ИИ отвечает по строгой JSON Schema; результат дополнительно проверяется локально.

## Голосовые

Вызывается существующий `~/.hermes/user_data/telegram/hermes_stt.py` Python-окружением Hermes. Его настройки STT сохраняются; собственные Whisper-модели и дополнительный STT-сервис не устанавливаются. Клиенту показывается распознанный текст перед продолжением интервью. Поддерживаются голосовые, кружочки и аудиофайлы до пяти минут/12 МБ. Временный аудиофайл удаляется после обработки. Неудачную транскрипцию можно повторить кнопкой, без запуска ИИ с пустым ответом.

Один worker последовательно обрабатывает генерацию/транскрипцию. Polling и отправка сообщений работают отдельно: дорогая операция не блокирует клавиатуру. Настройки API/расходов транскрипции Hermes независимы от отдельного ключа Luna. Сейчас проверенная функция Hermes вернула провайдер `local`.

## Развёртывание и обслуживание

Исходники: `services/specbot/`. Установка из этого каталога:

```bash
bash services/specbot/install.sh
# При первом запуске заполнить приватный файл и повторить установку.
```

Приватный файл: `~/services/qubite-specbot/private.env` с правами `600`; шаблон `services/specbot/.env.example`. `BOT_TOKEN`, `OPENROUTER_API_KEY`, `OWNER_ID`. Ключи никогда не публикуются в репозитории. Владелец задаётся единственным Telegram ID, а не первым написавшим пользователем.

Runtime: `~/services/qubite-specbot/app/`; SQLite и файлы: `~/services/qubite-specbot/data/`. Сервис `qubite-specbot`, включён в автозапуск. HTTP-портов, публичного домена и туннеля нет: используется исходящий Telegram long polling. Другая копия процесса блокируется файловой блокировкой. Если у бота уже настроен webhook, сервис отказывается запускать параллельный polling.

```bash
systemctl status qubite-specbot
journalctl -u qubite-specbot -n 50 --no-pager
sudo systemctl restart qubite-specbot
```

Ограничения unit: CPUQuota=100%, MemoryHigh=450M, MemoryMax=750M, MemorySwapMax=128M, один worker. **На текущей Raspberry memory controller cgroup отсутствует, поэтому лимиты памяти systemd не подтверждены как действующие.** Бот проверяет `MemAvailable` перед STT (минимум 600 МиБ), но это не гарантирует отсутствия конкурирующей нагрузки. Нагрузка локальной транскрипции выше, чем у ожидающего сетевые ответы бота. Проверять реальный RSS через `ps`, а не неподдерживаемый `MemoryCurrent`.

SQLite использует WAL и сохраняет очередь запросов и отправки. Восстановление отправки обеспечивает доставку «как минимум один раз»: при аварии сразу после принятия сообщения Telegram возможен повтор. Доставки с восемью последовательными ошибками помечаются failed; кнопка/ответ, сохранённые у владельца, не означают успешной доставки адресату. Секреты и тексты интервью не пишутся в journal.

Для резервной копии останови сервис и скопируй приватный конфиг вместе с `data/` в защищённое место, затем запусти сервис. Не помещай такие копии в git. Удаление интервью очищает рабочую БД и документы; прежние резервные копии требуют отдельного удаления.

## Проверки и границы

```bash
uv venv /tmp/specbot-tests
uv pip install --python /tmp/specbot-tests/bin/python -r services/specbot/requirements.txt pytest pypdf
/tmp/specbot-tests/bin/python -m pytest -q services/specbot/tests
```

Покрыты доступы, закрепление/отзыв/истечение приглашения, бюджеты, явный fallback и запрет переключения при 402, учёт неопределённого таймаута, перехват во время генерации, сохранение новых реплик, восстановление worker, повтор STT, приватная доставка PDF и кириллица/многостраничность.

Бот не загружает содержимое референсов по ссылкам, не определяет автоматически стоимость работы и не обещает отсутствие ошибок ИИ. Заказчик должен проверить итог, а исполнитель — согласовать открытые вопросы перед договором. Поведение @specflowbot не проверено изнутри: реализован описанный пользователем сценарий и согласованные дополнения.

Проверка 07.10.2026: 22 автоматических теста прошли. Реальные запросы интервью и PDF выполнены через `openai/flex`; при тестовом отказе первой попытки подтверждён реальный ответ через `openai`. Создан и визуально проверен четырёхстраничный PDF, отправленный владельцу. Готовая функция Hermes успешно расшифровала синтетическое аудио, включая запуск с ограничениями этого systemd unit. На проверочные запросы потрачено $0.0012742. Ожидающий бот занимал около 45–55 МиБ RSS; после проверки доступно около 1.3 ГиБ RAM. Это замер, а не нагрузочный тест множества одновременных клиентов.
