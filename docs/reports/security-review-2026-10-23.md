# Проверка безопасности всего кода — 23.10.2026 (SEC-001)

Что проверял: **весь текущий код** Qubite 2.0 в `main` (коммит `62b763d` и раньше) — сервер на
Rust (`crates/*`: вход, сессии, права, синхронизация, Входящие, Planner и файлы проекта,
агент и его инструменты, AI-шлюз, ElevenLabs и прокси, Главная, Telegram-бот, push), сайт
(`apps/web`, `packages/*`), CI (`.github/workflows`), скрипты и git-хуки, зависимости и историю
git. Tauri и Kotlin в репозитории пока нет. `legacy/qubite-v1/` не проверял — только убедился,
что новый код его не подключает (в `Cargo.toml` — только `crates/*`, в `pnpm-workspace.yaml` —
только `apps/*` и `packages/*`, импортов нет).

Каждую находку проверял так: есть ли **настоящий путь** от запроса злоумышленника до вреда.
Теоретические «а вдруг» в таблицу не попали — они в конце, в разделе «Проверено, дыр нет».

## Коротко для владельца

**Критичных и серьёзных (высоких) дыр не нашёл.** Чужие дела, проекты, файлы, документы,
память агента по чужому id не открываются; вход, пароли, cookie и защита от подделки запросов
сделаны правильно; SQL-инъекций нет; ключи AI и токен бота в журнал и ответы не попадают;
сервер не ходит по адресам из данных пользователя.

Нашёл и **исправил три средние** вещи:

1. **Старые библиотеки с известными дырами** (4 штуки): одна позволяла «подвесить» сервер
   особыми запросами HTTP/2, три — про проверку сертификатов HTTPS (сервер мог бы поверить
   отозванному промежуточному сертификату). Обновил до исправленных версий — `cargo audit`
   теперь чистый.
2. **У ответов сервера не было заголовков безопасности.** Теперь у каждого ответа есть
   `X-Content-Type-Options: nosniff` (браузер не «угадывает», что файл — это страница),
   `X-Frame-Options: SAMEORIGIN` (чужой сайт не может встроить Qubite и подсунуть «невидимую
   кнопку») и `Referrer-Policy: same-origin`. Для тебя ничего не меняется.
3. **Проверки на GitHub получали токен с правами по умолчанию** (у старых репозиториев это
   «запись»). Теперь у всех проверок токен только на чтение.

Ещё несколько **мелочей** (низкие) — в таблице; две средние, которые лучше делать вместе с
выкладкой на сервер, — карточка **SEC-002** в `TASKS.md`.

Настоящих ключей в репозитории и истории **новых нет**: в истории те же 23 срабатывания, что и
17.10 (старый `VPN_APP_TOKEN` — риск уже принят, D-136; остальное — ложные). Если VPN когда-нибудь
вернётся — этот токен нужно выпустить заново.

## Проверено, дыр нет

**Вход и сессии.** Пароли — Argon2id, сравнение «пустышкой» при несуществующей почте (по
времени ответа не понять, есть ли аккаунт); лимит попыток по почте и IP под блокировкой,
CAPTCHA после неудач; `X-Forwarded-For` берётся только при `QUBITE_TRUST_PROXY=true` и только
последний адрес. Cookie сессии — `HttpOnly; Secure; SameSite=Lax`, токены хранятся хешами.
CSRF: у всех изменяющих запросов с cookie — заголовок `X-CSRF-Token`; исключения (вход, обмен
кода приложения, вход Telegram, пропуск owner) не пользуются чужой сессией. Сброс пароля —
одноразовый код, 5 попыток, после смены закрываются все сессии. Вход приложений — PKCE S256,
возврат только на `qubite://` или `127.0.0.1`, разрешение — только нажатием кнопки.

**Вход через провайдеров и Telegram.** `state` привязан к cookie браузера; адрес возврата —
только свой путь (`//evil`, `/\evil`, `javascript:` отбрасываются, есть тест); привязка
проверяет, что вернулся тот же человек; чужой аккаунт по совпавшей почте **не** «склеивается»
(ошибка «почта занята»); регистрация «по приглашениям» не обходится через провайдера. Виджет
Telegram — проверка HMAC и срока. Бот: привязка — только одноразовым кодом из профиля (хеш,
срок), сообщения — только из личного чата, от привязанного аккаунта, права проверяются на
каждом сообщении; токен бота в ошибках вырезается (`without_url`).

**Права и чужие данные (IDOR).** Каждый `/api/owner/*` — через `Owner` (остальным 404, есть
страховочный тест на все адреса). Обычные маршруты: `Authenticated` + грант модуля, а объект
ищется с `owner_id`/`account_id` текущего человека — проверил дела, проекты, файлы и документы
проекта, документы, Входящие, ленту агента и откаты, файлы агента и выгрузку, вопросы, навыки,
колокольчик, «английский» (озвучка сообщения — только своё). Синхронизация: чужой объект «не
найден», модуль проверяется и при создании, дело нельзя положить в чужой проект, мысль —
связать с чужой. WebSocket (`/api/v1/sync/ws`, `/api/v1/english/live`) — проверка `Origin` для
cookie, права перепроверяются.

**SQL.** Все динамические запросы (`AssertSqlSafe`, 61 место) собираются только из констант
кода; данные пользователя — всегда через `$1…`.

**Файлы.** Файлы проекта лежат по хешу содержимого (`<root>/ab/cd/<sha256>`), имя файла в путь
не попадает — обхода папок нет. Имя чистится от `/`, `\`, управляющих символов. Отдача: только
картинки и PDF — `inline`, всё остальное (HTML, SVG) — `application/octet-stream` + `attachment`,
плюс `nosniff` и `Content-Security-Policy: sandbox`. Файлы агента — `text/markdown`, `attachment`.
Лимиты: 25 МБ и 200 файлов на проект, тело запроса 2 МБ по умолчанию.

**Сайт (XSS).** Нет `dangerouslySetInnerHTML`, `innerHTML`, `eval`, Markdown в HTML не
превращается. Ссылки из данных: новости — только `https://` (сервер отбрасывает остальное),
ссылки сводки от AI — только `https://`; адрес возврата после входа — `safePath`. Service worker
не перехватывает запросы, открывает только свой сайт.

**AI-шлюз и ключи.** Каждый платный вызов — права → резерв по всем лимитам → вызов; «живое»
распознавание голоса резервирует 120 с и обрывается на них. Ключи (OpenRouter, ElevenLabs,
токены ChatGPT, токен бота) — только из окружения, в ответы API и Console не отдаются, из ошибок
`reqwest` вырезается адрес; адрес прокси в сообщениях — без логина и пароля (`qubite_net::hide`);
при редиректе ElevenLabs показывается адрес без параметров (D-515). Внешний текст — в метках
`untrusted_<одноразовый ключ>`, подделка меток вычищается (есть тест).

**SSRF.** Сервер ходит только на заданные в настройках адреса: OpenRouter, ElevenLabs,
ChatGPT, Telegram, погода/курсы/геокодер/ленты новостей (список зашит, пользователь выбирает
только темы и город), провайдеры входа. Push — только на известные службы push браузеров
(`endpoint_allowed`). По ссылкам из Входящих сервер не ходит.

**Ошибки и журнал.** Уведомление owner о 5xx содержит только метод и путь, без параметров.

**Репозиторий.** `.env` не в git, `.env.example` — без настоящих значений (пароль
`qubite:qubite` — только локальной базы в Docker на 127.0.0.1). CI: нет `pull_request_target`,
в `run:` не подставляется текст из PR. `pnpm audit` — 0 уязвимостей. Скрипты (`dev-db.sh`,
`release.sh`, `env-sync.sh`) не выполняют данные из файлов.
