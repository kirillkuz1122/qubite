# CMD-005a — голосовой ввод, сервер (#219)

Добавлены GET/PUT `/api/v1/voice/prefs` и POST `/api/v1/inbox/voice`.
Все три требуют право записи во Входящие. Облако дополнительно требует
право AI; распознавание идёт только через общий шлюз и `voice.stt`.
Способы device/local используют готовый текст клиента, own_key пока сохраняет
только аудио с пояснением. Локального распознавания на Pi нет.

Решил так, можно откатить: результат приёма хранится отдельно в
`inbox_voice_captures` (миграция 0044 вместе с `voice_prefs`). Поэтому повтор
ID возвращает прежний результат распознавания даже после правки текста.
Блокировка по ID защищает от одновременных повторов. Объект, вложение и
результат приёма фиксируются одной транзакцией через движок синхронизации.
Чужой или занятый другим видом объекта ID получает 404.

Лимиты звука взяты из общего голосового слоя: 1 200 000 байт, до 120 секунд;
JSON до 2 МиБ. Пустые и некорректные записи возвращают 400. На ответ шлюза
отведено 15 секунд из общего HTTP-лимита 30 секунд; при отказе, пустом ответе,
слишком длинном тексте или таймауте остаётся аудио с понятной причиной.

Написаны HTTP-тесты с MockVoice, включая параллельный повтор, вложение,
права и изоляцию аккаунтов, настройки, отказ шлюза и неверное аудио.

По инструкции для этой сессии тесты, сборки и проверки не запускались.
`rustfmt` отсутствует. Сохранённые OpenAPI и TypeScript-типы дополнены
вручную: штатный `pnpm gen:api` запускает Rust-сборку, запрещённую на Pi.
CI должен выполнить проверки и штатную генерацию API; совпадение ручного
описания с выводом генератора пока не подтверждено.
