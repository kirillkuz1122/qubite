### Сделано

Подготовлен [патч клиента](DOC-002e1-client.patch) для issue #152, относительно
`task/DOC-002`, снимок `2b712644427351b1e32972fa1d1c5f7934f009d8`. Прочитаны замечания
[PR #147](https://github.com/kirillkuz1122/qubite/pull/147), решения D-751…D-758
и исходники клиента и сервера.

В патче:

- Повтор своего принятого seed отличает потерянный ответ от чужого переноса:
  первый отправленный вектор хранится в IndexedDB, после `seed_taken` делается
  pull. Свой seed продолжает обычную отправку с сохранением поздних дописок.
- Перед сбросом чужого seed свой Markdown сохраняется в той же транзакции,
  которая очищает журнал. `recovered` и `clearRecovered()` доступны через handle;
  экран предлагает вставку в конец. `open()` после сброса возвращает живой handle.
- `renderText` и фоновый экспорт через Lexical + `@lexical/yjs` получают Markdown
  из слитого дерева. Без этой опции остаётся прежнее поведение.
- Потерянные дописки отслеживает хранилище до первого сетевого слияния, включая
  закрытые документы и Item из прошлых открытий. Список хранится в IndexedDB и
  доступен через `lost`, `onLost()` и `clearLost()`.
- Возврат нескольких блоков сохраняет порядок. Провайдер больше не отслеживает
  потери. Добавлены тесты без сети на эти сценарии и обновлены описания API.

Решил так, можно откатить: передать изменения отдельным патчем к базе задания.
Это позволяет не переносить в текущий `main` целиком DOC-002, включая Rust.

### Не сделано

Патч **не применён к текущему дереву исходников**. Текущий `main` ещё не содержит
`packages/sync-client/src/docs.ts`, редактор `apps/web/src/app/docs/` и решения
`79.md`. Поэтому внести исправления непосредственно здесь без переноса другой
задачи невозможно. Rust, legacy, зависимости и протокол `/y` патч не меняет.

Скриншоты и приёмка интерфейса не выполнены. Локального Prettier нет;
пакеты для форматирования не устанавливались.
