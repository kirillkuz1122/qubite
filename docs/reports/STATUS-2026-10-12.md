## 2. Что согласовано и как делим систему

| Часть | UI | Backend/storage | Действие |
|---|---|---|---|
| Новый platform Auth/Profile/Owner Console/settings/support/analytics | React/TS, полностью новый дизайн | FastAPI/Postgres | реализовать необходимые shared функции заново с behavior compatibility |
| Search внутри Qubite | новый React UI: search/results/answers/history/media | FastAPI platform adapter, работающий Search/engines отдельно | полноценный service slice, сохранять history/ledger/keys/privacy |
| Writing внутри Qubite | новый React editor/highlights/check/AI diff | FastAPI API, LanguageTool/AI adapters | сохранить cancel/UTF16/no-text-log/addon contract |
| VPN внутри Qubite | новый React workspace/settings/devices/nodes | FastAPI domain API, VPN network engines отдельно | сохранить credentials/nodes/subscriptions/native clients |
| Другие собственные included services/new modules | React/TS, общие tokens/components | FastAPI + scoped engine/connector | новые полноценные UI, не только ссылки на старые HTML |
| Qubite Tournaments | прежний Vanilla HTML/CSS/JS/дизайн | Node.js + SQLite | отдельный optional legacy module, без полной переписи сейчас |
| Сторонние native apps/служебные движки | их native UI по необходимости | независимые runtime/data | не переписывать сторонний продукт на React; Qubite controls/grants новые |
| Telegram control bot | новое меню/диалоги, прежнее имя | отдельный Python worker, shared domain API | automatic text/voice capture, support, controls, alerts/digest/app links |
| Desktop | общий новый React UI | Tauri POC + platform adapters | Linux первым, Windows/macOS build/sign/test позже |
| Android | native Kotlin/Compose/Ink; остальные screens/hybrid после POC | local Room/files + shared sync/API | hardware probe и APK verification, без обещаний до теста |

React относится к интерфейсам, не заменяет FastAPI/server engine/VPN tunnel. Свой Web Search redesign и internal knowledge search — разные task tracks. Старый Node/Auth сохраняет работу ещё не migrated consumers только до безопасного cutover. Он не постоянный backend новой платформы. Tournaments не удаляется и не переписывается автоматически.

Owner остаётся ordinary home user, управление в отдельной Console. Default deny/manual module/model grants и budgets, включая owner. Tournament moderator/admin не global platform administrator. Support staff отдельные grants от owner; guest support доступен. Сначала отвечает owner.

Telegram capture: linked user отправляет text/voice без выбора категории; durable original→STT/classify/format→разрешённая note/task/Inbox→исправление/undo/link. При AI/cost/ASR fail исходник сохраняется. Guest → Support; admin/support forced reply не перехватывается capture. Critical events и daily digest связаны in-app/Telegram IDs и ведут в Qubite через authenticated links. Analytics aggregates по умолчанию, private content не logs.

## 4. Первая задача и последовательность

Первой идёт QUB-TEST-001: real legacy server в isolated fixtures, register/login/logout/revoke/reset и OAuth transport mocks; blocked/CSRF/state/PKCE/cookie negative matrix. Реальные ключи/почта/Telegram/live SQLite не используются. Outcome: воспроизводимый Auth compatibility baseline, actual commands/results/report и commit/push. После успешной проверки нельзя считать новую Auth реализованной — это защита для переноса.

Вторая QUB-CORE-001: отдельное FastAPI/Postgres ядро, health/typed contracts/versioned migration на disposable storage, без writes в legacy DB. Outcome: локально запускаемый target foundation и его tests.

Далее QUB-DESIGN-001: новый visual direction/auth/navigation UX, concrete макет, feedback/acceptance. DEPLOY-001 и TG-001 — готовые specification tracks (новый installer manifest и bot parity/commands). Одна primary задача на cycle; остальные ready не начинаются автоматически одновременно.

Затем dependency chain: identity mapping/cutover plan→FastAPI sessions/OAuth/verify/reset/minimal register→policy/settings/mock budget reservation/dispatcher→React shell/Owner Console→owner/Docs-only/revoke/cap acceptance. Service pairs SVC-SEARCH-001→002, SVC-WRITING-001→002, SVC-VPN-001→002: parity/API раньше UI; source data/keys/SSO совместимость раньше switch. Docs/capture/sync/notifications, Linux desktop и Android Ink выполняются отдельными проверяемыми slices по готовности contracts/device gates.

49 tasks сейчас: 1 done (audit baseline), 5 ready (TEST-001/CORE-001/DESIGN-001/DEPLOY-001/TG-001), 43 backlog; in_progress нет. Этот отчёт не запускает тайно новую coding задачу. Ready — можно начать cycle, а не функция уже реализована.

## 5. Как проверяем и продолжаем

Каждая task: read context/status→in_progress и bounded scope→implementation→targeted unit/integration/negative tests→обязательный UI/fixture/device check→review/testing→docs/report/task evidence→commit/push→remote verification. При open UX/device acceptance явно оставляем её открытой. Broad suite запускается при runtime changes/cross-service risks, а не повторяется без необходимости после каждой запятой.

Для migration: backup/restore rehearsal, source/target single writer, count/hash/FK/policy comparison, staging, approval, explicit route/authority switch, rollback preserving new writes. Push не deploy; autodeploy отсутствует по ответу владельца. Хостинг выбираем позже.
