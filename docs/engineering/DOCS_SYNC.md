# Обмен документами (DOC-002a)

Сервер хранит непрозрачное состояние Yjs в `docs_pages.ystate`. Формат —
**lib0/Yjs update v1**, совместимый с `Y.encodeStateAsUpdate` в Yjs 13.6.
На сервере закреплён `yrs = 0.28.0` (MIT). Дерево Lexical сервер не разбирает.
`body` — присланный устройством простой текст для поиска, а до перехода в
редактор — старый Markdown. Клиент отвечает за соответствие `text` своему
документу; после получения чужих изменений обновляет свой текстовый снимок.

## Порядок обмена

1. Без сети устройство создаёт `docs.page` обычной операцией `sync/push`:
   `object_id` — UUID устройства, `title` — заголовок, `fields` отсутствует или
   равен `{}`. После доставки сервер создаёт объект и пустую строку `docs_pages`.
   Повтор операции с тем же `op_id` безопасен, как в остальном sync.
2. `GET /api/v1/docs/{id}/y?sv=<base64>` возвращает
   `{update, sv, seed_markdown}`. Оба бинарных поля — **standard base64 с padding**.
   В query кодировать base64 через `URLSearchParams` (особенно `+`). Нет `sv`
   или пустая строка — полное состояние. Неверный base64 или вектор — 400
   `invalid_update`.
3. Пока `ystate IS NULL`, `seed_markdown` содержит `body`, в том числе пустую
   строку. Клиент переносит Markdown в Lexical и отправляет
   `POST /api/v1/docs/{id}/y` с `{update, text, seed: true}`. Сервер атомарно
   принимает только первый перенос. Второй получает 409 `seed_taken` и должен
   забрать серверное состояние, отбросив свою попытку повторного переноса.
4. Обычная запись — `{update, text}` (`seed` по умолчанию `false`). Допустима
   и при `ystate IS NULL`, например для нового документа. Ответ — `{sv}`.
   Слияние выполняется в транзакции с блокировкой объекта, затем `docs_pages`.
   Ошибка оставляет состояние, текст, версию и историю прежними.
5. Новое состояние вызывает событие `object.updated` с полями `body, ystate`.
   Обычный `/api/v1/sync/ws` будит устройства, затем они делают pull и обмен `/y`.
   Повтор уже принятого обновления игнорирует присланный `text`, не меняет
   версию и не создаёт события. Удаления и обновления, пришедшие раньше своих
   зависимостей, сохраняются; одного сравнения векторов для повтора недостаточно.

Для GET нужны права `docs/read`, для POST — `docs/write`. Чужой, удалённый или
отсутствующий документ — 404 `not_found`; нет гранта модуля — 403.
Cookie-запросы POST требуют обычного `X-CSRF-Token`; bearer — как у остального API.
WebSocket доступен также пользователям, у которых есть чтение только Docs.

## Лимиты и ошибки

| Условие                                                      | HTTP | `error`            |
| ------------------------------------------------------------ | ---- | ------------------ |
| Обновление после base64 больше 512 КиБ                       | 400  | `update_too_large` |
| Полное закодированное состояние больше 4 МиБ                 | 400  | `doc_too_large`    |
| `text` длиннее 200 000 Unicode-символов                      | 400  | `text_too_large`   |
| Битое обновление/base64/вектор, лишние байты после сообщения | 400  | `invalid_update`   |
| `seed: true`, когда состояние уже сохранено                  | 409  | `seed_taken`       |
| Старая правка пытается изменить текст после перехода в Yjs   | 409  | `use_editor`       |

Ответ ошибки — `{error: string, message: string}`, как в остальном API.
Граничные значения включены в разрешённый диапазон. Лимит состояния относится
к байтам v1, а не длине plain text. Независимые обновления могут содержать
структуру редактора, поэтому эти ограничения проверяются отдельно.

## Обычный sync и поиск

`docs.page` разрешает `create` без полей или с `{}`, `set_title`, `delete` и
`restore`. `patch` любых полей, включая `{}`, отклоняется с причиной `invalid`.
Pull возвращает `{preview, has_ystate}`: первые 200 символов plain text;
для старого Markdown разметка убирается, пробелы схлопываются. Полного состояния
и полного текста в pull нет. Заголовок продолжает передаваться полем объекта.

`PUT /api/v1/docs/{id}` продолжает работать для старого Markdown. После
перехода в Yjs он позволяет изменить заголовок с прежним `body` и актуальной
`revision`; изменение текста возвращает `use_editor`. Для одного заголовка
также подходит обычный `set_title` через sync.

`GET /api/v1/docs?q=документы` ищет только среди своих живых документов:
`websearch_to_tsquery('russian', q)`, сортировка по `ts_rank`, затем по времени
и ID. Заголовок имеет вес A, `body` — B. Пустой или отсутствующий `q` сохраняет
прежний список: свежие сверху, до 500 документов.

## Миграция и выбор реализации

Миграция `0043_docs_yjs.sql` добавляет nullable `ystate`, `search` и GIN-индекс.
Заголовок находится в `objects`, поэтому вместо generated column выбраны
триггеры: `body` при вставке/изменении и `objects.title` при переименовании.
Они охватывают HTTP, sync и остальные пути записи. Решил так, можно откатить.
Для снятия Markdown в preview используется `pulldown-cmark` 0.13.4 (MIT),
без HTML-рендера и дополнительных возможностей.

Миграция сама не переводит Markdown в Yjs и не удаляет данные. Перед применением
нужна обычная резервная копия БД. Откат приложения требует сохранить `ystate`:
старый сервер не умеет редактировать это состояние. Чтобы отменить только индекс,
можно отдельной миграцией убрать `docs_search_title`, `docs_search_body`, их
триггеры и поле `search`; `ystate` при этом оставить. Полное удаление `ystate`
не входит в безопасный откат: это потеря содержимого редактора.

## Независимость текста и названия (DOC-002e, #151)

`ydoc::apply` по-прежнему вызывает `objects::bump` с полями `body`, `ystate`:
превью, поиск, ревизия объекта и события пробуждения сохраняют прежний путь.
При `SetTitle` для `docs.page` sync-server блокирует строку объекта, затем
сверяет промежуточные ревизии с журналом `events`. Старую `base_revision`
можно поднять до текущей только при полном покрытии ревизий событиями
`object.updated` с полями `["body", "ystate"]`. Чужое переименование,
удаление/восстановление, неполный журнал и база из будущего остаются конфликтами.
Нового поля или изменения формата `/y` не требуется.
