# Дорога до дела (AGT-006a, #136)

У `planner.task` есть nullable-поля `place_text`, `place_lat`, `place_lon`,
`travel_minutes`. Они читаются через sync/pull и меняются через create/patch
синхронизации. Координаты места задаются парой; `null` очищает поле.
При смене места прежняя дорога сбрасывается. Новый текст без явных координат
сбрасывает и прежнюю точку.

`POST /api/v1/planner/tasks/{id}/route` с телом
`{"from":{"lat":55.12,"lon":61.23}}` требует входа, CSRF и права `planner.write`.
Чужие и удалённые дела возвращают 404 до обращения к картам.

Сервер ищет место по тексту через Nominatim, сохраняет найденную точку, затем
получает автомобильный маршрут OSRM и сохраняет округлённое вверх число минут.
Изменения проходят через синхронизацию: версия, история и очередь напоминаний
обновляются вместе. Если дело успели поменять, ответ — 409, нужен новый расчёт.
Ответ содержит `minutes`, `meters`, `geometry` (не больше 200 точек),
`place_text`, `to`, `provider: "osrm"`, `attribution: "© OpenStreetMap"`.

Ошибки: 400 `place_missing`, 404 `place_not_found`, 503 `route_unavailable`.
Неверные координаты — 400 `invalid`. При выключенном сервисе —
`route_unavailable`; исходное место и ранее рассчитанное время не теряются.
Геокодированная точка остаётся у дела, даже если OSRM не нашёл маршрут.

Настройки читаются при запуске сервера:

| Переменная | Значение по умолчанию |
| --- | --- |
| `QUBITE_ROUTE_ENABLED` | `true`; выключить: `false` или `0` |
| `QUBITE_ROUTE_OSRM_URL` | `https://router.project-osrm.org` |
| `QUBITE_ROUTE_NOMINATIM_URL` | `https://nominatim.openstreetmap.org` |

Адреса — корни сервисов; пути `/search` и `/route/v1/driving/...` добавляет
провайдер. Ключи не нужны. User-Agent:
`Qubite/2.0 (+https://qubiteapp.online)`. Таймаут одного HTTP-запроса — 8 с,
всего расчёта вместе с ожиданием очереди — 25 с. Редиректы запрещены.

Очередь общая на весь процесс: не чаще одного запроса в секунду на хост,
включая обратный поиск города для погоды через Nominatim. Разные хосты имеют
независимые очереди. Успешный геокод (включая «не найдено») и маршруты
кэшируются в памяти на 24 ч; ошибки не кэшируются. Ключ поиска — обрезанный
текст без учёта регистра, маршрута — координаты с точностью 0.001°.
Максимум 4096 записей в каждом кэше; истёкшие удаляются при заполнении.

Исходные координаты человека не передаются в синхронизацию, историю, БД
и сообщения ошибок. Для OSRM точки также округляются до 0.001°, чтобы
геометрия в кэше не удерживала точное исходное положение. Это даёт небольшую
погрешность старта; кэш с округлёнными точками и геометрией живёт только
в памяти. URL и ошибки reqwest с координатами приложение не пишет в журнал.

При автоматическом напоминании известная дорога заменяет прежнюю оценку:
до начала дела остаётся `max(before_minutes, travel_minutes + 10)` минут.
Своё точное время, ручное «за N минут» и выключение напоминания сохраняют
приоритет. Для свободных окон буфер до дела равен его `travel_minutes`;
без него для выхода куда-либо остаётся прежняя оценка из настроек.

Миграция 0042 только добавляет колонки, не меняет существующие значения.
Откат кода не требует удаления колонок. Перед применением миграций нужен
обычный резервный снимок БД; удаление колонок означает потерю мест и требует
отдельного решения владельца. В этой задаче миграция на Pi не применяется.

Решил так, можно откатить: резервные сервисы не подключаются автоматически;
при недоступности карт сервер возвращает понятную ошибку. Ограничение
`travel_minutes` — от 0 до 525600 (год), чтобы не принимать бессмысленные
значения. D-740/D-741 и файл `decisions/78.md` отсутствовали в рабочей копии;
для этой части использован контракт issue #136 и D-394.

Тесты провайдера и HTTP используют только локальный FakeHttp. Запуск проверок
и повторная генерация API переданы CI: на Pi они запрещены заданием владельца.
