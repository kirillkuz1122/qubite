# Личный ключ распознавания (CMD-005d, #226)

По D-854 человек оплачивает сервис сам. `own_key` можно выбрать через
`PUT /api/v1/voice/prefs` до добавления ключа. Web-флаг `OWN_KEY_READY` пока
остаётся выключенным (D-858); его включает отдельная web-сессия после слияния.

Все три метода `/api/v1/voice/key` требуют входа и права Write на `inbox`:

- `PUT`: `{api_key, base_url?, model?}`. По умолчанию —
  `https://api.openai.com/v1`, `whisper-1`. Возвращает только
  `{configured, base_url, model, last4}`. Неправильные данные — JSON
  `{error, message}`, статус 400. Проверка при сохранении не вызывает платный API.
- `GET`: те же безопасные сведения. Если ключа нет — `configured: false`,
  остальные поля `null`.
- `DELETE`: удаляет ключ только текущего аккаунта, возвращает 204, в том числе
  при повторном удалении. Способ распознавания не меняет.

В `voice_keys` хранится только шифротекст `SecretBox`, назначение `voice.own_key`.
Используется уже существующий серверный ключ шифрования `QUBITE_AI_SECRET_KEY`.
Без него сохранение возвращает 409 `secret_key_not_set`; открытый текст в базу
не пишется. GET и DELETE доступны и без ключа шифрования.
Миграция `0049_voice_keys.sql` только добавляет таблицу и не меняет старые данные.
При откате кода таблицу можно оставить; сохранённые ключи не затрагиваются.

Ключ: 16–4096 печатных ASCII-символов без пробелов, URL: до 2048 байт,
модель: 1–256 печатных ASCII-символов без пробелов. URL допускает только HTTPS
без логина, пароля, query и fragment. Локальные, частные, link-local и служебные
IP запрещены, включая ответы DNS. Проверка повторяется перед распознаванием,
все IP проверяются и закрепляются в HTTP-клиенте; редиректы запрещены.

Решил так, можно откатить: **для введённых адресов запрос идёт напрямую**.
Клиент `qubite_net::public_https` отключает прокси только для своих запросов:
иначе прокси может разрешить DNS повторно и направить ключ в частную сеть.
Общие настройки Pi и прокси других провайдеров не меняются. Сервис должен быть
доступен с сервера напрямую; сервисы, доступные только через прокси, пока
использовать со своим ключом не получится.

Распознавание: `POST {base}/audio/transcriptions`, multipart (`file`, `model`,
`response_format=json`, необязательный `language`), ключ в Authorization.
Весь путь от чтения ключа до ответа ограничен 15 секундами; ответ — 256 КиБ,
в том числе без Content-Length. Ограничения аудио общие с `cloud`: 120 секунд,
1 200 000 байт. Ошибки сервиса не отражаются в ответах или логах.

Без ключа, при повреждённом ключе, ошибке адреса, отказе или таймауте сервиса
сохраняются аудио и «Голосовая запись» с понятной причиной. Общая блокировка
ID и `inbox_voice_captures` защищают от повторных вызовов, включая параллельные.
Ключ платформы, UseAi и её денежные лимиты в этом пути не используются.
Результат записывается в **журнал аудита** (`voice.own_key.transcribe`, цель
`inbox_item`, `transcribed`, `cost_usd: 0`), без ключа, URL, аудио и текста.
Журнал расходов AI-шлюза не меняется: он связан с резервированием бюджета
платформы, которое для личного ключа не требуется.

Тесты подготовлены в `voice_key/tests.rs`, `openai_voice/tests.rs` и
`public_https.rs`; существующий `tests/inbox_voice.rs` остаётся общим покрытием
захвата. Используются MockVoice и поддельный сервер на 127.0.0.1. Обход HTTPS
для этого сервера существует только внутри `cfg(test)`, производственной
настройки отключения SSRF нет. Внешних запросов и настоящих ключей в тестах нет.

На Pi проверки и генерация `pnpm gen:api` не запускались по заданию владельца:
генератор вызывает `cargo run`. OpenAPI-аннотации и файлы контракта
`packages/api-client` дополнены без запуска Rust; точное совпадение с генератором
должен подтвердить CI, который уже выполняет `pnpm gen:api`.
