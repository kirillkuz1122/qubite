# Версии документов: сервер DOC-004a

История хранится в `docs_versions` (миграция `0046_docs_versions.sql`). Это полные
снимки Yjs v1 вместе с заголовком и прежним текстом для поиска. Формат `/y` для
существующих клиентов сохранён; новые поля необязательны.

- Перед изменением непустого `ystate` сервер снимает `auto`, если последний снимок
  любого вида был не менее 10 минут назад. Проверка обновления, снимок, запись
  состояния и замена текущих упоминаний происходят в одной транзакции.
- `reason: "restore"` принудительно сохраняет `before_restore`, даже для повтора
  обновления. `restore_of` — справочный UUID источника: снимок мог быть удалён после
  скачивания на устройство, поэтому наличие исходной версии не требуется.
- Прореживание после вставки оставляет не более 100 `auto`. Для снимков старше
  30 дней сначала остаётся последний за каждые сутки UTC. `named` и
  `before_restore` не затрагиваются. Выбор UTC — решил так, можно откатить.
- Связей в снимках нет. Восстановление приходит обычным обновлением поверх текущего
  Y.Doc со своими `text`, `snapshot` и `links`; старый снимок клиента по-прежнему
  не перезаписывает актуальные текст и связи.

API требует `docs` read/write и владельца документа. Чужие документы, версии,
версии другого документа и неизвестные UUID возвращают 404.

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/docs/{id}/versions?before=<RFC3339>&limit=50` | `{versions: [...]}` без состояния; размер страницы 1–50, свежие сверху |
| `GET /api/v1/docs/{id}/versions/{vid}` | Полный снимок: дополнительно `ystate` в standard base64 и `text` |
| `POST /api/v1/docs/{id}/versions` с `{name}` | 201, снимок текущего состояния сервера; без Yjs-состояния — 400 |
| `PATCH /api/v1/docs/{id}/versions/{vid}` с `{name}` | Переименование `named`; для других видов — 409 |
| `DELETE /api/v1/docs/{id}/versions/{vid}` | 204 для `named`; для других видов — 409 |
| `GET /api/v1/docs?deleted=true` | Корзина владельца в `{docs: [...]}`, включая `deleted_at` |

Имя обрезается по краям, затем должно содержать 1–80 знаков Unicode. `preview`
версии содержит первые 120 знаков текста; `size` — байты `ystate`. Курсор `before`
исключает саму границу, при одинаковом времени строки упорядочены по UUID.

Версии в корзине доступны для чтения; запись версий требует живого документа.
Удаление и возврат документа используют существующие операции sync `delete` /
`restore` с актуальной `base_revision`. Удаления документа навсегда и автоочистки
корзины в этой части нет.

Миграция только добавляет таблицу и индекс, существующие документы не переписывает.
Применение — штатным механизмом миграций после резервного копирования БД. Для отката
кода таблицу можно оставить: прежний сервер её не использует. Удаление таблицы
уничтожит историю и требует отдельного решения владельца.

Сценарии для CI: `crates/qubite-server/tests/docs_versions.rs` и тест восстановления
в `docs_links.rs`. API-контракт обновлён также в `packages/api-client`. На Pi сборки,
тесты и `pnpm gen:api` не запускались: последняя команда включает `cargo run`.
