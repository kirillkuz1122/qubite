# Возможности: сбор источников (AGT-005a, #131)

Основа — D-730…D-734 из `docs/product/decisions/77.md` ветки `task/AGT-005`.
В исходном main этого файла и фикстур не было. Решения прочитаны из ветки
задачи через GitHub API; сохранённые Кодолимп и Devpost перенесены оттуда
без изменения содержимого. Codeforces — явно обозначенная тестовая подделка.

`qubite-home::opportunities` разбирает три источника чистыми функциями.
HTTP использует общий `Sources` и `Urls`; тесты направляют все адреса на
`FakeHttp`. Devpost обходится постранично, только для онлайн-мероприятий с
открытым участием. Неоднозначные даты Кодолимпа пропускаются. В рабочем коде
нет мероприятий-примеров, AI-вызовов или обращений к `olimpiada.ru`.

Решил так, можно откатить:

- Даты Кодолимпа без часов — календарные дни Москвы; Devpost — дни UTC.
  Конец дня включителен, 23:59:59. Срок сдачи проекта Devpost не выдаётся за
  срок регистрации. Начало и конец мероприятия Codeforces задаются API.
- Внешний номер Кодолимпа — путь олимпиады, название, предмет, этап, классы и
  дата начала; повтор строки в другом месяце не создаёт дубля. Разные профили
  одного организатора остаются отдельными. Изменение даты начала образует
  новую запись.
- Повторный сбор только добавляет неизвестные записи (`ON CONFLICT DO NOTHING`):
  личные `status`, `why`, идентификаторы и прежние сведения сохраняются.
  Ошибка одного источника не мешает другим, старые строки не удаляются.
- Как у `home_settings` и `calendar_events`, отдельных ролей PostgreSQL и RLS
  нет: каждый запрос списка ограничен `account_id`, который HTTP берёт из сессии.
  POST защищён общей проверкой CSRF. Значения фильтров проверяются на сервере.
- Планировщик в `qubite serve` каждый час ставит одну задачу `opportunities.refresh`
  на активный аккаунт и день UTC. Постоянный ключ в jobs защищает от повторов и
  перезапусков; новые аккаунты подхватываются следующим обходом. Сбой источника
  приводит к штатному повтору jobs, даже если часть новых записей уже сохранена.
- Сеть выполняется до транзакций, параллельно для трёх источников. Весь обход
  Devpost ограничен 20 секундами и 100 страницами; при прерывании источник
  считается недоступным. Сохранение каждого успешного источника — отдельная
  транзакция.

API:

- `GET /api/v1/opportunities?status=&kind=` — `{items: [...]}`, свои записи по
  ближайшему сроку регистрации или начала; неверное значение фильтра — 400.
- `POST /api/v1/opportunities/refresh` — `{inserted, failed_sources}`; если
  недоступны все три источника — 502. Старые записи доступны через GET.

Миграция `0041_opportunities.sql` только добавляет таблицу и индекс; до включения
обработчика можно вернуться к предыдущему бинарнику, оставив таблицу в базе.
Миграция на Pi в этой задаче не применялась.

Тесты добавлены в `qubite-home/tests/opportunities.rs` и
`qubite-server/tests/opportunities.rs`, но на Pi не запускались. Сборки,
проверки и штатный `pnpm gen:api` также не запускались по условиям задачи:
генератор выполняет `cargo run`. OpenAPI и типы клиента дополнены вручную;
CI должен сверить их штатным генератором и выполнить остальные проверки.
