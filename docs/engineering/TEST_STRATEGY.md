# Стратегия тестирования

Цель: каждая задача доказывает, что работает, и ничего старого не ломает. При этом без ритуала «1000 тестов на каждую мелочь»: тестируем поведение и риски, а не количество.

## 1. Пирамида

| Уровень | Чем | Что проверяем | Когда запускается |
|---|---|---|---|
| Unit (Rust) | `cargo test` | Чистая логика: бюджеты, права, парсинг команд, протокол синхронизации | Каждый коммит |
| Интеграция сервера | `cargo test` + временный PostgreSQL | API, транзакции, гонки, миграции, негативные тесты прав | Каждый коммит |
| Unit/компоненты (TS) | Vitest + Testing Library | Логика UI, пакеты `ui`, `motion`, `companions` | Каждый коммит |
| E2E web | Playwright (Chromium; Firefox/WebKit выборочно) | Сценарии пользователя на настоящем сервере и БД | Каждый коммит (основные), полный набор — перед приёмкой |
| Плавность | Playwright + замедление CPU ×4 + замер длительности кадров | Нет длинных кадров во время ключевых анимаций | Задачи UI |
| Доступность | axe-core в Playwright | Контраст, роли, подписи | Задачи UI |
| Desktop | Сборка Tauri в CI + smoke-тест | Запуск, вход, синхронизация | Задачи клиента |
| Android | Unit (JUnit), инструментальные тесты, **ручная проверка на устройстве** | Ink, оболочка, офлайн | Задачи Android |
| Legacy | Существующие 321 тест | Старый код не сломан переносами | Отдельный job CI |

## 2. Обязательные категории

- **Права:** 10 негативных сценариев из [AUTH_AND_PERMISSIONS §6](../architecture/AUTH_AND_PERMISSIONS.md) — автотесты, которые живут всегда.
- **Деньги:** гонки резервирования, повторы, неизвестный результат, смена периода ([AI_COST_GUARD §4](../architecture/AI_COST_GUARD.md)).
- **Данные:** офлайн → онлайн, конфликт двух устройств, повтор запроса, падение процесса посреди записи.
- **Безопасность:** секреты не попадают в логи и ответы API; CSRF; истёкшие и отозванные сессии.
- **Миграции:** с пустой БД и с БД предыдущей версии.

## 3. Правила

- Внешние сервисы (AI-провайдеры, почта, OAuth, Telegram) — только mock в тестах. В CI нет реальных ключей.
- Тест, который иногда падает (flaky), — это баг: чиним или удаляем с записью в TASKS, не перезапускаем «до зелёного».
- Тестовые данные синтетические; реальные данные владельца в тестах не используются.
- Ручная приёмка владельцем — обязательная часть для UI и Ink, её результат записывается в отчёт задачи.

## 4. Команды (появятся в FND-001…FND-003)

```bash
just check          # всё: формат, линтеры, типы, тесты Rust и TS
just test-server    # Rust + временный PostgreSQL
just test-web       # Vitest
just e2e            # Playwright
just test-legacy    # старые 321 тест
```

До появления кода эти команды не существуют; список — целевой.

## 5. CI (GitHub Actions)

- `server`: fmt, clippy (`-D warnings`), tests с сервисом PostgreSQL + pgvector.
- `web`: lint, typecheck, Vitest, сборка, Playwright.
- `desktop`: сборка Tauri (Linux).
- `android`: сборка и unit-тесты (когда появится).
- `legacy`: тесты старого кода.
- `secrets`: сканирование на утечки ключей (gitleaks или аналог).

Красный CI блокирует статус `done`.
