### DOCS-001 — Аудит, перенос legacy, документация и план

- **Зачем:** перезапуск проекта на новом стеке; понятное ТЗ и план вместо разрозненного контекста.
- **Сделано:** старый код перенесён в `legacy/qubite-v1/` (321 тест проходит); контекст — в `docs/context/`; журнал решений, видение, требования, каталог модулей, Owner Console, архитектура, 7 ADR, дизайн-система, помощники (разбор видео), инженерные правила, дорожная карта, задачи; новые README, AGENTS, CLAUDE, SECURITY, `.env.example`.
- **Готово когда:** владелец прочитал и ответил на открытые вопросы из [STATUS](../project/STATUS.md).

### FND-001 — Rust-сервер: каркас, конфиг, PostgreSQL, CI
- **Зачем:** основа всех модулей.
- **Входит:** Cargo workspace (`crates/`), бинарник `qubite` с подкомандами `serve`, `migrate`, `version`; axum, конфиг из env, структурированные логи без секретов; пул sqlx + первая миграция; `GET /api/health`, `/api/ready`; OpenAPI (utoipa); временный PostgreSQL в тестах; GitHub Actions: fmt, clippy, test с Postgres + pgvector.
- **Не входит:** аккаунты, модули.
- **Требования:** PLT-01, PLT-02, PLT-09, OPS-03.
- **Уже известно:** хостинг не ограничен Pi (VPS/сервер/ПК), ориентир по памяти — базовый набор в 2 ГБ ([D-110](../product/DECISIONS.md)); сборка под `x86_64` и `aarch64`.
- **Вопросы владельцу:** берём текущие стабильные версии Rust и PostgreSQL?
- **Готово когда:** `qubite serve` отвечает на health, миграции применяются на пустую БД, CI зелёный.
- **Сделано (17.10.2026):** workspace из трёх crate'ов (`qubite-kernel` — версия, окружение, тип `Secret`, который не печатается в логи; `qubite-db` — пул, встроенные миграции, проверка готовности; `qubite-server` — бинарник `qubite` с командами `serve`/`migrate`/`version`, `/api/health`, `/api/ready`, `/api/openapi.json`, таймаут 30 с, логи pretty/json, аккуратная остановка по SIGTERM). Скрипт `scripts/dev-db.sh` (PostgreSQL 18 + pgvector 0.8.7 в Docker). 10 тестов (2 unit + 8 интеграционных на настоящей PostgreSQL), fmt и clippy чистые. Release-бинарник 11 МБ, память в простое ≈ 9 МБ. CI — `.github/workflows/server.yml`.

- **Вопросы:** нет (технический каркас) — подтвердить, что React 19 + Vite устраивают.
- **Готово когда:** пустое приложение собирается, тесты и сборка в CI зелёные, клиент API генерируется.

### FND-004 — Ядро объектов
- **Входит:** таблицы `objects`, `relations`, `events`, `audit_log`, `file_blobs`, `attachments`, `jobs`; UUIDv7; очередь задач (`SKIP LOCKED`, повторы, идемпотентность); хранилище файлов по хешу; тесты гонок и падения воркера.

### FND-005 — Синхронизация v1
- **Входит:** crate `qubite-sync` (операции, `op_id`, курсоры); `POST /sync/push`, `GET /sync/pull`, уведомление по WebSocket; офлайн-очередь в IndexedDB в web; статусы синхронизации; тесты повторов, конфликтов, офлайна; решение по полной локальной БД в web — ADR.

- **Готово когда:** объект, созданный офлайн в браузере, появляется на сервере после восстановления сети без дублей; конфликт показывается.

### DS-002 — Движок движения и живые элементы
- **Входит:** `packages/motion`: пружины, один общий rAF-цикл с остановкой в покое, жесты (pointer events), rubber-band, отмена жеста; компоненты: кнопка (нажатие, растяжение, возврат), сегменты/навигация с перетекающей подложкой (в т.ч. по тапу на дальний пункт и между рядами), переключатель, ползунок; настройки податливости и длительности, облегчённый режим, reduced motion; тест длительности кадров при CPU ×4.

- **Вопросы:** покажу 2–3 «характера» пружины для каждого элемента — выбираешь ощущение; проверка на Redmi 12 в Firefox ([D-114](../product/DECISIONS.md)).
