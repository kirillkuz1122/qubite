## HAR-001: что решено
Исследование: `docs/reports/harness-research-2026-10-27.md`, начинай с разделов «Топ-10» и «Неожиданные».
- **Документы:**
  - AGENTS.md до 60 строк, STATUS до 80;
  - DECISIONS — индекс по строке на решение + файлы по требованию;
  - задачи — в GitHub Issues: одна карточка на задачу, статус — метка. Владелец за, удобно и сообществу.
  - Цель: новая сессия стартует с 20–30k своего контекста. Ещё ~60k — системная «цена входа», её не убрать; урезать можно только ненужные MCP.
- **Два уровня:** менеджер → сессия задачи. Подагенты — только для поиска, логов и ревью.
- **Codex (ChatGPT) — вторая рабочая сила** для обычного кода по готовому заданию.
  - Вариант 1 (начать с него): `@codex` в GitHub, Codex сам делает PR.
  - Вариант 2: Codex CLI в облачной сессии.
  - Вариант 3: Codex на Pi как MCP-сервер, только с защитой.
  - Код Codex Claude проверяет всегда (D-621); код Claude проверяет Codex.
- **Уровни рассуждения:**
  - менеджер — medium (ставит владелец);
  - дизайн и еженедельная проверка качества — xhigh через файлы агентов `.claude/agents/*.md` или `ultrathink`;
  - max не используем.
  - Свой уровень сессия менять не может: только через агентов с заданным уровнем или новые сессии.
- **Дизайн:** готовые компоненты делаются один раз на xhigh. Автоматическая проверка запрещает «сырые» цвета и отступы, скриншот-тесты сравнивают с эталоном.
- **Единая проверка** `scripts/check.sh` (5–20 строк вывода): её запускают Claude (хук), Codex (через AGENTS.md) и CI.
- **Проверка безопасности** — раз в неделю или когда наберётся пачка задач (D-622).
- **Отчёты:**
  - одна страница-артефакт «Панель Qubite»: что идёт, что готово, что ждёт владельца, сколько потрачено лимита;
  - на ней кнопки выбора, чтобы владелец выбирал из вариантов и получал готовый ответ агенту;
  - проверить, можно ли читать его выбор прямо из данных страницы (ArtifactData), чтобы ему ничего не копировать.
- **Журнал поправок:** каждая поправка владельца — строка в файл. Раз в неделю — разбор: правило, автоматическая проверка или выкинуть. Правила с лимитом «добавил одно — убрал одно».
- **Ночная работа:**
  - будильник в начале окна лимита запускает свежую сессию;
  - сессия берёт верхнюю задачу и обновляет панель;
  - работа останавливается, когда остаётся запас 10%.
- **Шаблоны запланированных задач Claude** (идея владельца): сводка по ревью PR, проверка обновлений зависимостей, заметки о выпуске при слиянии PR (связано с OPS-007).
- Владелец готов подключить любые MCP и скиллы — проси, если нужно.
- Будущее: общий харнес для всех проектов. Пока строим в Qubite так, чтобы потом скопировать.

## Как запускать облачные сессии
- `create_session`:
  - окружение `env_01Tk3trsaQfuJSQbVrhmSCeC`;
  - `outcome_branch: main`;
  - тег `qubite-night`;
  - `permission_mode: auto`. Не `plan`: без человека сессия зависнет.
- Модель выбирай по роли: Opus — сложное и дизайн, Sonnet — обычное; сравнить на одной задаче.
- Одновременно не больше 2–3 сессий.
- Вывод `list_events` бывает огромным, он сохраняется в файл. Разбирай его python-ом, не читай целиком.
- Будильники: `send_later` с временем в UTC. В старую управляющую сессию будильник не пускало («нет доступа»), а в новой сработал точно (D-588).
- Пуш: в `main`. Номера: решения управляющей — с D-623. Перед новым разделом DECISIONS проверь последний номер «## NN»: были повторы.

## Права в сессиях
У владельца стоит режим «авто»: отдельный агент сам решает, можно ли выполнить команду, без вопросов владельцу. Для ночных сессий это то, что нужно: опасное действие просто не пройдёт, и сессия выберет другой путь.
