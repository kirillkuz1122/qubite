## 0. Правила стиля — обязательны для каждого изменения UI (DS-008)

> Владелец 21.10.2026: «элементы выбиваются из стиля, неправильные отступы, цвета, выравнивание… записать правила, чтобы агенты больше так не делали» ([отзыв](../reports/owner-feedback-2026-10-21.md), [D-436](../product/DECISIONS.md)). Этот раздел важнее старых частей документа ниже. Нарушение правила = UI-задача не готова.

### 0.1. Только общие компоненты `packages/ui`

| Нужно | Бери | Нельзя |
|---|---|---|
| Кнопка действия | `Button` (`variant="fill"` — одна главная в контексте, `size="sm"` — в строке) | свой `<button class="…">` с рамкой и заливкой |
| Вкладки, варианты, фильтры | `Segmented` (`variant="chips"` — фильтры с числами). Не помещается в 360 px — сам переходит в ряды | свой ряд кнопок; горизонтальная прокрутка страницы |
| Смена вкладки / вида | `Swap` вокруг содержимого вкладки | `{tab === 'a' && …}` без перехода |
| Модальное окно, настройки блока, подтверждение | `Sheet` (ПК — окно в центре, телефон — нижний лист; Escape, нажатие мимо, фокус) | раскрытие настроек внутри блока; свой `position: fixed` с затемнением |
| Блок появляется / исчезает | `Presence` (соседи — `useFlip`), строки списка — `useLeaving` | `{open && <div>}` рывком |
| Выделение строки / пункта | `useSlide` (подложка перетекает) | `background` у `.on` сменой класса |
| Значок | `DotIcon` — только из точек; новый значок — в `icons.tsx` (сетка 20×20, 8–13 точек). Смена `name` — точки перетекают | эмодзи и символы (⚙, ✕, 🔔), контурные SVG |
| Крупный заголовок | `DotText` (Tiny5 точками); заголовок секции — `SecHead` | обычный жирный текст вместо заголовка |
| Поле, пароль, флажок, переключатель, ползунок | `Field` (`reveal` — глаз из точек), `Check`, `Switch`, `Range` | `<input>` без `Field` |
| Сообщение, ошибка | `Note` (`tone="bad"`), под полем — `error` у `Field` | красный текст своим стилем |

### 0.2. Сетка отступов и раскладка

- Шаг **4 px**: отступы 4 · 8 · 12 · 14 · 16 · 24 · 26 · 40. Других чисел не придумывать.
- Поля экрана: телефон **18 px**, ПК **40 px**; ширина колонки — до 760 px (`.main-in`).
- Секция: `SecHead` — сверху 26 px, снизу 8 px. **Действие секции — справа от заголовка** (детьми `SecHead`: число, «все →», «+ Новый проект»), не отдельной строкой под ним.
- Карточка (`.panel`): внутри 14–16 px на телефоне, 16–24 px на ПК; между карточками 12–14 px.
- Под вкладками (`Segmented`) до текста — 14 px (`.lead`).
- Зона нажатия — не меньше **44×44 px** (у маленьких значков-кнопок — прозрачное поле вокруг).
- Недоступные кнопки (`:disabled`, `[aria-disabled=true]`): `opacity: .45`, `cursor: not-allowed`, прежняя заливка, без реакции на наведение и нажатие.
- Экран 360 px — **без горизонтальной прокрутки**. В CSS-сетках колонки `minmax(0, 1fr)`, у flex-детей с текстом — `min-width: 0`.
- Всплывающее (список колокольчика, меню, подсказки) **не закрывает** шапку с помощником и строку Command.

### 0.3. Цвета — только токены `--q-*`

Никаких `#hex` и `rgb()` в CSS приложения — только переменные из `packages/ui/src/tokens.css` (они есть в обеих темах):

| Токен | Роль |
|---|---|
| `--q-bg`, `--q-panel`, `--q-panel-2` | фон, карточка, вложенная поверхность / наведение |
| `--q-ink`, `--q-mute`, `--q-dim`, `--q-faint` | основной текст, вторичный, подписи, неактивные точки |
| `--q-line`, `--q-line-2` | разделители и рамки карточек; рамка кнопки |
| `--q-orange` | действие и акцент (одна главная кнопка, «новое», число непрочитанного) |
| `--q-sky`, `--q-yellow`, `--q-green`, `--q-peach` | роли: выбор, мысль, успех, помощники — по смыслу, а не для украшения |
| `--q-on-accent`, `--q-veil`, `--q-shadow` | текст на оранжевом, затемнение под окном, тень перетаскиваемого |

Ссылки-действия («все →», «почему →», «Скачать .md») — **без подчёркивания**: цвет `--q-mute`, при наведении `--q-ink`. Подчёркивание — только у ссылок внутри абзаца юридического текста.

### 0.4. Анимации

- Двигаем **только `transform` и `opacity`**, пружинами из `@qubite/motion` через компоненты выше (одна физика, D-142). Ничего не появляется и не исчезает рывком.
- Что чем: раздел — оболочка (`AppShell`); вкладка — `Swap`; окно — `Sheet`; блок — `Presence`; выделение — `useSlide` / `useFlow`; значок — `DotIcon` (перетекание точек); нажатие — `Button` / `usePress`.
- CSS-переходы допустимы только для цвета и `opacity` при наведении (до 0,2 с). Свои `@keyframes` — нельзя, кроме уже существующих коротких (`talk-in`, `q-found`).
- Без `filter`, `backdrop-filter`, анимированных теней, `width/height/top/left` в анимации. «Меньше движения» и облегчённый режим работают сами через `loop()`.
- Тест кадров `e2e/frames.spec.ts` (CPU ×4) — зелёный на CI.

### 0.5. Чек-лист перед коммитом UI (обязателен)

1. Скриншоты **ПК 1440×900 и телефон 360×780** всех затронутых экранов: `node scripts/ui-screens.mjs docs/design/screens/<задача>` (нужны `just dev` и owner; в облаке — `QUBITE_CHROMIUM=/opt/pw-browsers/chromium`). Посмотреть глазами и положить в задачу.
2. На 360 px нет горизонтальной прокрутки; ничего не обрезано и не наезжает (колокольчик, помощник, капля, Command).
3. Каждое переключение (вкладка, вид, окно, раскрытие, значок) — с анимацией из §0.4; только `transform` / `opacity`.
4. Цвета — только токены (`grep -nE "#[0-9a-f]{3,8}|rgb" *.css` в своих файлах пуст), обе темы выглядят нормально.
5. Нет самодельных кнопок, вкладок, модалок, значков-символов — только §0.1.
6. Отступы — из §0.2; действие секции — справа от заголовка.
7. `just check` и `just e2e` зелёные; в STATUS — что посмотреть владельцу. UI-задача готова только после приёмки владельцем.

Главное требование владельца: интерфейс должен **ощущаться живым**. Каждый элемент управления реагирует на касание, тянется, перетекает и возвращается, как вязкий материал. Без «стекла», которое режет глаза, и без дёрганых анимаций, даже на слабом телефоне.

Утверждено владельцем: материал **«Поток»**, палитра **«Игрушечная»**, знаки **«Лента»**, шрифты **Unbounded + Manrope**, темп **100% / 503 мс** ([D-090…D-099](../product/DECISIONS.md)).
Переделывается **с нуля и лучше**: движение, иконки, логотип, тёмная тема, питомцы ([D-096](../product/DECISIONS.md)).

## 1. Что было не так у Codex (и как не повторить)

| Проблема | Причина (вероятная) | Что делаем |
|---|---|---|
| Дёрганые анимации, особенно большая кнопка на телефоне | Анимация градиентов и формы краёв на каждом кадре, перерасчёт раскладки, `ResizeObserver` сбрасывал анимацию | Анимируем **только** `transform` и `opacity`; форма — заранее нарисованные слои/SVG-пути с морфингом через `transform`; ни одного `box-shadow`, `filter`, `width/height` в анимации |
| Выбор «прыгал», а не перетекал | Индикатор ставился сразу в конечную точку | Индикатор — пружина с собственным состоянием; новая цель меняет цель пружины, а не позицию |
| Оболочка без живых элементов | Компоненты витрины не перенесли в продукт | Сначала пакет компонентов `packages/ui`, потом экраны **только** из него |
| Слабые иконки и логотип | Сгенерированы без системы | Своя сетка и правила, ручная проверка владельцем |
| Плохая тёмная тема | Инверсия светлой | Отдельная палитра тёмной темы, свои уровни поверхностей и насыщенности |
| Питомцы «простые, острые, дёрганые» | Нет физики изгиба, жёсткие позы | Деформация от основания, мягкие пружины, эталон — [COMPANIONS.md](COMPANIONS.md) |

## 2. Принципы

1. **Материал реагирует на всё**: наведение, касание, перетаскивание, фокус, ввод, ошибку, успех, загрузку, смену раздела.
2. **Непрерывность**: элемент не исчезает и не появляется из ниоткуда. Кнопка превращается в меню, окно вырастает из точки нажатия, выделение перетекает.
3. **Физика, а не таймлайны**: движение задаётся пружинами (жёсткость, затухание, масса). Прерывание анимации продолжает движение из текущей точки с текущей скоростью.
4. **Пределы**: тянуть можно в пределах, дальше — нарастающее сопротивление (rubber-band). Отпустил — элемент возвращается. Отменённое перетаскивание **никогда** не нажимает кнопку.
5. **Спокойное чтение**: живыми бывают элементы управления, а текст и рабочие поверхности спокойны.
6. **Цвет по роли**, а не по порядку элемента.
7. **Уважение к железу и человеку**: облегчённый режим для слабых устройств, «меньше движения» и `prefers-reduced-motion` сохраняют смысл переходов без физики.

## 3. Токены

### 3.1. Цвет — «Игрушечная» (светлая тема)

| Роль | Токен | Цвет | Где |
|---|---|---|---|
| Основа | `--surface-0` | молочный `#fbf7f0` (уточняется) | Фон приложения |
| Карточка | `--surface-1` | `#ffffff` | Карточки, панели |
| Текст | `--ink` | почти чёрный тёплый `#1d1b19` (уточняется) | Текст, контуры, «тёмный» персонаж |
| **Действие** | `--plastic-action` | оранжевый `#ff9852` | Одна главная кнопка в контексте |
| **Выбор** | `--plastic-select` | небесный `#71cfff` | Выделение навигации, вкладки, ползунки |
| **Мысль** | `--plastic-idea` | жёлтый `#ffe163` | Черновики, Inbox, новые идеи |
| **Успех** | `--plastic-success` | мята `#90dea5` | Включено, сохранено, выполнено |
| **Ошибка** | `--plastic-error` | коралл (подобрать, контраст AA) | Ошибка всегда со значком и текстом, не только цветом |

Правила (из утверждённой версии):
1. Насыщенный цвет — на управляющих деталях и коротких маркерах, а не на текстовых поверхностях.
2. В одном контексте одна главная кнопка действия. Подтверждённое сохранение переводит её в роль «успех».
3. Один яркий токен не используется сразу как мелкий текст, контур и заливка. У каждой заливки свой цвет текста на ней.
4. Фиолетовый как доминирующий цвет запрещён ([D-093](../product/DECISIONS.md)).

### 3.2. Тёмная тема

Не инверсия. Своя шкала поверхностей (тёплый графит, не чистый чёрный), пластиковые цвета **чуть приглушены по насыщенности и светлее по тону**, чтобы не «кричать» на тёмном. Контраст текста AA на всех поверхностях. Варианты (3–5) показываем владельцу в задаче DS-004.

### 3.3. Типографика

- Заголовки — **Unbounded** (широкий, игрушечный характер). Только крупные заголовки и цифры, не мелкий текст.
- Текст и интерфейс — **Manrope**.
- Шрифты подключаются локально (subset кириллица + латиница), без внешних CDN.
- Шкала: адаптивная (`clamp`), отдельные шкалы для телефона и ПК.

### 3.4. Форма и отступы

Скругления «игрушечные», крупные; сетка отступов 4/8 px; минимальная зона касания 44×44 px. Тени — заранее отрисованные, неанимируемые; глубина передаётся смещением и масштабом слоя.

### 3.5. Движение

| Токен | Значение по умолчанию | Смысл |
|---|---|---|
| `flow.duration` | 503 мс | Целевое время перетекания выбора ([D-092](../product/DECISIONS.md)) |
| `flow.pliancy` | 100 (0–100) | Насколько элемент поддаётся пальцу |
| `spring.snappy` | подбирается в DS-002 | Нажатия, переключатели |
| `spring.flow` | подбирается так, чтобы оседание ≈ `flow.duration` | Выделение, навигация |
| `spring.soft` | подбирается в DS-002 | Окна, меню, питомцы |
| `rubber.limit` | подбирается | Предел растяжения |

Пользователь в настройках меняет податливость, длительность, включает облегчённый режим и «меньше движения». Настройки синхронизируются между устройствами.

## 4. Поведение элементов

| Элемент | Поведение |
|---|---|
| Кнопка | Нажатие — короткое сжатие; можно потянуть в пределах, при этом она тянется и слегка вытягивается в сторону пальца; отпустил — упругий возврат; отмена жеста (увёл палец за предел) — без срабатывания |
| Сегменты / вкладки / навигация | Подложка-капля перетекает к выбранному пункту через промежуточные положения, даже при простом нажатии на дальний пункт; её можно тащить пальцем между пунктами; на телефоне умеет переходить между рядами |
| Переключатель | Ручку можно тянуть; переключается по положению, а не по клику; капля растягивается при движении |
| Ползунок | Ручка тянется с инерцией; дорожка заполняется цветом «выбора»; за краем — сопротивление |
| Меню | Вырастает **из** кнопки (кнопка превращается в меню), закрывается обратно в неё |
| Диалог / лист | Вырастает из точки нажатия; на телефоне — нижний лист, который тянется и закрывается свайпом |
| Переход между экранами | Общие элементы перелетают (shared element), остальное — мягкий сдвиг и проявление |
| Поле ввода | Фокус — мягкое подсвечивание и подъём; ошибка — короткое «нет»-покачивание + текст ошибки |
| Qubite Command | Нижняя панель-капля: в покое компактна, при фокусе раскрывается вверх, подсказки выезжают из неё; поднимается вместе с клавиатурой |
| Загрузка | Не «спиннер», а живое переливание материала внутри элемента |
| Наведение (ПК) | Элемент тянется к курсору на несколько пикселей (магнетизм) |

## 5. Производительность — жёсткие правила

1. Анимации — только `transform` и `opacity`; слои с `will-change` только на время анимации.
2. Физика считается в одном общем цикле `requestAnimationFrame`; когда всё успокоилось — цикл останавливается (нет вечного idle-цикла).
3. Никаких `filter: blur`, `backdrop-filter`, анимированных градиентов и теней в продакшн-компонентах.
4. Чтение раскладки (`getBoundingClientRect`) — только до начала анимации, не на каждом кадре.
5. Облегчённый режим включается автоматически на сенсорных слабых устройствах (эвристика + ручной выбор).
6. Бюджет: 60 к/с на эмуляции 4× замедления CPU в Chromium; проверяется автоматическим тестом с записью длительности кадров. Финальная приёмка — владелец на своём телефоне.
7. Холсты с точками (`DotEngine`) не рисуют за экраном и не перерисовываются, пока их точки стоят ([D-541, D-542](../product/DECISIONS.md)). Новый холст или сцену — только через `DotEngine`, свой `requestAnimationFrame` для холста не заводить.

## 6. Иконки и знаки

- **Иконки:** своя сетка 24 px, единая толщина линии, скругления в духе «игрушечного» стиля; набор для навигации, модулей, действий, статусов. Источник — SVG в `packages/ui/icons`, проверка контраста и размера.
- **Логотип Qubite (семейство «Лента»):** знак обыгрывает Q и/или кубит (сфера Блоха, суперпозиция двух состояний); работает в 16 px и на тёмном. У каждого модуля свой знак в той же системе.
- Задача DS-005: 3–5 вариантов знака и набора иконок → выбор владельца → финальная сборка.

## 7. Доступность

Контраст AA, видимый фокус (тоже «живой»), полная работа с клавиатуры, подписи у всех иконок-кнопок, `aria-current` / `aria-pressed` у выделений, reduced motion, масштабирование до 200% без поломок.

## 8. Как проверяем

- Витрина компонентов (`apps/web` → `/design`) — живая, на настоящих компонентах `packages/ui`.
- Автотесты: отмена жеста не нажимает кнопку; перетекание проходит промежуточные точки; reduced motion; контраст; длительность кадров при замедленном CPU.
- **Владелец принимает** каждый компонент на телефоне — без этого компонент не «готов».

| 0. Бриф | Смотрит старую лабораторию (поведение), Claude, Liquid Glass, видео-эталон; пишет короткий бриф | Подтверждает |
| 1. Основа | Цвета, фон, шрифты, размеры, скругления на `/design`, 2–3 варианта | Фон, схема цветов модулей, крупность |
| 2. Лаборатория ощущений | Движок пружин + кнопка, переключатель, ползунок, выбор пунктов; у каждого ползунки настроек | Подбирает ощущение на Redmi 12 |
| 3. Превращения | Меню из кнопки, окно из точки, переходы, капсула Command | Какие переходы нравятся |
| 4. Тёмная тема | 3 варианта | Выбор |
| 5. Иконки и логотип | Сетка, 3–5 вариантов знака | Выбор |
| 6. Помощники | Элик, Прото, Нейт, Фоти по видео-эталону | «Живые и мягкие» |
| 7. Оболочка | Главная, навигация, каталог — из принятых деталей | Финальная приёмка |

Каждый шаг: скриншоты + видео (Playwright), замер кадров при CPU ×4, ссылка для телефона (временный туннель Cloudflare), «принято» владельца. Главное правило ([D-142](../product/DECISIONS.md)): **одна физика и одни правила движения для всех элементов** — не набор отдельных анимаций.

Стили-варианты ([D-146](../product/DECISIONS.md)): «Поток», «Жидкое стекло», «Пиксель», «Пластилин», «Тёплая бумага» — переключаются в лаборатории, физика у всех общая. Главный эталон движения — Apple Liquid Glass ([D-145](../product/DECISIONS.md)). Правило «без `backdrop-filter`» из §5 пересматривается по замерам на Redmi 12.
