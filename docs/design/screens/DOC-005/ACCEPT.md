# DOC-005b — визуальная проверка Markdown

5 ноября 2026. Chromium, dev-сервер на локальном адресе, изолированный профиль и поддельный API из `apps/web/e2e/docs-mock.ts`. Данные владельца не использовались. Размеры: 1440×900 и 360×780, светлая и тёмная темы. В каждом имени кадра указаны ширина и тема.

| Кадр | Результат |
|---|---|
| `*-empty.png` — пустой список и обе кнопки импорта | В норме: элементы видны; на 360 px кнопка импорта переносится на отдельную строку. |
| `*-document.png` — открытый документ | В норме: все четыре действия видны; на 360 px размещены в два ряда. |
| `*-import-ok.png` — два файла | «Загружено 2 из 2» видно. Замечание: сразу после импорта на некоторых кадрах под созданными документами написано «Пустой документ», хотя в файлах был текст; открытый «Первый» содержит «Текст первого». Требуется отдельно проверить обновление превью. |
| `*-import-error.png` — один неподходящий файл и один корректный | В норме: «Загружено 1 из 2», имя `плохой.pdf` и причина ошибки видны; второй файл добавлен. |
| `*-focus.png` и `*-focus-import.png` | В норме: у «Скачать .md» и верхней «Импорт .md» видна оранжевая рамка фокуса при клавиатурном режиме. |

На всех четырёх комбинациях ширина страницы равна ширине окна, горизонтальной прокрутки нет. Измеренные кнопки «+ Документ», оба «Импорт .md», «Создать первый документ», «К документам», «Скачать .md», «История» и «Удалить» имеют высоту 44 px и ширину более 44 px. Проверка скачивания в каждой комбинации: имя `Первый.md`, UTF-8 содержимое `Текст первого`, без добавления заголовка в тело.

Селекторы: `getByLabel('Импорт Markdown')` — скрытый файловый input; `getByRole('button', { name: 'Импорт .md' })` возвращает две кнопки в пустом состоянии, для верхней нужен `.first()`. Документ выбирался по `getByRole('button', { name: /^Первый/ }).first()`. Ошибка намеренно вызвана выбором `плохой.pdf` через input: обычный системный диалог фильтрует расширения. Рамка фокуса проверена после включения клавиатурного режима клавишей Tab и установки фокуса; полный порядок обхода клавиатурой не проверялся.

Это проверка в браузере с имитацией API, не проверка реального сервера. Приёмка внешнего вида владельцем остаётся открытой. Полные тесты и сборка на Pi не запускались.

Dev-сервер сообщил `ECONNREFUSED` для `/api/platform/status`: настоящий сервер намеренно не запускался и этот запрос не был покрыт поддельным API. Экраны документов и операции выше при этом удалось проверить; статус платформы не проверен.
