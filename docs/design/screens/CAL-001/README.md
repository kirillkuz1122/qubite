# Календарь (CAL-001): проверка по DESIGN_SYSTEM §0.5

Снимки сделал Chromium (Playwright) на ПК 1440×900 и телефоне 360×780, тёмная и светлая тема.
**Сервер не запускался:** вход и синхронизацию подменили моки из `apps/web/e2e`, ответ `/api/calendar`
сделан по образцу настоящего (события, дела, уроки; таймзона платформы Asia/Yekaterinburg).
Серверная часть проверена тестами CI, настоящее приложение владельцу смотреть отдельно.

Имя файла: `вид-устройство-тема.png`. `cluster10-*` — три одновременных события в 10:00,
`cluster14-*` — три по 15 минут подряд в 14:00; `empty-*` — пустой день; `form-*` — форма «Новое событие».

## Найдено и поправлено

- «ещё N» переносилось на две строки («ещё / 2») — теперь в одну (`calendar.css`).

## Найдено, оставлено (решение владельца / отдельная задача)

1. **Неделя на ПК тесная:** колонка страницы до 760 px (§0.2), семь дней — по ~90 px, названия переносятся
   посреди слова («План/ёрка»), одновременные записи уходят в «ещё N». Хочется шире, как в Google Календаре.
2. **Строка «весь день»:** в каждом дне кнопка «Создать» — семь рамок в ряд, шумно; лучше компактный «+».
3. **Форма на ПК (900 px по высоте):** кнопки «Сохранить» и «Удалить» ниже видимой части, окно прокручивается.
4. **Телефон:** шапка раздела (заголовок, вид, кнопки, легенда, пояс) занимает ~420 px, сама шкала
   видна в нижней трети экрана; плавающая панель закрывает низ шкалы.
5. Время в форме показано как `09:00 AM` — это язык браузера для проверки (en-US), не дефект.
