## 3. Что решено (кратко, подробно — D-951…D-961)

- Светофор читается сверху вниз за 2–5 секунд: **сколько осталось** (две шкалы, LOW ниже 15%) → **три цифры** (работает · ждёт тебя · готово) → **что ждёт тебя** → расход за неделю.
- «Ждёт тебя» — только решения владельца, 0–3 карточки с кнопками прямо в строке; пусто — Прото «Ничего не ждёт тебя».
- В карточке агента — задача, модель, контекст шкалой, цена, кэш тёплый/холодный, PR и история событий, которую пишет код (0 токенов).
- Крупные числа — текстом «Число 32», точки — для шкал, графиков и заголовков (D-954).
- Дорогое везде выглядит одинаково: оранжевая рамка, «≈ N% недельного лимита», «Да / Нет / дешевле» — в Пульте, Command и Telegram (D-944).
- Под каждым ответом диспетчера — «не то? это вопрос / это мысль» и какая модель ответила за сколько (D-960).

## 4. Под вопросом (решает владелец)

> **Ответы 17.11:** 1 — лимиты сверху (D-962); 2 — % лимита главным, $ мелко (D-963); 3 — переключатель 2D/3D, начинаем с 2D везде (D-964); 5 — 5% недельного лимита (D-965); 4 — Command растёт по ходу разговора (D-966).

1. **Что на телефоне сверху:** лимиты (как нарисовано) или «ждёт тебя», а лимиты — одной строкой? Рекомендую лимиты: без них нельзя решить, что запускать.
2. **В чём считать расход:** ≈ $ по ценам API (нарисовано), % недельного лимита или ₽? На подписке доллары — оценка; % лимита честнее, но не видно «дорого/дёшево» между неделями. Рекомендую % лимита главным, $ — мелко.
3. **Карта на ПК:** сфера с орбитами (нарисовано) или только кольца без сферы? Сфера красивее, кольца в 2–3 раза проще в коде. Рекомендую начать с колец, сферу — вторым шагом.
4. **Command на телефоне:** чат на весь экран (нарисовано) или маленький лист снизу, как сейчас? Весь экран — видно ответ и план; лист — быстрее «записал и ушёл». Рекомендую весь экран только для вопроса и поручения, мысль — тостом без открытия.
5. **Порог «дорогого»:**  за запуск (нарисовано), 5% недельного лимита или «всё на Fable/Opus»? Рекомендую 5% недельного лимита — понятно без пересчёта.

Технические мелочи (агент решил сам): телефон 390 px (D-951), старый `Dock` заменить в коде, светлая тема нарисована только для Светофора.

## Command в AOS-5h

Строка ввода находится в нижней части окна беседы. На телефоне первая реплика показывается в полупрозрачном листе, на второй окно занимает экран. Под ответом видны модель и её фактическая цена. Подтверждение показывает оценку запуска отдельно.

В карточке агента «Открыть сессию» появляется при наличии ссылки от сборщика. Кнопки из макета «Остановить» в этой версии нет. Для задачи и PR используются прежние ссылки. Подробности — D-1043…D-1045.

Снимки окна Command (Chromium, моки ответов диспетчера, тёмная и светлая темы) — [screens/AOS-5h](screens/AOS-5h/): ПК 1440 — `command-pc-popover` (первая реплика), `command-pc-expanded` (после «Развернуть»), `command-pc-confirm` (дорогое, ждёт «Да, запустить»), `command-pc-confirmed` (после «да»); телефон 360 — `command-phone-overlay` (лист поверх экрана), `command-phone-full` (со второй реплики на весь экран), `command-phone-confirmed`. Замечено при снимках: на телефоне подсказка в строке обрезается до «Спроси или» (место занято кнопками) — мелочь, в задачу приёмки.

## 6. Облачные сессии и сборщик по таймеру — AOS-5i (20.11.2026)

Решения — D-1070…D-1077 ([decisions/103.md](../product/decisions/103.md)). У облачных сессий токены и лимиты сервер сам не видит, их знает только управляющая сессия. Поэтому два источника, оба шлют один и тот же `POST /api/pult/report`:

| Источник | Что присылает | Кто и когда |
|---|---|---|
| **ПК** (`source: pc`) | сессии ПК, расход по дням, навыки, лимиты из строки состояния | `pult_collect.py once` по таймеру systemd каждые 2 мин |
| **Облако** (`source: cloud`) | облачные сессии: модель, контекст, токены (цена считается на сервере), лимиты 5ч/7д из событий сессий | менеджер вызывает `scripts/pult_cloud.py` на каждом будильнике (≈ раз в 40 мин), см. [MANAGER.md](../harness/MANAGER.md) |

Лимиты в Светофоре — самые свежие из обоих источников (счётчик подписки один). Блок «Источники» внизу Светофора показывает обе записи; нет сводки — серая запись с причиной («управляющая сессия ещё не присылала сводку»), цифр никто не выдумывает.

### Установка сборщика на ПК (делает владелец, агент на ПК ничего не ставит)

1. В Пульте → «Подключить ПК» выпустить токен, положить в `~/.config/qubite/pult.env` строкой `QUBITE_PULT_TOKEN=qpult_…` (файл — только для себя: `chmod 600`).
2. В репозитории посмотреть план: `scripts/install-pult-collector.sh`. Он только печатает, что будет сделано.
3. Установить: `scripts/install-pult-collector.sh --apply` — копирует сборщик в `~/.local/share/qubite/`, юнит и таймер — в `~/.config/systemd/user/`, включает `qubite-pult-collect.timer`.
4. Проверить: `systemctl --user list-timers qubite-pult-collect.timer` и `journalctl --user -u qubite-pult-collect -n 5` («Отправлено: сессий N»). В Пульте внизу появится «ПК …» с зелёной точкой.
5. Чтобы таймер работал и без входа в систему: `loginctl enable-linger $USER` (один раз, по желанию).
6. Убрать: `scripts/install-pult-collector.sh --remove`.

Лимиты на ПК по-прежнему идут из строки состояния Claude Code (`pult_collect.py statusline`, начало скрипта): нет её — «сессии есть, лимитов нет».

### Токен облака

Для сводки облака нужен второй токен сборщика (имя «Облако»). Он попадает в управляющую сессию только через `request_credential` (хост `qubiteapp.online`) или как секрет окружения; в git и в чат его не кладём (D-1075). Без него менеджер пишет в отчёте «сводку облака не отправил».
