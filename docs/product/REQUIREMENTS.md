# Реестр требований Qubite

Каждое требование имеет ID, приоритет, источник и критерий готовности. Задачи в [plan/TASKS.md](../plan/TASKS.md) ссылаются на эти ID.

**Приоритеты:** `MVP` — нужно для ежедневного использования владельцем; `P2` — следующее расширение; `P3` — большой отдельный релиз; `R&D` — сначала исследование.

**Источники:** `MC §N` — раздел [мастер-контекста](../context/QUBITE_MASTER_CONTEXT.md); `AC` — [политика доступа](../context/QUBITE_ACCESS_AND_OWNER_CONSOLE.md); `D-NNN` — [журнал решений](DECISIONS.md); `I-NN` — номер идеи из каталога 48 идей (MC §20).

**Как читать критерий:** это проверка, после которой требование можно считать выполненным. Если её нельзя автоматизировать (ощущение пера, плавность), владелец проверяет вручную.

## 1. Платформа и ядро (PLT)

| ID | Требование | Приор. | Источник | Критерий готовности |
|---|---|---|---|---|
| PLT-01 | Модульный монолит на Rust: один сервер, модули — отдельные crate'ы с явными границами | MVP | MC §19.1, D-003 | Модуль нельзя импортировать в обход его публичного API (проверка в CI) |
| PLT-02 | PostgreSQL + pgvector на сервере, миграции версионируются и применяются автоматически | MVP | D-004 | Чистая установка поднимает схему с нуля; откат миграции описан |
| PLT-03 | Общий «конверт» объекта: `id` (UUIDv7), `type`, `owner_id`, `workspace_id`, `visibility`, даты, `revision`, `created_by`, `source_refs` + типизированные таблицы модулей | MVP | MC §19.2 | Любой объект любого модуля находится по `id` через ядро |
| PLT-04 | Типизированные связи между объектами (`Relation`) с проверкой прав в обе стороны | MVP | MC §19.2, §3 | Связь не раскрывает заголовок объекта, к которому нет доступа |
| PLT-05 | Журнал событий и аудит действий (append-only) | MVP | MC §16.2 | Каждое изменение прав, бюджета и данных имеет запись: кто, когда, что, на каком основании |
| PLT-06 | Файлы и медиа: локальное хранилище с адресацией по хешу содержимого | MVP | MC §16.2 | Повторная загрузка одинакового файла не дублирует его на диске |
| PLT-07 | Фоновые задачи на очереди в PostgreSQL: повторы, таймауты, идемпотентность | MVP | MC §19.1 | Падение воркера не теряет задачу и не выполняет её дважды |
| PLT-08 | WebSocket/SSE: уведомления, прогресс задач, синхронизация | MVP | MC §19.1 | Обрыв соединения восстанавливается без потери событий |
| PLT-09 | OpenAPI-описание всего API, TS-клиент генерируется из него | MVP | MC §19.1 | В CI сгенерированный клиент совпадает с закоммиченным |

| ID | Требование | Приор. | Источник | Критерий готовности |

| AUTH-01 | Вход по email и паролю, хеш Argon2id, ограничение попыток | MVP | D-050 | Пароль не хранится и не логируется в открытом виде; перебор упирается в лимит |
| AUTH-02 | Сессии: защищённая cookie (HttpOnly, Secure, SameSite), CSRF-защита, список своих сессий, выход, «выйти везде» | MVP | D-051 | Отозванная сессия сразу теряет доступ ко всем API и WebSocket |
| AUTH-03 | Owner создаётся командой установщика/CLI; публичного способа стать owner нет; owner один | MVP | D-052, D-053 | Повторный запуск команды не создаёт второго owner; нет HTTP-маршрута назначения owner |
| AUTH-04 | Режимы регистрации: закрыта / по приглашениям (по умолчанию) / открыта | MVP | D-056 | Переключение в Owner Console сразу меняет поведение формы и API |
| AUTH-05 | Приглашения: на конкретную почту и общая ссылка; одноразовые, срок 7 дней, отзыв; ввод ссылкой или кодом | MVP | D-057 | Повторное использование приглашения отклоняется; одновременная регистрация по одной ссылке даёт одного победителя |
| AUTH-06 | Подтверждение почты обязательно до входа; восстановление пароля по подтверждённой почте отзывает все сессии | MVP | D-058 | Неподтверждённый аккаунт не может войти |
| AUTH-07 | OAuth: Google, Яндекс, VK, Telegram; привязка только из открытого аккаунта; совпадение почты не объединяет аккаунты | MVP | D-060 | Попытка входа через провайдера с почтой существующего аккаунта не даёт к нему доступа |
| AUTH-08 | Вход нативных приложений (Android, desktop) через системный браузер + PKCE; отдельные отзываемые сессии устройств | MVP | D-034 | Приложение получает токен устройства; его отзыв в профиле блокирует приложение |
| AUTH-09 | Тумблеры платформы: регистрация, вход, техработы, каждый способ входа, почта, глобальный запрет входа | MVP | D-059 | Выключенный способ входа скрыт в UI и отклоняется API, включая уже начатый OAuth |
| AUTH-10 | Ограниченные API-ключи для расширений, агентов и MCP: scope, срок, отзыв, отдельные бюджеты | P2 | D-051, MC §15.2 | Ключ не может сделать больше своего scope и прав владельца ключа |
| AUTH-11 | Вход через ChatGPT; использование личного плана ChatGPT отдельно от гранта на API владельца | P2 | D-061 | Сначала исследование условий OpenAI, отчёт владельцу |
| AUTH-12 | Двухфакторный вход (почта/TOTP/passkey) | P2 | MC §19.5 | Включается пользователем; восстановление описано |
| AUTH-13 | Защита от ботов на регистрации (CAPTCHA: Turnstile или Yandex SmartCaptcha) | MVP | legacy | При открытой регистрации без капчи форма не отправляется |
