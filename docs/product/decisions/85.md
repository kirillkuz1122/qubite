# 85. Версии документов и восстановление (DOC-004, 3.11.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Сделала сессия задачи DOC-004 (#66) по D-751, D-752, D-757, D-758. Блок номеров D-810…D-819. Образцы поведения: Google Docs (история версий справа, «Восстановить эту версию», именованные версии), Notion (история страницы, откат).

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-810 | **Разбивка DOC-004:** a — сервер (таблица версий, автоснимки, API, корзина документов); b — клиент `packages/sync-client` (список, загрузка, восстановление правкой поверх, офлайн); c — экран (панель «История», просмотр, сравнение, «Восстановить», корзина); затем проверка вёрстки (designer, ПК и 360 px). Части идут по очереди из-за общей очереди Codex. | CONFIRMED | агент, можно откатить |
| D-811 | **Версия — полный снимок Yjs-состояния** (`docs_versions`: документ, владелец, вид, имя, заголовок, `ystate`, `text` Markdown, время, кто). Виды: `auto` (автоснимок), `named` (именованная), `before_restore` (состояние перед восстановлением). Снимок полным состоянием, а не цепочкой правок: просто читать и сравнивать, а размер ограничен 4 МБ документа (D-751). | CONFIRMED | агент, можно откатить |
| D-812 | **Автоснимки:** сервер при `POST /y` перед слиянием смотрит на последний снимок; если прошло ≥ 10 минут и состояние меняется — кладёт снимок **состояния до этой правки** (вид `auto`). Так перед долгой сессией правок всегда есть «как было». Автоснимков хранится до 100 на документ: старше 30 дней оставляем по одному в сутки, остальное убираем. Именованные и `before_restore` не убираются никогда, пока жив документ. | CONFIRMED | агент, можно откатить |
| D-813 | **Именованная версия:** кнопка «Сохранить версию» с именем (до 80 знаков) снимает **текущее состояние сервера**, а не локальное: сначала устройство досылает правки (`sync`), потом просит снимок. Без сети кнопка неактивна с подсказкой «Нужна связь: версия снимается на сервере». Переименовать и удалить можно только именованные. | CONFIRMED | агент, можно откатить |
| D-814 | **Восстановление — новая правка поверх, ничего не теряем:** устройство строит Y.Doc из снимка и в одной транзакции заменяет содержимое текущего документа копией содержимого снимка. Это обычное обновление Yjs: оно лежит в IndexedDB, уходит при связи и сливается с правками других устройств, как любая другая правка. Запись в историю: обновление уходит с `reason: "restore"` и номером версии — сервер **принудительно** кладёт снимок `before_restore` (состояние до восстановления). Восстановить можно и без сети (снимок уже скачан), `before_restore` появится при отправке. | CONFIRMED | агент, можно откатить |
| D-815 | **Просмотр и сравнение — на устройстве:** версия показывается только для чтения теми же блоками, что и редактор. Сравнение с текущим — по блокам (длиннейшая общая подпоследовательность по виду и тексту), внутри изменённого блока — по словам. Цвета: добавлено — токен успеха, удалено — токен опасности + зачёркивание (не только цвет, D-DS). Чистая функция `diffBlocks`, тесты без DOM. | CONFIRMED | агент, можно откатить |
| D-816 | **Корзина документов:** у документа появляется «Удалить» (мягкое удаление объекта ядра, `deleted_at`, D-199-образец «в архив, не навсегда»). В «Документах» — раздел «Корзина»: список удалённых, «Вернуть» (операция `restore` движка синхронизации, работает офлайн), «Удалить навсегда» — только после подтверждения и только для документов из корзины. Автоочистки нет (удаление данных — решение владельца). | CONFIRMED | агент, можно откатить |
| D-817 | **Права и 404:** `GET/POST …/versions` — права `docs` read/write, чужой документ и чужая версия — 404; версии удалённого документа читаются, пока он в корзине. Размер списка — страницы по 50. | CONFIRMED | агент, можно откатить |
| D-818 | **Вёрстка истории (по §0 DESIGN_SYSTEM):** ПК — панель справа (≈ 320 px) рядом с редактором, список по дням, именованные сверху с пометкой; выбор версии открывает просмотр в области документа с лентой «Версия от … · Восстановить · Сравнить с текущей · Закрыть». Телефон 360 px — экран «История» поверх, список; просмотр — на весь экран, кнопки «Восстановить» и «Сравнить» — в нижней панели, попадание ≥ 44 px. Восстановление просит подтверждения одной строкой («Текущий текст сохранится в истории»). | CONFIRMED | агент, можно откатить |
| D-819 | **Не делаем в DOC-004:** авторы правок внутри версии («кто что написал»), совместное восстановление части документа, версии вложений. Идеи — отдельными issue при необходимости. | CONFIRMED | агент, можно откатить |
| D-816а | **Уточнение D-816 по итогам:** «Удалить навсегда» и автоочистка корзины **не сделаны**: на сервере нет такой операции, а удаление данных — решение владельца. В корзине подсказка «Документы остаются в корзине, пока вы их не вернёте». Корзина показывает локально удалённое (работает без сети) вместе с `GET /docs?deleted=true`. | CONFIRMED | агент, можно откатить |
| D-816б | **Сравнение версий:** пустые абзацы, целиком добавленные или удалённые, правкой не считаются; UUID упоминания в сравнении — одно слово; общие начало и конец блока отсекаются до сравнения, на огромной середине (> 4 млн ячеек) общих слов не ищем (замечание ревью: квадратичная работа). | CONFIRMED | агент, можно откатить |
| D-816в | **Восстановление версии:** документ должен быть загружен на устройство (иначе пустое дерево не заменило бы серверные блоки); обновление-восстановление больше ~480 КБ отклоняется с понятной ошибкой, пока сервер принимает до 512 КБ (D-751). | CONFIRMED | агент, можно откатить |
| D-816г | **Приёмка вёрстки истории и корзины (designer):** панель «История» на ПК — «Закрыть» справа от заголовка, подтверждение с названием действия; на 360 px главное действие первым, кнопки ≥ 44 px, без горизонтальной прокрутки.
