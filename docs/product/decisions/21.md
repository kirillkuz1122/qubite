# 21. Вход через провайдеров (AUTH-004, 19.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

| ID | Решение | Статус | Источник |
|---|---|---|---|
| D-194 | AUTH-004, ответы владельца (18.10.2026): **Яндекс ID и VK ID (PKCE) — включены** по умолчанию; **Google и Telegram — сделаны, но выключены** по умолчанию (с учётом российских законов). В тестах — поддельные (mock) провайдеры; настоящие приложения у провайдеров создаёт владелец. Имена провайдеров общие для всего проекта: `yandex`, `vk`, `google`, `telegram` (их же используют тумблеры ACC-002). | CONFIRMED | [CL] |
| D-195 | AUTH-004, как устроен вход (решения агента):<br>— **вход только по сохранённому ID у провайдера**; почта от провайдера сохраняется для показа, но не даёт входа и ничего не объединяет (D-060). Неизвестный ID → `oauth_not_linked`: **новый аккаунт через провайдера не создаётся**, пока нет регистрации (AUTH-003, вопрос Q-26);<br>— Яндекс, VK, Google — «код + PKCE S256». Начатый вход привязан к браузеру cookie `qubite_oauth` (секрет `state`, в базе — только хеш), **одноразовый, 10 минут**; чужой браузер, повтор адреса возврата, другой провайдер, просрочка → `oauth_invalid_state`. Путь возврата — только на наш сайт;<br>— способ входа доступен, если **включён и настроен** (есть `CLIENT_ID`). Выключение действует **сразу, в том числе на уже начатый вход** — к провайдеру за токеном не идём. Сейчас переключатели — переменные `QUBITE_OAUTH_<P>_ENABLED` и `OAuth::set_enabled` на ходу; тумблеры Owner Console (ACC-002) подключаются туда же;<br>— **привязка и отвязка — из открытого web-аккаунта с паролем**; неверный пароль считается в тот же лимит, что и вход (5 за 15 минут). Привязку завершает тот же человек, что начал (сессия в браузере та же и жива). Один ID провайдера — один аккаунт (`oauth_taken`); у аккаунта не больше одной привязки к каждому провайдеру (`oauth_already_linked`);<br>— **Telegram** — виджет входа: подпись HMAC-SHA256 токеном бота, данные не старше 10 минут, каждые данные — один раз. Бот тот же, что у `qubite bot` (новый, CMD-006);<br>— ответы входа — перенаправления: успех → сайт (`/settings?linked=…` после привязки), ошибка → `/auth?error=<код>&provider=…` (экран — AUTH-005). Все входы, привязки и отвязки — в аудит. | CONFIRMED (на усмотрение агента) | [CL] |
