# 63. Raspberry Pi снова работает: новый Qubite на нём и автодеплой (OPS-005, 24.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-564 | **Pi снова в строю, работать на нём можно — в рамках OPS-005.** Владелец 24.10: «Raspberry включил, вернул её к жизни». Это снимает «не трогать Pi» только для сессии OPS-005, которую владелец сам запускает на Pi. **Нельзя отключать и ломать:** бот Qubite (старый, им владелец управляет), AliasVault, LanguageTool, поиск, Quark Parser — «без них жить не могу»; их поддомены и доступ остаются. VPN и сеть Pi — только с вопросом. Меняет D-111 и D-266. | CONFIRMED | [CL] |
| D-565 | **Новый Qubite 2.0 — на основном домене `qubiteapp.online`** (старый сайт Qubite уже выключен владельцем). API — там же, как сейчас в новом коде; поддомены модулей (ADR-0006) — по мере готовности. Поддомены старых сервисов остаются как есть. | CONFIRMED | [CL] |
| D-566 | **Автодеплой: после зелёного `main` Pi сам обновляется.** Владелец: «чтобы он автоматически деплоил после успешного коммита». Pi **сам забирает** готовую сборку aarch64 из CI (таймер systemd, раз в несколько минут): бэкап базы → замена бинарника и статики → миграции → проверка `/api/ready` → при ошибке откат на прошлую версию и сообщение владельцу в Telegram. **Без self-hosted runner и без SSH из GitHub на Pi:** репозиторий публичный, чужой код из PR не должен исполняться на Pi. Меняет DEPLOYMENT §6 («автодеплоя нет»). | CONFIRMED | [CL] |
| D-567 | **Tailscale на Pi — главный, нагрузку держать низкой.** Владелец 24.10: Tailscale падал при большой нагрузке; Codex настроил, чтобы ему в первую очередь доставались ресурсы. Эти настройки не менять. Службы Qubite на Pi «скромные»: приоритет ниже, чем у Tailscale и сервисов владельца (Nice, CPUWeight, MemoryMax/MemoryHigh, OOMScoreAdjust, IOWeight); PostgreSQL под малую память; автодеплой ничего не собирает на Pi, проверяет не чаще раза в 5 минут и откладывает обновление при высокой нагрузке. Нагрузку замерять до и после установки. | CONFIRMED | [CL] |
| D-568 | **Старый вход Qubite (`qubite-auth`, порт 9131) — на отдельный адрес `gate.qubiteapp.online`.** Он закрывает siyuan, memos и vikunja; `auth.` оставлен новому Qubite. Перед переключением `qubiteapp.online` проверить снаружи, что эти три сервиса закрыты. | CONFIRMED | [CL] |
| D-569 | **База нового Qubite на Pi — уже стоящий PostgreSQL 17**, отдельные пользователь и база, малые настройки памяти; второй PostgreSQL не ставим (миграциям хватает 16+, расширений нет). | CONFIRMED | [CL] |
| D-570 | **Ставим новый бот Qubite 2.0** (`qubite bot`, свой токен); старый `qubite-control-bot` остаётся. Заполненный `.env` владелец копирует на Pi сам; в чат и git секреты не попадают. | CONFIRMED | [CL] |
| D-571 | **Сессия на Pi пушит в `main` сама** — владелец сам входит на Pi в свой аккаунт GitHub. Обновление пока сразу для всех после зелёного CI. | CONFIRMED | [CL] |
| D-572 | **Поэтапная раскатка — на будущее (OPS-006, идея).** Владелец видел, как у больших компаний: после CI обновление сначала получает часть людей, собираются ошибки, потом больше, потом все. Для Qubite: флаги функций по долям пользователей, сбор ошибок, автооткат; на одном сервере — «синий-зелёный» запуск (новая версия рядом со старой, переключение после проверки). | IDEA | [CL] |
| D-573 | **Голос Нейта — живой разговор через подписку ChatGPT (OpenAI Realtime), ElevenLabs — запасной** (ENG-005, владелец 25.10). Сессия на Pi проверила с входом владельца в Qubite («Sign in with ChatGPT»): `api.openai.com` выдаёт временный ключ realtime (`gpt-realtime-1.5`, 201) и сеанс распознавания (`gpt-4o-mini-transcribe`); обычные `/v1/audio/transcriptions` и `/v1/audio/speech` — 401. В настройках «Английского» — переключатель «ChatGPT / ElevenLabs»; на экране — живая расшифровка обеих сторон. Подписка — только для своих запросов человека (как AI-005); основной токен в браузер не попадает, только временный ключ. Ретранслятор через сервер не нужен: у владельца на устройствах всегда VPN (без него `qubiteapp.online` за Cloudflare и так не открывается); при неудаче — ошибка «проверь VPN». | CONFIRMED | [CL] |
