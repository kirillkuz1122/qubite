# 57. Проверка безопасности всего кода (SEC-001, 23.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Проверка по слову владельца (отчёт — [security-review-2026-10-23](../../reports/security-review-2026-10-23.md)). Решения — на усмотрение агента: поведение для владельца не меняется.

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-545 | **Заголовки безопасности на каждый ответ сервера:** `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN` (не `DENY` — чтобы будущий просмотр PDF/картинок проекта во фрейме своего сайта работал), `Referrer-Policy: same-origin`. Слой в `router_with`, заголовки, поставленные обработчиком (например, `Content-Security-Policy: sandbox` у файла проекта), не перезаписываются. | CONFIRMED (на усмотрение агента) | агент |
| D-546 | **Токен CI — только чтение:** у каждого workflow `permissions: contents: read`; право писать — только у шага, которому оно нужно (черновик релиза в `release.yml`). | CONFIRMED (на усмотрение агента) | агент |
| D-547 | **Уязвимые зависимости обновляются сразу**, если исправление — в той же младшей версии (`cargo update -p …`): 23.10 — `h2` 0.4.20, `rustls-webpki` 0.103.16, `webpki-roots`/`webpki-root-certs` 1.0.10. Проверка — `cargo audit` и `pnpm audit` в каждой проверке безопасности. | CONFIRMED (на усмотрение агента) | агент |
| D-548 | **CSP и HSTS для сайта, приём файла потоком, `Origin` у входа, хеши actions — отдельной задачей SEC-002** вместе с выкладкой 2.0 на сервер (OPS-001, Caddy): сейчас сайт отдаёт Vite, ставить CSP некуда, а строгая CSP без проверки на настоящем сайте может сломать вход через провайдеров и CAPTCHA. | RECOMMENDED | агент |
