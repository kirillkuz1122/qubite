# 69. Codex на Pi: очередь заданий (HAR-001, 29.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Сделала сессия на Pi по D-623, D-629 и D-640. Описание для работы — [docs/harness/CODEX.md](../../harness/CODEX.md), код — `deploy/pi/codex-queue/`. Всё можно откатить: `sudo systemctl disable --now qubite-codex.timer`.

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-630 | **Очередь — systemd-таймер `qubite-codex.timer`** раз в 5 минут после конца прошлого запуска, служба `qubite-codex.service` от пользователя `kirill` (там вход в ChatGPT и `gh`), в `qubite.slice`: Nice 15, CPUWeight 10, IO idle, MemoryHigh 450M, MemoryMax 600M. `ProtectSystem=strict`, писать можно только в `~/codex-queue`, `~/.codex`, `~/.config/gh`, `~/.cache`. Входящих портов нет. Одно задание за раз (`flock`). | агент | HAR-001 |
| D-631 | **Метки.** `codex` — задание; `codex-model:sol` → `gpt-6.1-sol` (по умолчанию), `codex-model:terra` → `gpt-6.1-terra`; `codex-effort:medium\|high\|xhigh`, по умолчанию `high`; итог ставит очередь: `codex:в-работе`, `codex:готово`, `codex:ошибка`. Id моделей взяты из `~/.codex/models_cache.json` (codex-cli 0.164). | агент | D-640 |
| D-632 | **Ветка `codex-issue-N`, а не `codex/issue-N`:** в репозитории есть ветка `codex` (её нельзя удалять), и git не даёт завести `codex/…` — первый push упал «directory file conflict». Если ветка занята — `codex-issue-N-время`. Без `--force`. | агент | HAR-001 |
| D-633 | **Только задания владельца.** Берётся открытый issue, если его автор или тот, кто последним поставил метку `codex`, — `kirillkuz1122`; остальные пропускаются. Текст issue — данные для Codex: скрипт его не исполняет, модель и уровень берутся только из меток по белому списку. В промпте правила очереди стоят выше текста задания. | агент | HAR-001 |
| D-634 | **Песочница.** Отдельная чистая копия на задание (`~/codex-queue/jobs/issue-N-время`, из общего `base.git`), не папка старого Qubite. `codex exec --sandbox workspace-write` без сети, без `/tmp`; ревью — `read-only`. Коммит, push и PR делает скрипт, не Codex. Перед push дифф проверяется на токены; в комментариях токены вырезаются. | агент | HAR-001 |
| D-635 | **Отчёт.** Codex заканчивает ответом с разделами «Сделано / Не сделано / Нужно от человека / Проверки»; он идёт в тело PR («Closes #N») и комментарием в issue, плюс проверки на Pi и модель. Нет изменений — только комментарий и `codex:готово`. Ошибка — комментарий с хвостом лога (40 строк, без секретов) и `codex:ошибка`; снять метку — повтор. | агент | HAR-001 |
| D-636 | **На Pi только лёгкие проверки:** `git diff --check` и `scripts/check.sh --quick`, если не задеты Rust и web (cargo и pnpm на Pi нет, и собирать нельзя — D-620). Тесты и сборка — CI PR. | агент | D-620 |
| D-637 | **Режим ревью** (D-640): метки `codex` + `codex-review`, в тексте «PR #N». Копия на голове PR, дифф в `.git/codex-review.diff`, песочница только на чтение; ответ — комментарий в PR («Итог / Проблемы / Проверки»), ссылка — в issue. | агент | D-640 |
| D-638 | **Когда Pi занята, задание ждёт:** load average > 6 или свободно < 600M. Порог 6, а не 3.5: Pi часто под нагрузкой от сессий Claude, а Codex в основном ждёт сеть и стоит с низким весом. Сеть Pi иногда моргает (git до github.com 135 с) — fetch/clone/push повторяются 3 раза. Запуск, оборванный перезагрузкой, помечается `codex:ошибка`. | агент | HAR-001 |
| D-639 | **Проверено на Pi 29.10:** #77 (правка строки в `OWNER.md`, Sol) → PR #79 с отчётом, `codex:готово`; #80 (ревью PR #79, Terra) → отзыв в PR, `codex:готово`. PR #79 не слит — его проверяет Claude (D-621). Terra без сети и браузера: проверки «в браузере» потребуют отдельной доработки. | агент | HAR-001 |
