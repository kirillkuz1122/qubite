| D-187 | Регистрация (AUTH-003):<br>— **владелец:** CAPTCHA — **обе на выбор**: Cloudflare Turnstile и Yandex SmartCaptcha; выбирает owner тумблером `captcha.provider` (`turnstile` по умолчанию / `smartcaptcha` / `off`); аварийная переменная `QUBITE_CAPTCHA_DISABLED=true` выключает CAPTCHA, что бы ни стояло в тумблере. Ключи — только в переменных окружения сервера. Режим регистрации по умолчанию — **по приглашениям** (D-056);<br>— **агент:** режимы `closed` / `invite_only` / `open` хранятся в новой таблице `platform_settings` (`registration.mode`); при `closed` не работают и приглашения;<br>— CAPTCHA спрашивается только при **открытой регистрации без приглашения**. Если сервис CAPTCHA не ответил или для выбранного провайдера нет ключей — регистрацию **не пускаем** (ответ 503), а не пропускаем без проверки;<br>— приглашение — код из 12 знаков без похожих букв (`7KQ2-M9XD-4TPR`, 60 бит), его же содержит ссылка `…/register?invite=…`; код показывается owner один раз, в базе — хеш. Срок 7 дней по умолчанию (1…30), одноразовое, отзываемое. Приглашение на почту сразу уходит письмом и подходит только для этой почты;<br>— две регистрации по одной ссылке одновременно: строка приглашения блокируется (`FOR UPDATE`), выигрывает ровно одна;<br>— после регистрации аккаунт ждёт подтверждения почты (D-058), письмо с кодом уходит сразу — **даже по приглашению на почту** (безопасный вариант, вопрос Q-21);<br>— если почта уже занята, ответ такой же, как при успехе, приглашение не тратится, а владельцу почты уходит обычное письмо («новый пароль» или «подтвердите почту»): по форме регистрации нельзя узнать, есть ли у человека аккаунт;<br>— приглашения в API Owner Console: `POST/GET /api/owner/invitations`, `DELETE /api/owner/invitations/{id}`; переключать режим и CAPTCHA через API — в ACC-002. | CONFIRMED (ответ владельца + на усмотрение агента) | [CL] |
