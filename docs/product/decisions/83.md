Уточнение реализации DOC-003a (#172): реальный тип проекта — `planner.project`.
События календаря пока хранятся в `calendar_events` отдельно от `objects`;
типа `calendar.event` в ядре нет, а оба конца `relations` обязаны ссылаться на
`objects`. Поэтому текущая реализация подсказок поддерживает документы, дела
и проекты; упоминания календарных событий требуют согласованного расширения
модели и миграции. Это незавершённая часть D-793, а не изменение решения о
доступных целях. Календарь не менялся (решение — D-795).

Поправки по ревью DOC-003a (#172, PR #174): существующая связь с целью в
корзине сохраняется, пока её UUID остаётся в `links`; новую связь с удалённой
целью не создаём. Удаление UUID убирает связь и в корзине. Восстановление цели
возвращает обратную ссылку без повторного сохранения документа (D-792, D-794).
При записи Yjs блокируем сначала `objects`, затем `docs_pages` через
`FOR NO KEY UPDATE`: изменения документа сериализуются, а внешние ключи
встречных упоминаний могут брать совместимый `KEY SHARE`. `objects::bump`
меняет версию и служебные поля, ключ объекта остаётся прежним.
Решил так, можно откатить; контракт API и модель календаря не менялись.
