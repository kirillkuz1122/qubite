# 27. AI: выбор моделей, провайдеры, лимиты, защита от цикла (AI-004, 19.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Ответы владельца на Q-30…Q-32 (19.10.2026). Пересматривает D-201 (allowlist) и D-202 (`data_collection`).

| ID | Решение | Статус | Источник |
|---|---|---|---|
| D-210 | **Модели выбирает owner** (Q-30): каталог OpenRouter хранится целиком (`ai_catalog`, обновляется при запуске и раз в сутки); owner включает и выключает **любую** модель из каталога (цена — из каталога), выбирает модель **по умолчанию** (`default`) и **для задач** (`inbox.triage` …). Модуль спрашивает `Gateway::model_for(задача)`: выбор для задачи, иначе по умолчанию; выключенная модель — отказ, тихой замены нет (D-076). Где: `qubite ai catalog`, `qubite ai model <id> on/off`, `qubite ai use <id> [--task …]`, API Owner Console `/api/owner/ai/{models,catalog,tasks}` (экран — AI-003). `QUBITE_AI_OPENROUTER_MODELS` теперь — только набор **первого запуска** (пересматривает D-201: «настройки побеждают» убрано, чтобы выбор owner не сбрасывался). | CONFIRMED (ответ владельца + на усмотрение агента) | [CL] |
| D-211 | **Провайдеры модели — закрепляет owner** (Q-31): `data_collection: deny` по умолчанию **не** отправляется (у части моделей таких провайдеров нет) — это настройка: у модели (`allow` / `deny`) или сервера (`QUBITE_AI_OPENROUTER_DATA_COLLECTION`). Owner вписывает модели провайдеров OpenRouter по порядку (slug, например `google-vertex`, `deepinfra/turbo`) — тогда в запросе `provider: { order: […], only: […], allow_fallbacks: false }`: только они, без автосмены (поля сверены с документацией OpenRouter, 19.10.2026). Пустой список — OpenRouter выбирает сам. Кроме того, в каждый запрос идёт `max_price` = цены из каталога: если провайдер дороже — OpenRouter запрос не выполнит (отказ без трат). | CONFIRMED (ответ владельца + на усмотрение агента) | [CL] |
| D-212 | **Лимиты: и на каждого, и на платформу, сброс каждый день** (Q-32): дневные лимиты уже обнуляются в полночь по поясу платформы (`QUBITE_AI_TIMEZONE`), месячные — по желанию. Новый лимит «**на каждого пользователя**» (`each_user`, `QUBITE_AI_EACH_USER_USD_PER_DAY` или `qubite ai limit --scope each-user`): одно значение, у каждого свой счётчик; это **потолок, а не разрешение** — AI по-прежнему открывает только личный лимит или режим owner (D-173). Режим «owner без личного лимита» (D-200) остаётся, но **работает только при заданном дневном потолке платформы в $** (без него — отказ `platform_cap_not_set`): этот потолок действует и на owner; «на каждого» owner в этом режиме не касается. | CONFIRMED (ответ владельца + на усмотрение агента) | [CL] |
| D-213 | **Защита от зацикливания** (Q-32): до резерва, под блокировкой аккаунта (параллельные запросы не проскакивают вместе): не больше **20 начатых вызовов в минуту на человека** и **10 на фоновую задачу** (`AiRequest.job_id`); один и тот же запрос (та же модель, инструкции и данные) — не больше **3 раз за 10 минут**. Сверх — отказ `rate_limited` / `repeated_request`, к провайдеру ничего не уходит. Всё настраивается (`QUBITE_AI_USER_REQUESTS_PER_MINUTE`, `…_JOB_…`, `QUBITE_AI_REPEAT_LIMIT`, `QUBITE_AI_REPEAT_WINDOW_SECS`; 0 — выключить). Для сравнения запросов в журнал пишется «отпечаток» — HMAC с секретом процесса, не текст и не хеш, который можно сверить с догадкой. | CONFIRMED (ответ владельца + на усмотрение агента) | [CL] |
| D-214 | **ChatGPT по подписке — не делаем** (Q-30). Исследование (19.10.2026): Codex CLI входит через OAuth `auth.openai.com` со **своим** `client_id` Codex (PKCE, адрес возврата `localhost:1455`, есть вход по коду устройства) и шлёт запросы на **закрытый** адрес `chatgpt.com/backend-api/codex/…` с заголовками Codex. Официальный «Sign in with ChatGPT» для сторонних приложений (бета с 29.07.2026, шесть партнёров) даёт только **вход** (имя, почта), а не модели по подписке. Значит, Qubite пришлось бы **выдавать себя за Codex CLI**: это против условий OpenAI (риск блокировки аккаунта владельца), адрес и формат без документации и могут сломаться в любой день, лимиты подписки (окна по 5 часов и неделе) не отдаются заранее — бюджет по-честному не посчитать. Надёжно и честно — нельзя, поэтому провайдера `chatgpt` нет. Варианты на выбор владельца — в STATUS (Q-33). | CONFIRMED (на усмотрение агента, вывод для владельца) | [CL] |
