# 81. Безопасность при выкладке (SEC-002, 31.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Сделала сессия задачи SEC-002 (#17) по D-548. Блок номеров D-770…D-779.

| № | Решение | Статус | Источник |
|---|---|---|---|
| D-770 | **CSP и HSTS ставит Caddy** (`deploy/pi/qubite.caddy`, один источник строки). Скрипты — только свои + CAPTCHA (Turnstile, SmartCaptcha) + виджет Telegram; фреймы — CAPTCHA и `oauth.telegram.org`; `object-src 'none'`, `frame-ancestors 'self'`. Скрипт темы вынесен из `index.html` в `/theme-init.js`, поэтому `unsafe-inline` для скриптов не нужен; для стилей он оставлен (React `style={{}}`). HSTS — `max-age=31536000` без `includeSubDomains` и `preload` (их не откатить, на других поддоменах владельца могут быть свои сервисы). Проверка — `pnpm e2e:csp` (собранный сайт с этой CSP, экраны без нарушений). | агент, можно откатить | #17 |
| D-771 | **Вход проверяет `Origin`:** если браузер прислал `Origin` и он не равен `Host` — 403 `origin_mismatch`; без `Origin` (curl, нативные клиенты) вход разрешён. Это закрывает login CSRF. | агент, можно откатить | #17 |
| D-772 | **Файл проекта идёт потоком на диск** и не больше 4 загрузок одновременно на сервер (5-я — 429). Делает #159. | агент, можно откатить | #17 |
