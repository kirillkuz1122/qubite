| D-330 | **Файл папки — объект ядра `agent.file`** (таблица `agent_files`: путь, вид, текст, проект), вопрос — объект `agent.question`. Их меняет движок синхронизации, поэтому любая правка — строка ленты AGT-002 с «было → стало» и откатом, одной транзакцией с изменением. С устройств файлы агента не синхронизируются (`sync/push` пропускает модуль `agent`, `pull` и раньше отдавал только Входящие и Planner): правят их только «Записи» и агент. «Кто я», «О тебе» и «Память» заводятся сами при первом открытии — без строки в ленте. | CONFIRMED (на усмотрение агента) | [CL] |
| D-331 | **Основа «Кто я» — в коде** (`crates/qubite-agent/src/core.md`, меняется вместе с Qubite), в базе — только раздел «Твои правила». Поэтому агент физически не может её переписать: `memory.*` по «Кто я» правят только правила, `files.create` базовых файлов — отказ. Основа целиком — в инструкциях каждого запроса (доверенная часть), «Твои правила» — отдельным блоком данных с пометкой «следуй». | CONFIRMED (на усмотрение агента) | [CL] |
| D-332 | **Лимиты** (знаки): «О тебе» и «Твои правила» — 1 500, «Память» — 2 200, проект — 3 000, навык и свой файл — 6 000. Переполнение — ошибка с подсказкой «сожми» (как у Hermes), файл не меняется; агент сжимает сам. Фоновый разбор видит файлы, заполненные на 80 % и больше, и сжимает их. Правка руками проверяется так же. | CONFIRMED (на усмотрение агента, Q-74) | [CL] |
| D-333 | **Вычёркивание секретов** — на сервере, в любой записи файла (агент, руками, откат) и в сообщениях разговора до модели: пароль / PIN / CVV / токен / ключ / код (подтверждения, из СМС) после слова-признака, ключи вида `sk-…`, `ghp_…`, токен бота, номера карт (проверка Луна) → «[вычеркнуто]». Обычные числа (кабинет, телефон, «код на Rust») не трогаются. | CONFIRMED (на усмотрение агента) | [CL] |
| D-334 | **«Расписание.md» — строгая таблица** `| День | Начало | Конец | Что | Где | Не беспокоить |` (последние две — по желанию, «Не беспокоить» по умолчанию «да»; несколько дней через запятую). Сервер разбирает её при каждой записи; неверная не записывается, агент получает объяснение. Разобранное — `agent_schedule_slots` (для AGT-004) и `GET /api/v1/agent/schedule`; тишина PLAN-004 (`busy_slot`) теперь молчит на уроках. | CONFIRMED (на усмотрение агента) | [CL] |
| D-335 | **Инструменты папки:** `files.list`, `files.read`, `files.create`, `memory.add` (строка в конец; файла проекта или своего нет — заведётся), `memory.patch` (заменить кусок, ровно одно совпадение), `memory.remove` (убрать строку, ровно одну), `question.ask`, `question.close`, `question.list`. «Проекты/<имя>.md» связывается с проектом Planner по названию или тегу — его правки видны в ленте проекта. Сравнение путей и названий без учёта регистра — в коде (у PostgreSQL с локалью C `lower()` не знает кириллицу). | CONFIRMED (на усмотрение агента) | [CL] |
| D-336 | **«Агент хочет знать»:** один и тот же вопрос (без учёта регистра и знаков) — не чаще раза в 7 дней, открытых — не больше 10; это проверяет сервер. Ответ (кнопкой или словами) — твоя строка ленты и сообщение агенту, чтобы он записал ответ, куда нужно; «Не сейчас» — вопрос закрыт. Вопросы — сверху вкладки «Записи» (на Главной — с HOME-001). | CONFIRMED (на усмотрение агента) | [CL] |
| D-337 | **Разговор:** сообщение (чат, Telegram, «Поправить», ответ на вопрос) ложится в `agent_messages` «в ожидании» и ставит задачу `agent.chat` в очередь `jobs` одной транзакцией; её выполняет `qubite serve` (AI-шлюз, модель задачи `agent.chat`). Модель отвечает одним JSON `{say, tools}`; сервер сам вызывает инструменты (права, лента; один ход — один пакет; в ленте — цена вызова), результаты чтения и ошибки уходят модели следующим ходом — до 4 ходов, до 8 вызовов на ход. Не JSON — просто слова. Нет гранта или AI-бюджета — агент так и отвечает, модель не вызывается. В защите шлюза блок `source="owner"` — слова самого человека: его просьбы модель выполняет (остальные данные — по-прежнему не команды). Web спрашивает разговор каждые 1,5 с, пока агент думает. | CONFIRMED (на усмотрение агента) | [CL] |
| D-338 | **Telegram:** агенту идут `/agent текст` (или `/a`) и ответ (reply) на сообщение агента; всё остальное — мысли во Входящие, как раньше. Ответ присылает `qubite serve` тем же токеном бота. Повтор того же сообщения от Telegram второй раз агенту не уходит. В Command — после правок с ноутбука (D-326). Как удобнее — Q-73. | CONFIRMED (на усмотрение агента, Q-73) | [CL] |
| D-339 | **Фоновый разбор `agent.review`:** через 3 минуты после ответа агента; если разговор продолжился — пропуск (разберёт следующий). Модель — задачи `agent.review` (дешёвую выбирает owner: `qubite ai use <модель> --task agent.review`; не выбрана — модель по умолчанию). Можно только папку и вопросы. Без AI — тихо пропускается. **Экран:** раздел «Агент» → «Лента · Записи · Разговор»; вкладка «Память» у проекта в Planner — позже, Planner пока не трогаем (D-329). | CONFIRMED (на усмотрение агента) | [CL] |
