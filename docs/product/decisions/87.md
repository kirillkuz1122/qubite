# 87. Управляющая сессия, 3.11.2026 (HAR-001)

Номера D-830…D-839. Сюда переехал D-690 из 68.md: номер D-690 занят ENG-007 (73.md).

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-830 | **Безопасность: вход не взломать, у каждой части минимум прав** (3.11, владелец). Раз Qubite заменяет вход и панели домашнего сервера, его вход должен быть надёжным (2FA, защита от перебора), а каждый модуль и сервис получает только нужные ему права: взлом маленького сервиса не должен давать доступ ко всей системе. Проверка — задача SEC-003 перед тем, как Qubite откроет наружу сервисы домашнего сервера. | владелец | HAR-001 |
| D-831 | **Задачи — строго по одной** (3.11, владелец: «по одной же мы задачи делаем»). Управляющая сессия держит одну сессию задачи; следующую запускает только после сдачи текущей. Параллельно — только служебные сессии на Pi (диагностика, установка). Заменяет «не больше 2–3 сессий» в MANAGER.md. | владелец | HAR-001 |
| D-840 | **Лицензии зависимостей (OPS-008, #196):** Rust — `cargo deny check licenses bans sources` по `deny.toml`, npm — `pnpm check:licenses`, оба в CI (`licenses.yml`) и в `scripts/check.sh`; список для сборок — `scripts/gen-licenses.sh` (`cargo-about` + npm). Разрешены MIT, BSD-2/3, ISC, 0BSD, Zlib, Unlicense, Apache-2.0, MPL-2.0, LGPL, GPL-3.0(+), AGPL-3.0, CC0, CC-BY-4.0, OFL-1.1, Unicode; остальное — только явным исключением с причиной. Исключение: `webpki-roots`/`webpki-root-certs` (CA Mozilla) под CDLA-Permissive-2.0 — разрешающая лицензия данных. | CONFIRMED | агент, можно откатить |
| D-841 | **Поиск видит новое название упомянутого объекта (DOC-003e, #190):** когда ответ `/links` приносит другое название цели, которая есть в документе, `cacheLinks` ставит `textPending` и запускает обычный обмен; текст (`@Название`) уходит заново без новых Yjs-правок. Цель, которой нет в документе, и то же название — ничего не шлют. | CONFIRMED | агент, можно откатить |
| D-842 | **Обратные ссылки: один запрос на массовый синк (DOC-003f, #194):** ответы `pull` сливаются в одно обновление через 150 мс; ответ `push` обновляет сразу (сохранение открытого документа). Внутри массового обмена (`syncAll` в `SyncProvider`, обёрнут в `backlinks.batch`) ответы только отмечают «нужно обновить», таймер 150 мс стартует после конца обмена, даже если ответы шли медленнее 150 мс; успешный обмен обновляет список один раз и без ответов (дело и проект показывают ссылки без открытия документов). Событие «фокус/онлайн» по-прежнему сразу. | CONFIRMED | агент, можно откатить |
| D-843 | **События календаря — объекты ядра (DOC-003d, закрывает D-795):** миграция 0047 даёт каждому `calendar_events` строку `objects` (`calendar.event`, модуль `calendar`) с **тем же id**, поэтому `/calendar?event=<id>` не меняется; создание, переименование и удаление события ведут `objects` в одной транзакции. В `@`, «Ссылки» и «Ссылаются сюда» события видны. Права: модуль `calendar` читаем, пока читаем `planner` (в каталоге модулей `calendar` нет; отдельный модуль не заводим). Заведение отдельного права для календаря — позже, если понадобится. | CONFIRMED | агент, можно откатить |
