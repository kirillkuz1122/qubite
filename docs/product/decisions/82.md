# 82. Список и Kanban под проект (PLAN-002, 31.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

Сделала сессия задачи PLAN-002 (#62) по D-250…D-263 (PLAN-001) и AGT-002. Блок номеров D-780…D-789.

| № | Решение | Статус | Источник |
|---|---|---|---|
| D-780 | **Статусы дел не меняются** (`todo`/`doing`/`done`, D-252): «колонки под проект» — это какие из трёх статусов проект показывает на доске и как они называются. Новых статусов нет: иначе ломаются «Сегодня», повторения (D-253) и агент. | агент, можно откатить | [CL] |
| D-781 | **Настройка доски — поле проекта `board`** (jsonb): `{columns: [{status, title}], view: "board"\|"list"}`. Колонок 2–3, статусы без повторов, `done` всегда есть, название до 24 символов. Нет поля — как раньше: «Надо» / «В работе» / «Готово», вид — доска. Едет через обычную синхронизацию (D-260), правится одной правкой проекта. | агент, можно откатить | [CL] |
| D-782 | **Дело в скрытом статусе не пропадает:** если проект скрыл «В работе», дела `doing` показываются в первой колонке, а при переносе получают статус колонки. Статус в базе меняется только действием человека. | агент, можно откатить | [CL] |
| D-783 | **Список — второй вид того же проекта:** группы по колонкам, сворачиваются; те же действия (галочка, перенос через «⋯ → Переместить в…», клавиши). Выбор вида хранится в `board.view` проекта. Общая доска «Planner» остаётся тремя колонками. | агент, можно откатить | [CL] |
