# 103. Облачные сессии в Пульте: сводка управляющей сессии и сборщик по таймеру (AOS-5i, 20.11.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md). Продолжает [D-980](95.md) (откуда Пульт берёт данные). Задача — [#276](https://github.com/kirillkuz1122/qubite/issues/276), код — [#277](https://github.com/kirillkuz1122/qubite/issues/277).

| # | Решение | Статус | Источник |
|---|---|---|---|
| D-1070 | Токены и лимиты облачных сессий Пульту даёт **управляющая сессия**: это единственное место, откуда они видны (`get_session`, `list_events` дочерних сессий; сервер их сам не видит, D-980). Она собирает ответы в сводку того же формата и шлёт тем же `POST /api/pult/report`. Отдельного нового API нет. | PROPOSED | агент, можно откатить |
| D-1071 | Скрипт — `scripts/pult_cloud.py`. Менеджер на каждом будильнике сохраняет вывод `get_session` и `list_events` (kinds `result`, `rate_limit_event`) дочерних сессий в файлы и вызывает скрипт; тот разбирает их, собирает сводку и шлёт. Скрипт сам MCP не вызывает — только читает файлы, поэтому его можно проверить без облака. | PROPOSED | агент, можно откатить |
| D-1072 | Что берётся из облака: модель — `last_served_model`; контекст — `context_usage.used_tokens`; токены по моделям — последнее событие `result`, `modelUsage` (накопительно за сессию); лимиты 5ч/7д — последнее `rate_limit_event`, `unifiedWindows` (доля 0…1 → проценты). Цену сервер считает сам по токенам и своей таблице («≈ $ по ценам API», как у ПК); `costUSD` из облака в сводку не идёт, чтобы цена у ПК и облака считалась одинаково. | PROPOSED | агент, можно откатить |
| D-1073 | Нет данных — так и пишем: нет события `result` — у сессии пустой расход, нет `rate_limit_event` с окнами — `limits: null` (проценты из `rate_limit_info` без окон не выдумываются). Сводка облака — отдельная запись в `sources` («Облако») с причиной; нет сводки совсем — `ok: false` и «управляющая сессия ещё не присылала сводку». Свежесть облака — 90 минут (будильник менеджера ≈ раз в 40 мин), у ПК остаётся 30. | PROPOSED | агент, можно откатить |
| D-1074 | В сводку добавлено необязательное `source`: `pc` (по умолчанию) или `cloud`. Старые сборщики не меняются. Лимиты в Светофоре — как и раньше самые свежие среди всех источников: облако и ПК показывают один и тот же счётчик подписки, берётся тот, что новее. | PROPOSED | агент, можно откатить |
| D-1075 | Токен для сводки облака — обычный токен сборщика (Пульт → «Подключить ПК», имя «Облако»). В сессию он попадает **только** через `request_credential` (его подставляет прокси сессии, в чат и git не попадает) или секрет окружения `QUBITE_PULT_TOKEN`. В файлах репозитория, комментариях issue и сообщениях его нет. Если токена нет — скрипт выходит с кодом 2, менеджер пишет в отчёт «сводку облака не отправил: нет токена». | PROPOSED | агент, можно откатить |
| D-1076 | Сборщик на ПК запускается таймером **systemd --user**: `deploy/pult/qubite-pult-collect.service` (`oneshot`, `pult_collect.py once`) и `.timer` (каждые 2 минуты, `Persistent=true`). Вместо `watch` в терминале: переживает перезагрузку и закрытый терминал. Ставит `scripts/install-pult-collector.sh --apply` (без флага только показывает план); токен лежит в `~/.config/qubite/pult.env`, скрипт его не создаёт. | PROPOSED | агент, можно откатить |
| D-1077 | На ПК владельца агент ничего не ставит: установка — по инструкции в [PULT.md](../../design/PULT.md) §6, владелец запускает сам. | PROPOSED | агент, можно откатить |
