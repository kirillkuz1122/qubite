# 13. Вход приложений (AUTH-006, 18.10.2026)

Индекс всех решений — [DECISIONS.md](../DECISIONS.md).

| ID | Решение | Статус | Источник |
|---|---|---|---|
| D-177 | Решения агента в AUTH-006 (OAuth 2.0 для нативных приложений, RFC 8252 + PKCE RFC 7636):<br>— приложение открывает системный браузер; человек в своей web-сессии нажимает «Разрешить» (`POST /api/auth/device/authorize`); приложение получает одноразовый код на **5 минут** через `qubite://auth/callback` (desktop может и `http://127.0.0.1:<порт>/callback`) и меняет его вместе с `code_verifier` на токены (`POST /api/auth/device/token`). Только `S256`;<br>— **access-токен 15 минут**, refresh живёт как сессия: **30 дней с продлением** (как web, D-170). Refresh одноразовый (ротация); повтор старого refresh или кода закрывает сессию устройства целиком (признак кражи);<br>— токены — случайные строки, в базе только хеши, каждый запрос сверяется с базой: отзыв устройства в списке сессий, «выйти везде» и смена пароля действуют сразу;<br>— приложения: `qubite-desktop`, `qubite-android`; список — в коде. Запросы приложений идут с `Authorization: Bearer`, им CSRF не нужен; токен приложения нельзя подставить в cookie и наоборот, и им нельзя разрешить вход другому приложению;<br>— тело запроса токенов — JSON (а не form, как в RFC 6749): оба клиента наши; при необходимости добавим form;<br>— страница «Разрешить вход приложению?» — AUTH-005 (экраны Qubite Auth). | CONFIRMED (на усмотрение агента) | [CL] |
